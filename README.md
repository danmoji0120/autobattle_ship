# SIDERARIUM — 영속형 우주 PMC 운영 RPG

민간군사기업(PMC)을 세워 낡은 함선 몇 척으로 시작해, 소행성을 캐고 해적을 사냥하고 계약을 따내며
자체 정거장을 가진 거대 기업으로 성장시킨다. 함선은 직접 조종하지 않는다 — 편대를 만들고, 지휘관을 앉히고, 임무를 맡긴다.
기존 함대전(아래 "FLEET COMMAND")은 세계 속 교전으로 그대로 이어진다.

```bash
npm install
npm run dev          # 클라이언트 (싱글플레이 + 모의 전투)  http://localhost:5173
npm run build && npm start   # 멀티플레이 서버 (정적 파일 + WebSocket)  http://localhost:8080
npm test             # 시뮬레이션·월드·서버·락스텝 테스트
npm run worldbot -- 30       # 헤드리스 '봇 플레이어'로 30분 진행 경제/위협 확인
node scripts/mptest.mjs      # 실제 WebSocket 클라이언트 2개로 동기화·재접속·재시작 영속성 검증
```

전략 화면 상단 **경제 · 월드**에서 자사 손익·물류와 공개 시장·세계 추세를 확인할 수 있습니다. 관리자 조회 권한, 통계 보존·집계 기준과 검증 결과는 [창고·월드 분석 개발 기록](docs/STORAGE_ANALYTICS.md)에 정리했습니다. [최종 검증 보고서](docs/STORAGE_ANALYTICS_VERIFICATION.md)에서 완료 범위·성능 수치·Partial 항목을 확인할 수 있습니다. 운영 서버의 관리자 조회는 계정 UUID를 설정하기 전까지 비활성화됩니다.

성장 월드의 **물류 관리**에서 편대별 반복 운송·자동 판매·생산 공급을 설정할 수 있습니다. 일괄 정지·재개와 장애 해결 화면 연결을 제공하며, 취소·대기 시 화물을 보존합니다. [사용법과 설계](docs/LOGISTICS_AUTOMATION_P2.md), [P2 검증 결과 및 성능 한계](docs/LOGISTICS_AUTOMATION_P2_VERIFICATION.md)를 확인하세요.

성장 월드에서 새 기지를 세울 때는 구매한 합금을 실제로 운반해야 합니다. 건설 화면의 **건설 공급 노선 설정**으로 자사 현장에 필요한 자재를 보내거나, 화물선의 **현장 반입**을 사용할 수 있습니다. 설립 명령에서 선납한 비용은 착공 전 명령을 중단하면 환급됩니다. [건설 물류 설계와 검증](docs/P95_CONSTRUCTION_LOGISTICS.md)을 참조하세요.

P8 함선·성장·경제 분석·물류를 합친 개발 브랜치는 `integration/growth-p8-logistics`입니다. [통합 검증 보고서](docs/INTEGRATION_VERIFICATION.md)에 실제 플레이·저장·권한 검사와 남은 성능 한계를 기록합니다.

**P11 전투(옵트인, `COMBAT_P11=1`인 새 월드 전용)**: 3개 이상 진영의 다자간 교전(적대·중립·동맹), 진행 중인 전투로의 실위치 증원, PMC 간 PvP(적대 선언·동맹 제안), 회사별 독립 지휘(서버 검증), 진영별 철수, 회사별 1회 정산을 지원합니다. 기존 월드·저장은 그대로입니다. [P11 설계·검증](docs/P11_COMBAT_MULTISIDE.md)을 참조하세요.

계정 전용 실험함 **BB-EX**와 지휘관 **BB**(세계 유일, 서버가 지정 계정에만 지급)는 [BB-EX 문서](docs/BBEX.md)를 참조하세요. 운영 서버는 `SIDERARIUM_BB_OWNER_ACCOUNT`를 설정하기 전까지 누구에게도 지급하지 않습니다.

## 구조 (멀티플레이 전제)

| 층 | 내용 |
|---|---|
| `src/world/` | 영속 세계 시뮬레이션. 상태 전체가 순수 JSON (저장/동기화/복원 동일 경로) |
| `src/server/core.ts` | 전송 계층과 무관한 **권위 서버**: 토큰 인증, 소유권 검증, 스냅샷, 회사별 이벤트, 전투 명령 틱 스탬핑 |
| `src/server/node.ts` | Node 서버: 정적 호스팅 + `/ws` WebSocket + 저장(파일 또는 `DATABASE_URL` Postgres), 30초 자동 저장·종료 시 저장 |
| `src/client/net.ts` | `LocalTransport`(브라우저 안에서 같은 GameServer 실행 = 싱글플레이) / `WsTransport`(멀티플레이) |
| `src/client/strategic/` | 성계 3D 지도, PMC 지휘 UI |
| `src/client/battleLink.ts` | 세계 교전을 전술 전투 화면으로 연다. 서버가 보낸 셋업+스탬프된 명령으로 결정론적 재시뮬레이션(락스텝) |
| `src/sim/` | 기존 결정론적 함대전 엔진 (세계 교전이 그대로 사용) |

- 플레이어마다 독립 PMC·함선·지휘관·창고·정거장 소유권. 명령은 서버가 소유권을 검증한다.
- 오프라인이어도 함대는 지휘관들이 계속 운용한다 (영속 세계).
- 전투는 서버에서 실시간 진행, 결과(선체 손상·격침·현상금·지휘관 경험치·잔해 지대)가 PMC 자산에 반영된다.
- 같은 교전에 여러 PMC가 같은 편으로 참여 가능(협력 구조). PvP·외교·거래는 이 구조 위에 추가 예정.

## 플레이 흐름
1. 아스트라 자유항에서 채굴선 2척 + 경비대로 시작 → 채굴반 선택 후 소행성 지대 우클릭.
2. 광석은 정거장에 하역·판매. 계약(납품/현상금/은신처 토벌)으로 보수와 연합 평판.
3. 수송선(채굴선이 쉬지 않음), 함선, 지휘관 영입. 편대를 중첩해 상위 지휘관에게 위임.
4. 약 10분 후부터 해적 습격 — 지휘관이 판단력에 따라 미리 감지해 철수하거나, 경비대가 요격.
5. 공작선 + 자금 + 합금으로 정거장 설립 → 정비소·정제소·방어 포대·조선소 모듈.
6. 순양함·전함으로 해적 은신처 토벌 → 성계 전체의 위협 지형이 바뀐다.

## 성계 구조 · 치안 · 넷코드
- **성계**: 기존 월드는 헬리오스·아스트라·드레이크·엠버·검은 송곳니의 5개 성계이며, 새 P9 성장 월드는 이를 포함해 22개 성계로 확장된다. 기존 저장은 자동 확장하지 않는다. 각 성계는 점프게이트로 연결된 연속 공간이며, 새 월드의 지역과 항로는 [P9 월드 설계](docs/P9_WORLD_EXPANSION.md)를 참조한다.
- 6,000 이상 거리는 **워프**(함급별 정렬 3~8초 → 최대 7,000/s → 하강). 3,000 이내 적 전투함이 있으면 워프 방해. 다른 성계는 게이트 경로(BFS)로 자동 이동.
- **치안 0~100**: 핵심 90+(해적 없음) · 주요 거주 70~89(외곽 소규모 떠돌이) · 변방 40~69(빈번) · 위험 15~39(은신처·중대형) · 무법 0~14(해적 지배). 지역 치안 = 기본 치안 − 최근 해적 활동(상한 있음, 수도권은 몇 번의 습격으로 무너지지 않음) − 외곽 페널티 + 연합 주둔지/플레이어 방어 포대 − 은신처 영향.
- **연합군**: 정거장 주둔함대, 순찰대, 신속대응함대(치안 비례 규모). 손실 시 모항에서 보충·수리, 전멸 시 일정 시간 후 재편성. 해적은 자기 전력과 주변 연합 전력을 비교해 습격 대상을 고른다.
- **경제**: 고치안 = 안전하지만 세금(핵심 12%·주요 5%·변방 2%)과 빈약한 광맥, 저치안 = 광맥 풍부도 ×1.35~2.2, 납품·현상금 보수 가중.
- **넷코드**: 서버 권위. 1초마다 관심 영역(내 함선 + 보고 있는 성계) 상태 동기화(프로토콜 2: 이전에 받은 상태와의 차이만, 엔티티 직렬화는 클라이언트 간 공유 — 구 클라이언트는 전체 스냅샷), 0.2초마다 압축 이동 패킷. 운영·제한값·관측은 [P0 서버 안정화](docs/P0_SERVER_STABILITY.md) 참조. 클라이언트는 서버 월드 시각 기준 버퍼 보간(Hermite, 외삽 없음, 시간은 절대 역행하지 않음). NPC끼리 전투는 서버 이벤트 루프를 막지 않도록 란체스터 자동 판정.
- 조작: **Tab** 성계 지도 · **V** 치안 지도 · **F3** 진단(클라 FPS/렌더 시간, RTT·패킷 간격·지터·버퍼 고갈, 서버 틱 시간·진행 속도).
- 이전 세이브(v3)는 자동 이전: 자금·함선·편대·지휘관·자사 정거장 유지, 함선은 아스트라로 재배치.
- 검증 스크립트: `npx vite-node scripts/secsim.ts 2 3`(2시간·시드별 치안 리포트), `node scripts/mptest.mjs`(실제 WebSocket 2클라이언트, 성계 분리, 재시작 복원).

# FLEET COMMAND (모의 전투 모드) — 다중 계층 지휘형 함대전

함대를 편성하고, 지휘관을 배치하고, 임무를 맡긴다. 전투는 지휘관들이 각자의 능력과 성향으로 치르고,
플레이어는 전술 지도에서 흐름을 읽다가 결정적인 순간에 개입한다.

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 시뮬레이션 테스트 (결정론/리플레이/지휘관 효과/장갑 모델 …)
npm run balance    # 헤드리스 대량 전투로 승률·전투 시간·무기별 피해 비중 확인
npm run build      # 정적 빌드 (dist/)
```

URL 옵션: `?auto=1` 편성 생략하고 바로 전투, `&scenario=kestrel|bastion|wolfpack`, `&seed=N`, `&cam=director`.

## 플레이 방법

1. **함대 편성** — 시나리오 선택 → 부대(그룹)를 만들고 하위 부대를 중첩 → 함선 추가·무장(로드아웃) 선택 → 지휘관 배치 → 초기 명령과 자동 후퇴 기준 설정 → 출격.
   기본 편성(제7 기동함대)은 바로 출격해도 되도록 구성되어 있다.
2. **전투** — 지휘관들이 스스로 싸운다. 플레이어는:
   - 좌측 **지휘 계통**에서 부대를 선택(▸로 펼치기/접기, 펼친 단계까지 지도에 부대 표식이 나뉘어 표시됨)
   - 하단 **명령 패널**: 자유 교전 / 공격 / 좌·우측 우회 / 호위 / 이동 / 사수 / 후퇴 / **지휘권 위임**, 위험 시 자동 후퇴 기준
   - **우클릭** 상황 명령: 적 → 공격(Shift: 특정 함선 집중), 아군 → 호위, 빈 곳 → 이동
   - 상위 부대에 명령하면 그 지휘관이 하위 부대에 역할을 나눠 준다. 하위 부대에 직접 명령하면 그 부대는 "직접 지휘"(주황 표시) 상태가 되고, `T`로 다시 위임할 수 있다.
3. **관찰** — `전술 지도` / `추적`(더블클릭) / `시네마틱`(자동 연출, 대형함 격침 시 슬로모션). 우측 통신 로그를 클릭하면 해당 위치로 이동.
4. **결과** — 하이라이트, MVP 함선, 지휘관별 평가. `리플레이 보기`는 같은 시드와 기록된 명령으로 전투를 완전히 재현한다.

단축키: `Space` 정지, `1-4` 배속, `Tab` 전술/시네마틱, `F` 추적, `C` 시네마틱, `E/A/Q/R/G/M/H/B/T` 명령, `Esc` 취소.

## 설계

| 층 | 내용 |
|---|---|
| `src/sim/` | 렌더링과 분리된 **결정론적 시뮬레이션** (30Hz 고정 스텝, 시드 RNG). 저장·리플레이·헤드리스 밸런싱의 기반 |
| `src/sim/ai/commander.ts` | **계층형 지휘관 AI** — 상위 그룹은 명령을 해석해 하위 그룹에 역할 분배(모루/망치/호위), 말단 그룹은 표적 선정·집중 사격·교전 거리·대형·우회 단계·뇌격 돌입을 수행 |
| `src/render/` | Three.js: 절차적 함선 모델(진영별 실루엣, 회전 포탑, 엔진 플룸, 반파 시 앞뒤로 분리되는 잔해), 성운 스카이박스, 인스턴스 파티클, 예광탄 리본, 충격파, 섬광 조명, 블룸, 시네마틱 디렉터 |
| `src/ui/` | 편성 화면, 전투 HUD(계층 트리, 명령, 통신, 전술 오버레이), 결과 화면 |
| `src/audio/` | 에셋 없이 코드로 합성한 효과음과 전투 강도에 반응하는 음악 |

### 지휘관이 전투 양상을 바꾸는 방식
- **판단력(skill)**: 판단 주기(0.9~3.4초), 표적 선정 품질(장갑 상성·고립·손상도 vs 단순 최단거리), 집중 사격과 과잉 살상 분산, 마무리 일격, 측면 위협 탐지, 우회 경로의 폭, 함대 속도 동기화, 망치-모루 타이밍(예: 바로스 제독은 뇌격대를 대기시켰다가 주력이 적을 붙잡는 순간 돌입 신호를 보낸다), 신참은 우회 명령을 잘못 이해하기도 한다(그레이 대위).
- **공격성(aggression)**: 교전 거리, 어뢰 발사 거리, 후퇴 시점.
- **규율(discipline)**: 낮으면 플레이어 명령 중에도 기회를 보면 독자 판단으로 돌입(카이 렌), 불만을 표시.
- **특기**: 포술(명중), 기동(속도·선회), 방공(요격률), 전술(판단 속도).
- 같은 함선에 지휘관만 바꾼 대조 실험: 지휘관 배치 함대가 "선임 함장" 함대에 약 19:1로 승리 (`scripts/cmdtest.ts`).

### 전투 모델 요점
전면/측면/후면 장갑과 관통력 → 관통·저지·**도탄**, 치명타(기관·포탑·화재·함교), 격침 시 탄약고 유폭(주변 함선 연쇄 피해),
미사일은 탄창 제한(초반 일제 사격 → 포격전으로 전환), 근접 방어포가 미사일·어뢰를 요격, 작고 빠른 함선은 맞추기 어렵다.

## 검증 현황
- `npm test`: 결정론, 리플레이 일치, 모든 시나리오 종료, 지휘관 효과, 직접 지휘/위임, 후퇴 이탈, 장갑 모델.
- `npm run balance`: 미러 매치 50:50(진영 편향 없음 확인 — 이 과정에서 발사 순서/조준 편향 버그를 발견·수정), 시나리오별 기본 편성 자동 진행 승률 약 40~70%, 전투 시간 약 3~4분.
- `scripts/shot.mjs`: 헤드리스 Chromium으로 실제 화면 캡처(편성, 전술 지도, 추적, 시네마틱).
- **자동 테스트로 판단할 수 없는 부분**: 연출의 박력, 사운드 믹스, 조작감, 장시간 플레이 재미는 직접 플레이로 확인이 필요하다. 헤드리스 환경은 소프트웨어 렌더링이라 실제 GPU 프레임레이트는 측정하지 못했다.
