# A-1 — P10 통합 기준 월드

로드맵 v2의 A-1. 지금까지 개별 플래그로만 켤 수 있던 시스템을 하나의 표준 월드로 묶어, 실제 서버가 새 월드를 만들 때 그 기준을 쓰게 한다.

## 1. 플레이어가 겪는 변화

- 서버가 새 월드를 만들면(빈 저장소에서 처음 시작할 때, 운영자 `WORLD_RESET` 때) **P10 우주: 40개 성계와 6개 세력**이 만들어진다. 영토와 탐사 안개도 함께 들어간다.
- 그 우주에서 다음이 **동시에** 동작한다.
  - 세력 경제 v2
  - P11 다자 전투·PvP
  - P12 함대 작전
  - P12.5 자동 물류
  - P13.1 잔해 인양
  - P13.2 약탈
  - P13.3 암시장
  - P13.4 치안·법 집행
  - P14 회사 신용도·세력 신뢰도
  - 기존 건설·생산·시장·조선·연구 (성장 월드 기본 기능)
- PMC 설립 화면이 실제 지급 조건을 서버에서 받아 보여준다.
  - 등록 정거장 이름과 운영 자금(성장 월드 12,000 cr)이 표시된다.
  - 이전 화면은 "운영 자금 7,000 cr"로 고정되어 있었다. 이는 성장 월드 이전의 금액으로, 실제 지급액과 달랐다.
- 이미 저장된 월드는 바뀌지 않는다. 프리셋은 **새로 만드는 월드**에만 적용된다.

## 2. 구현

| 위치 | 내용 |
|---|---|
| `src/world/worldPreset.ts` | `STANDARD_WORLD` 생성 옵션. `newWorldOptions(flags)`가 새 월드 생성 규칙의 단일 출처다. `worldRules(state)`는 월드가 실제로 돌리는 규칙을 상태에서 읽는다(로그·검사용). |
| `src/server/core.ts` | `ServerOptions.worldPreset` 추가. 빈 저장소에서 시작하면 `newWorldOptions(opts)`로 생성한다. |
| `src/server/node.ts` | 환경 변수를 한 번만 읽어 `worldFlags`로 만든다. 최초 시작(GameServer)과 `WORLD_RESET`이 같은 `worldFlags → newWorldOptions`를 쓴다. 시작 로그에 `rules={…}`를 남긴다. |
| `src/world/sim.ts` | `starterTerms()`: 새 회사가 받을 자금과 정거장. `createPlayer`와 같은 상수를 쓴다. |
| `src/server/protocol.ts`, `src/client/net.ts`, `src/client/app.ts`, `src/client/account.ts` | `needPmc`에 `start`를 실어 PMC 설립 화면에 표시한다. 구버전 서버가 값을 보내지 않으면 금액을 약속하지 않는 문구로 표시한다. |

### 환경 변수

- `WORLD_PRESET=standard`(기본값): 통합 표준 월드.
  - `COMBAT_P11`, `LAW_P134`, `REPUTATION_P14` 등 개별 기능 플래그는 새 월드 생성에 쓰이지 않는다.
  - 개별 플래그가 설정되어 있으면 시작 로그에 그 사실을 남긴다.
- `WORLD_PRESET=legacy`: 이전 동작(P9 배치, 개별 플래그 opt-in).
- 그 밖의 값: 서버가 월드를 쓰기 전에 오류로 종료한다.
- `REPUTATION_P14_MIGRATE`, `CONTENT_MIGRATE`, `ECON_MIGRATE`는 **기존 저장**을 변환하는 플래그로, 프리셋과 무관하게 그대로 동작한다.

### 발견해 고친 결함

- `WORLD_RESET` 경로에는 `REPUTATION_P14`가 빠져 있었다.
  - 그래서 `REPUTATION_P14=1`이어도 리셋한 월드는 평판 규칙 없이 만들어졌다.
  - 이제 두 경로가 같은 함수를 쓰므로 이런 불일치가 생길 수 없다.
- PMC 설립 화면의 지급 금액 표기 오류(7,000 → 실제 12,000).

## 3. 기존 기능과의 연결

- 각 시스템의 버전 게이트(`combatV`, `opsV`, `logisticsV`, `salvageV`, `piracyV`, `blackMarketV`, `lawV`, `repV`, `factionEcon`)는 그대로다. 프리셋은 이 게이트를 모두 켠 상태로 월드를 만들 뿐이며, 각 시스템의 규칙 자체는 바꾸지 않는다.
- 클라이언트는 상태에 실린 버전으로 UI를 고르므로, 표준 월드에서는 다음이 자동으로 나타난다.
  - 신용도 HUD
  - 평판·관계 탭
  - 세력 표시
- 계정은 월드와 분리된 저장소(DB 또는 `accounts.json`)에 있다. 리셋 뒤에도 로그인이 유지되고, 각 계정은 PMC 설립을 다시 받는다. A-2의 계정 정책과 일치한다.

## 4. 결정 필요 사항 (보고)

1. **운영 서버 기본값이 standard로 바뀐다.**
   - 운영 서버의 현재 저장 월드에는 영향이 없다.
   - 다음에 `WORLD_RESET`을 하거나 저장소가 비면 표준 월드가 만들어진다.
   - 운영 배포와 리셋은 이 작업에서 수행하지 않았다(승인 필요).
2. **가치사슬 가격(`ECON_PRICING=chain`)은 표준에 넣지 않았다.**
   - 로드맵의 통합 목록에 없고, 미승인 기본값으로 남아 있는 가격 방식이기 때문이다.
   - 넣으려면 `STANDARD_WORLD`에 `econ: 'chain'` 한 줄을 추가하면 된다.
3. **싱글플레이(브라우저 내 서버)는 여전히 P9 월드다.**
   - `src/client/net.ts`의 GameServer가 프리셋 없이 만들어지기 때문이다.
   - 로드맵 A-1이 "실제 서버"를 대상으로 하므로 바꾸지 않았다.
   - 싱글플레이도 표준으로 할지는 결정이 필요하다. 표준 월드는 틱 비용이 더 커서 배속 플레이에 영향이 있다(5절 참조).

## 6. 성능·장기 실행

`scripts/a1/a1-perf.ts 6`: 회사 3곳(아무 명령 없음), 시드 21, 6시간 진행. 서버와 같은 0.05초 스텝 20회 = 게임 1초.

| 월드 | 게임 1초당 ms (시작 → 6시간 후) | 1초 틱 ms, 시간대별 | 함선 | 저장 크기 |
|---|---|---|---|---|
| P9 (legacy 기본) | 6.40 → 12.27 | 10.0 · 10.8 · 10.4 · 9.9 · 9.8 · 10.2 | 159 | 347 KB |
| P10 배치만 | 7.54 → 10.92 | 12.6 · 11.6 · 12.4 · 13.4 · 12.7 · 13.4 | 182 | 393 KB |
| **표준** | 10.33 → 16.42 | 13.9 · 14.4 · 13.3 · 14.5 · 14.2 · 14.4 | 185 | 437 KB |

- 표준 월드의 서버 부하는 게임 1초당 약 16ms다. 한 코어의 약 1.6%이며, P9보다 약 1.3배다.
- 시간대별 틱 비용은 일정하다. 증가 추세가 없다.
- 잔해 1개, 이벤트는 상한 400, 저장 크기 437 KB로 누적 증가가 보이지 않는다.
- 관찰: 세 월드 모두 명령 없는 회사의 자금이 6시간 안에 0이 되었다. 운영비가 약 2,349 cr/h다. 이는 이번 변경과 무관한 기존 경제 사항이며, A-3(통합 플레이 검증)에서 다룬다.

회귀: 전체 vitest 896 통과, 16 건너뜀(PostgreSQL 필요 15, `OPS_LONG` 1). 기록은 `artifacts/a1/vitest-full.log`.

## 7. 남은 사항

- **A-2**(리셋 운영 절차와 일관성 심화)와 **A-3**(다계정 전체 플레이 흐름, 장기 보존 검증)은 별도 작업이다.
- 운영 서버에 적용하려면 배포 후 `WORLD_RESET=<토큰>`이 필요하다. 승인 전에는 수행하지 않는다.
