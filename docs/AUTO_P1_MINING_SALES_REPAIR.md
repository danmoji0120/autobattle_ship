# 자동 경제 운영 P1 — 채굴·판매 물류 통합과 자동 수리

AUTO-P0(재고 보호·초과 재고 판매, `docs/AUTO_P0_STOCK_SALES.md`)과 P0.1(정책 일관성)을 그대로 쓰고, 다음 세 가지를 더했다.
1. 재고를 용도별로 나누어 센다.
2. 채굴 편대의 수송선이 하역 후 초과 재고를 다른 시장에 팔고 돌아온다(판매 왕복).
3. 손상된 자동 수송선을 플레이어가 정한 예산 안에서 수리한다.

## 1. 재고 집계 기준 (`operations.ts`)
### 1.1 분류
`companyStock(w, owner, item)`이 회사의 한 품목을 다음처럼 나눈다. 모든 실물은 정확히 한 번씩 센다.

| 분류 | 내용 | 쓰임 |
|---|---|---|
| `stored` 확보 재고 | 모든 정거장 보관함 | 판매 상한(`companyHolding`, `companySaleCap`), 비축 목표 진행 |
| `incoming` 입고 예정 | 판매가 아닌 운송 작업이 보관함에서 꺼냈거나(`reserved`) 싣고 있는(`carried`) 화물 | 비축 목표의 중복 구매·생산 방지에만. 확보 재고로 보지 않는다 |
| `selling` 판매 중 | 판매 운송 작업의 `reserved` + `carried` | 이미 팔기로 한 양 |
| `afloat` 미확정 | 작업에 묶이지 않은 함선 화물(채굴선·자유 수송선) | 자산 합계에만. 판매 하한을 낮추는 근거로 쓰지 않는다 |
| `total` 전체 실물 | 보관함 + 모든 작업의 `reserved` + 모든 함선 화물 | 자산 표시 |

- 생산·건설·조선 예약은 이전과 같이 보관함 단위 하한(`industryHold`)으로 따로 보호한다.

### 1.2 바뀐 계산
- **`companyHolding`은 확보 재고만 센다.** P0.1까지는 판매가 아닌 운송 화물도 보유로 셌다. 이제 바다 위의 화물을 믿고 창고 재고를 팔지 않는다.
  - 예(요청의 기준 사례): 회사 목표 500, 창고 300, 다른 정거장으로 가는 수송선 화물 300 → 판매 상한 0. 창고의 300은 팔지 않는다.
- **회사 전체 비축 목표**: 진행은 확보 재고로 보고, 구매·생산 부족분은 `목표 − 확보 − 입고 예정`으로 계산한다. 이미 오는 화물만큼 다시 사지 않는다.
- **재고 화면(`companyInventory`)**: 행에 `incoming`(입고 예정)과 `afloat`(미확정 함선 화물)을 함께 싣는다.
- 채굴선 하역 판매는 P0.1처럼 하역 중인 양을 그 순간의 보유로 더해 계산한다(`companySaleCap(…, extra)`).

## 2. 채굴 수송선 판매 왕복
### 2.1 동작
- 설정: `autoOpsPolicy { minerSales: true }`. **기본은 꺼짐.**
- 채굴 편대 수송선이 하역지 정거장에서 하역을 마쳐 빈 배가 되었을 때만 `planMinerSaleTrip`이 판단한다. 채굴 운반이 여전히 주 임무이다.
- 조건(순서대로 검사, 하나라도 어긋나면 이유를 남기고 채굴 운반을 계속):
  1. 판매 정책이 있는 품목이 있다.
  2. 쓸 수 있는 유휴 공용 수송선이 없다. 있으면 그 배가 판매를 맡는다(공용 수송선 우선).
  3. 수송선 내구가 배차 하한(40%) 이상이다.
  4. 하역지의 판매 가능 초과분(`sellableStock`과 회사 판매 상한 중 작은 값)이 있고, 하역지 시장에서 최저 단가로 팔 수 없다(팔 수 있으면 P0 `planSales`가 현지 판매).
  5. 한 번에 실을 양의 60% 이상 모였거나, 창고 여유가 한 번 적재량 이하이거나, 초과분이 10분 넘게 남았다.
  6. P0와 같은 시장 선택(가격 하락·세금·시장 예산·다른 운송의 약속분·최저 단가·경로 위험 한도·정박·선석).
  7. 시장까지 3점프 이내(`MINER_TRIP_MAX_JUMPS`), 예상 판매액이 점프당 1,500 cr 이상(`MINER_TRIP_MIN_VALUE`). 먼 곳·적은 금액이면 왕복하지 않는다.
- 통과하면 P0의 판매 운송 작업(`kind: 'sell', sale: true`)을 만들고, 공용 배차 대신 그 채굴 수송선에 직접 배정한다(`assignMinerTrip`, 작업에 `miner: 편대 id` 표시).
  - 운송·도착 판매·최저 단가 재확인·대기·다른 시장 재지정은 P0/P0.1 판매 운송 코드를 그대로 쓴다.
- 판매가 끝나면 작업이 완료되고 수송선은 다음 틱부터 채굴 운반으로 돌아간다.
- 왕복 동안 채굴선은 기존 규칙대로 스스로 하역지에 가서 하역한다. 채굴 운반 대상(`haulers`)에서 왕복 중·수리 이동 중인 배를 빼서, 왕복과 채굴 수거가 서로의 배·화물을 가져가지 않는다.
- 왕복은 그 수송선 한 척만 움직인다. 채굴선이나 다른 함선에는 명령하지 않는다.

### 2.2 중단과 복구
- **함대 명령 변경**(편대 작전을 채굴이 아닌 것으로 바꿈, 예비·매물 지정 등): `maintainPool`이 작업을 취소한다. 화물은 배에 남고, 다시 채굴을 시키면 하역지에 내린다.
- **플레이어의 직접 명령**: 기존 `interruptPoolShips` 경로로 취소된다.
- **수송선 상실**: 작업이 취소되고 실은 양이 `lost`로 기록된다. 다른 배를 대신 보내지 않는다.
- **저장·복원**: 작업(`miner` 표시 포함)과 배의 `logisticsJob`이 저장되어, 복원 후에도 그대로 이어서 판매한다.
- **시장 사정 변화**: P0.1의 대기 코드(`market`/`price`/`budget`)와 재지정 규칙을 그대로 따른다. 화물은 판매되거나 배에 남는다.

## 3. 조건부 자동 수리 (`src/world/autoRepair.ts`)
- 설정: `autoOpsPolicy { repair: { enabled, minCredits, maxPerRepair, perHour } }`. **기본은 꺼짐.**
  - 켜려면 1회 최대 수리비와 시간당 수리 예산을 0보다 크게 정해야 한다(무제한 지출 불가).
  - 끄면 진행 중인 수리 이동도 취소된다.
- 대상: 공용 물류 수송선(대기 편대 소속)과 채굴 편대 수송선 중, 배차 하한(내구 40%) 아래로 손상된 배.
- 한도 검사(모두 만족해야 수리):
  - 1회 수리비 ≤ `maxPerRepair`.
  - 수리 후 잔고 ≥ max(`minCredits`, 회사 운영 정책의 최소 잔고).
  - 최근 1시간 자동 수리비 + 이번 수리비 ≤ `perHour`.
  - 회사 운영 정책의 시간당 자동 지출 한도(`hourlyLimit`) 안. 수리비는 그 지출 기록에도 남는다.
- 비용과 결제는 기존 수동 수리와 같다. `repairQuote` 견적으로 기존 `repair` 명령을 실행하므로 장부·업무 기록·이벤트가 그대로 남는다. 즉시 무료 수리는 없다.
- 위치:
  - 수리 가능한 정거장에 정박해 있으면 그 자리에서 수리한다.
  - 아니면 수리 가능·정박 가능·선석이 맞는 정거장 중 경로 위험 한도(`maxRisk`) 안에서 가장 가까운 곳으로 이동해(`repairAt`) 수리한다. 한 배에 수리 이동은 하나뿐이다.
  - 수리를 마치면 원래 자동 작업(공용 배차 또는 채굴 운반)으로 돌아간다.
- 채굴 수송선은 화물을 비운 뒤에만 수리하러 간다. 채굴 화물을 수리 정거장으로 가져가지 않는다.
- 한도·경로 조건이 맞지 않으면 화물과 작업을 그대로 두고, 배별 상태에 이유를 표시한다. 다음 10초 주기에 다시 판단한다.
- **승인 방식(판단 사항):** 자동 수리 정책을 켜고 한도를 정하는 것을 플레이어의 사전 승인으로 본다. 한도 안의 수리마다 결재 요청을 따로 만들지 않는다. 회사 운영 정책의 최소 잔고·시간당 자동 지출 한도는 함께 지킨다.

## 6. 검증
### 6.1 자동 시험 (`tests/autop1.test.ts`, 11건)
- 재고 집계: 창고 300 + 운송 중 300 + 채굴선 화물 50 → 확보 300 / 입고 예정 300 / 미확정 50 / 전체 650. 회사 목표 500의 판매 상한 0, 목표 진행 300, 추가 구매 결재 없음.
- 판매 왕복 꺼짐(기본): 왕복 없음, 규산염이 창고에 남고 판매 상태에 켜는 방법이 표시된다.
- 판매 왕복 켜짐(40분): 왕복 2회 이상 완료, 판매처는 앤빌이 아닌 규산염 매입 시장, 실제 단가 ≥ 최저 단가. 왕복 뒤 다시 광석 운반, 왕복 중 채굴선이 스스로 하역, 철광석 500 유지, 창고가 차지 않음, 판매 작업을 받은 배는 그 수송선뿐.
- 판매 불가 사유: 시장 모두 닫힘 / 최저 단가가 모든 시장보다 높음 / 위험 한도 0 → 왕복 없음, 이유 표시, 재고 보존. 유휴 공용 수송선이 있으면 그 배에 맡기고, 없애면 왕복이 시작된다.
- 왕복 중 편대 작전 변경: 작업 취소, 화물 보존(회사 전체 규산염 + 판매량 불변), 다시 채굴하면 하역지에 내린다.
- 왕복 중 수송선 상실: 작업 취소, 실은 양이 `lost`로 기록, 다른 배를 보내지 않는다.
- 왕복 중 저장·복원: 작업·배정·화물·잔고가 그대로 복원되고 판매가 끝까지 진행된다.
- 자동 수리: 기본 꺼짐(수리·지출 없음) / 한도 안에서 정박지 수리 1회(수리 명령의 업무 기록 포함) / 1회 한도·시간당 예산·최소 잔고 초과 시 수리 안 함·이유 표시·화물 보존 / 예산 0으로 켜기 거부 / 정박지에 수리 시설이 없으면 공용 수송선이 가까운 수리 정거장에 가서 한 번만 수리하고 복귀.

## 7. 판단 사항·남은 일
1. **판매 왕복 기본값:** 꺼짐. 채굴 운반이 잠시 멈추므로 플레이어가 켜도록 했다.
2. **왕복 한도:** 3점프, 점프당 1,500 cr는 상수다. 앤빌 시나리오에서 일부 소량 왕복이 이 기준으로 건너뛰어졌다. 정책 값으로 노출할지는 결정이 필요하다.
3. **채굴 수송선 수리 시점:** 화물이 빈 뒤에만 수리하러 간다. 하역지에 수리 시설이 있으면 하역 직후 그 자리에서 수리한다.
4. **결재:** 자동 수리 정책 자체를 사전 승인으로 본다(한도 안의 수리마다 결재 요청을 만들지 않는다).
5. **예산이 바닥난 시장에서의 대기:** 판매 왕복 배가 P0.1 규칙대로 다른 시장을 찾을 때까지 기다리는 동안, 채굴선은 스스로 하역해 채굴은 계속된다. 대기가 길어질 때 왕복을 끊고 화물을 가지고 돌아오는 규칙은 넣지 않았다.
6. **자동 수리 대상:** 자동 물류·채굴 운반 수송선만. 전투 편대·채굴선 자체는 대상이 아니다.
