## 1. 기존 시스템 분석(작업 전)

- 지휘관은 `WCommander`(`src/world/types.ts`): 판단력(`skill` 0..1), 공격성, 규율, 특기(`specialty`), 계급, 고용비, 부상, 사기. 편대(`WGroup.commanderId`)에 하나씩 붙고 상위 편대가 있다.
- 전투에서는 `CommanderDef`로 바뀌어 `src/sim/ai/commander.ts`의 판단 주기·협동 판정·표적 선택에 쓰였다.
- 기존 성장: 교전 1회마다 `12 + 격침/12` XP(전투만), `level × 100`을 넘으면 레벨업과 판단력 +0.03(최대 0.95). 분야·스킬·급여는 없었다. **이 규칙은 `officerV`가 없는 세계와 NPC 회사 지휘관에 그대로 남아 있다**(B-1 장교는 플레이어 회사 소속과 영입 풀만).
- BB(`x_bb`, `causal` 능력)는 계정 전용 지휘관으로 `grantExclusive`가 지급한다(`docs/BBEX.md`).
- 영입은 정거장마다 소유자 없는 지휘관 풀(`stationId`)에서 `hire` 명령으로 한다. 급여 개념은 없었다(고용비 일시불).
- **문서와 코드 차이**: README "지휘관이 전투 양상을 바꾸는 방식"은 판단력·특기만 다룬다. B-1 이후 장교 효과는 이 문서에만 기록되어 있다(README에는 요약과 링크만 추가).

## 2. 성장 규칙

모든 수치는 `src/world/officerData.ts`, 규칙은 `src/world/officers.ts`.

| 항목 | 값 |
|---|---|
| 최대 레벨 | 40 |
| 다음 레벨 XP | `round(60 · L^1.7)` — Lv1→2 60, Lv10→11 3,007, Lv39→40 30,406. Lv40까지 합계 454,511 |
| 스킬 포인트 | `spForLevel(L) = 1 + (L−1) + floor(L/10)` → Lv40에서 44 |
| 숙련도 단계 | 미숙 0 / 입문 500 / 숙련 2,000 / 전문 6,000 / 대가 15,000 / 전설 35,000 |
| 단계 게이트 | 1 기초(Lv1) · 2 중급 전문(Lv3·입문) · 3 고급 분기(Lv8·숙련) · 4 분야 연계(Lv15·전문) · 5 최종 전문화(Lv25·대가) |
| 최종 전문화 | 장교당 최대 2개(`MAX_CAPSTONES`) |
| 시간당 XP | 게임 1시간에 1,500(SOFT)까지 전액, 그 위로는 감액, 4,000(HARD)에서 정지 |
| 훈련 방향 | 지정 분야 숙련도 +25%, 1시간마다 변경 가능 |
| 특성 | 26종(특기별 기본 특성 + 일반 특성). 작은 상시 효과 |
| 성장 재능 | 0~+30% 경험치. 일반 장교가 더 높게 나온다(고유 장교는 앞서 시작하는 대신 낮음) |

- **경험치와 숙련도는 따로 쌓인다**: 같은 실적이 장교 XP(레벨→SP)와 해당 분야 숙련도(단계 게이트)를 함께 올린다. 숙련도 분배는 실적의 분야 가중치를 **최댓값으로 정규화**한다(주 분야는 실적 전액, 보조 분야는 비율만큼). 처음에는 합으로 정규화했으나 전투(여러 분야 동시)가 채광(단일 분야)보다 숙련도가 크게 느려져 바꿨다 — **설계 판단, §12-1**.
- **모든 캡스톤 마스터가 어려운 이유**: 44포인트, 최종 전문화 2개 제한, 단계 5에 대가(15,000) 숙련도 필요, 같은 트리 안 택일. 시험 `mastering every capstone is impossible…`이 Lv40 장교도 13개 트리 26개 최종 노드 중 2개만 가질 수 있고 포인트가 모자람을 확인한다.

## 4. 효과 적용

- **보직 범위**: 편대 지휘관은 자기 편대(하위 편대 함선 포함) 작업에만, 정거장 책임자는 그 정거장의 생산·연구·조선에만 효과가 있다. 한 장교가 두 보직을 가질 수 없어 이중 적용이 없다.
- **상위 지휘관 오라**: 상위 편대 장교의 오라(`aura`, `auraAir`, `mineAura`)는 하위 편대에 **최댓값**으로만 적용된다(합산 아님). 부상 장교는 효과가 없다.
- **전투**: 서버가 전투 시작 때 `CommanderDef.ofx`로 효과 묶음을 넣는다. 전투 엔진은 이 값만 읽으므로 재생(리플레이)이 결정적이다. 적용 지점은 `src/sim/world.ts`(명중·연사·사거리·피해·장갑·PD·회피·재밍·재생·화재·후퇴 속도 등)와 `src/sim/ai/commander.ts`(판단 주기·협동).
- **월드 시스템**: 채굴(`sim.ts` 채굴 단계, 마모 `upkeep.ts`), 인양(`salvage.ts`), 물류(`logistics.ts`, `autonomousLogistics.ts`, `sim.ts` 운송 속도·하역), 생산(`production.ts`), 연구(`research.ts`), 조선·건설(`sim.ts`), 탐사(`sim.ts` 탐사·유적), 정비·보급·수리(`upkeep.ts`, `repair.ts`), 재가동(`sim.ts` `reactivateS`), 함대 AI 위협 판단(`fleetops.ts`), 해적 표적 선택(`sim.ts`, 은신).
- **캐시**: `officerFx`는 장교의 `rev`(습득·보직 변경 때 증가)로 캐시. 정거장 책임자 캐시는 보직 변경 시 삭제. 전투 지휘관 메모(`cmdrMemo`)는 장교·부상·`rev`·상위 편대를 키로 하고 모든 명령 시작 때 비운다(같은 틱 안의 습득·부상·재배치가 바로 반영되도록).
- **설명 = 효과**: 노드 설명 줄은 효과 값에서 생성된다(`nodeLines`). 시험이 모든 노드의 단계별 설명이 실제 값과 일치함을 확인한다.
- **엔진이 읽는 효과**: 시험 `every effect key is read by the engine`이 `src/`(클라이언트·데이터 표 제외)를 스캔해 83개 효과 키 전부가 읽힘을 확인한다.

**수치로 측정한 대표 효과(시험)**

## 5. 경험치

| 출처 | 지급 기준 | 분야 |
|---|---|---|

| 정비 | 장교 편대 정박 정비비 | 군수 |

**악용 방지**
- 적대 관계가 아닌 상대, 교전하지 않은 전투, 자기 함대 공격은 0. PvP는 선언된 적에게만(양쪽 장교 지급).
- 일회성 지급(전투·배송·발견·조선)은 키로 기록되어 두 번 지급되지 않는다.
- 게임 1시간 예산(SOFT 1,500 / HARD 4,000)으로 반복 파밍이 선형으로 늘지 않는다.
- 대기·반복 명령·보직 변경은 XP 0.
- 지급량은 실적(가치·초)에 비례하고 틱 길이와 무관(시험이 같은 채굴을 서로 다른 틱으로 돌려 비교).

## 6. 일반 장교와 고유 장교

- **일반 장교**: 영입 풀에서 무작위 생성. 성장 재능이 높아(경험치 +0~30%) 빨리 큰다.
- **고유 장교 11명**: 정거장 영입 풀에 낮은 확률로 등장(해시 기반 판정 — 아래). 시작 숙련도가 있고 서명 노드 1개를 쓸 수 있지만, 약한 분야가 하나 있고(그 분야 숙련도 성장 감소) 성장 재능이 0이며 급여 ×1.3. 효과 상한은 일반 장교와 같다. 시험 `named officers…`는 서명 노드 허용, 약한 분야, 재능 0 대 일반 장교 재능 > 0, 같은 상한, 같은 고유 장교 중복 등장 없음을 확인한다. **같은 실적 뒤의 성장 비교를 실행으로 측정한 시험은 없다**(§13).
- **BB**: `causal` 능력을 그대로 유지하고 일반 장교처럼 육성된다(서명 노드 `NAMED_BB`, 시작 숙련도). BB 판별을 id(`x_bb`)가 아니라 `causal` 유무로 바꿨고, `grantExclusive` 뒤에 장교 초기화를 부른다.
- **난수열 중립**: 고유 장교 등장 판정은 `hashId(named:정거장:분)`으로 하고, 등장하더라도 일반 장교 생성과 같은 난수를 소비한다. B-1을 켜도 월드 난수열이 바뀌지 않는다(처음 구현에서 `rng.chance` 한 번이 난수열을 밀어 A-3.2b.2 저장·복원 시험이 실패했던 것을 고쳤다 — §12-3).

## 7. 고용과 급여

| 보직 | 시간당 급여 |
|---|---|
| 대기 | 30 |
| 편대 지휘 | 80 + 함선당 15(최대 300) + 하위 편대당 20 |

- **체불**: 급여는 일반 운영비 미납금이 되고 기존 체납·회생(A-2.1) 규칙을 따른다. 장교가 명령을 거부하거나 이탈하는 규칙은 넣지 않았다(요구 사항).

## 10. 기존 저장과 마이그레이션

- 게이트: `WorldState.officerV === 1`. 새 표준 세계(`STANDARD_WORLD`)는 B-1을 켠다(`officers: 'b1'`). `worldRules`에 `officers` 항목.
- **기존 저장은 그대로**: `officerV`가 없는 저장은 B-1 이전과 똑같이 동작한다(효과·XP·급여 없음).
- **명시적 전환**: 서버 환경 변수 `OFFICERS_B1_MIGRATE=1`일 때만 저장 로드 시 `migrateOfficers`가 돈다. 플레이어 회사 지휘관과 영입 풀 지휘관에 `of`를 붙인다. 기존 레벨·판단력·특기·전적은 유지하고, 기존 XP는 같은 진행 비율로 새 곡선에 옮기며, 기존 누적 XP와 교전 수로 전투 숙련도를 시작값으로 준다(대가 미만, 최대 14,999). 스킬 포인트는 현재 레벨만큼 지급. 그 외 필드는 바꾸지 않는다(비파괴). 두 번 실행해도 결과가 같다(멱등, 시험으로 확인). 결과는 서버 로그에 남는다.
- 운영 서버·운영 DB에는 적용하지 않았다. 전환 시 기존 운영비에 급여가 더해진다는 점(§7)을 운영 판단 사항으로 남긴다.

## 11. 육성 시뮬레이션(실제 WorldSim)

**산업 신병**(시험 `an industry rookie…`): Lv1로 영입 → 채굴 편대 지휘 → 게임 6시간 채굴.
- 결과: Lv7, 채광 숙련도 5,052(숙련), 시간당 약 676 XP(SOFT 예산 1,500 아래 — 정상 플레이로 예산에 걸리지 않음), 전투 XP 0.
- 습득: `mn_rate`(단계 1) → 단계 2 노드, 장교 효과 `mine` > 0.
- 이 시험 안에서는 채굴량 증가와 정거장 책임자 배치를 다시 재지 않는다. 같은 효과가 실제 채굴량을 올리는 것은 `mining skills raise the real output…`, 책임자 효과는 `a station director speeds up production…` 시험이 따로 확인한다.

**전투 신병**(시험 `a combat rookie…`): Lv1로 영입 → 적대 회사 편대와 실제 교전 8회(정산 9건).
- 결과: Lv4, 전투 XP 726, 기동 숙련도 545(입문), 포술 312.
- 습득: 포술 `gn_aim`, 방어 `df_armor`, 기동 `mv_turn` → 단계 2 `mv_evade`(입문 + Lv3 게이트 통과). 편대 전투 설정(`sim.cmdr(g).ofx`)에 명중 효과가 들어감을 확인.
- 전투 신병은 산업 신병보다 레벨이 느리다(교전 8회 ≈ 몇십 분 vs 채굴 6시간이라 직접 비교는 어렵다). 교전 빈도는 플레이에 달려 있어 장기 전투 성장 속도는 §12-1에서 조정 대상으로 남긴다.

**Lv40 도달 시간**: 합계 454,511 XP. SOFT 예산(1,500/시간)으로 약 300시간, HARD 상한(4,000/시간)으로도 최소 114시간 — 오래 키운 장교의 가치를 유지하려는 의도다.

## 12. 설계 판단(사용자 확인 필요)

1. **XP 밸런스**: 숙련도 분배를 최댓값 정규화로, 전투 XP 기본값을 15→25·격침 가치 /8→/6으로 바꿨다. 목적은 전투 장교와 산업 장교가 비슷한 시간에 중급(단계 2)에 이르게 하는 것. 장기 전투 성장 속도는 실플레이 데이터로 다시 보는 것이 좋다.
2. **표준 세계 포함**: 새 표준 세계는 B-1을 켠다. 기존 저장은 플래그 없이는 바뀌지 않는다.
3. **급여 공식**(§7): 소규모 회사 부담을 줄이려 대기 30, 편대 80부터 시작한다. 경비대 배경(지휘관 1명, 3척) 기준 시간당 125 cr.
4. **마이그레이션 플래그**: `OFFICERS_B1_MIGRATE=1`. 운영 적용 여부·시점은 정하지 않았다.

## 13. 백로그(이번 범위 밖)

1. 장교별 효과 개별 수치 시험 확대(§9-2의 정적 확인 항목을 실행 측정으로). 고유 장교 대 일반 장교의 같은 실적 뒤 성장 비교 시험.
2. 모바일 스킬 트리 확대·이동(지금은 축소된 SVG를 그대로 보여 줌, 글씨가 작음).
3. 장교 은퇴·부상 회복 치료·재훈련(포인트 재분배) — 지금은 재분배 없음.

5. NPC 회사 장교 육성(지금은 NPC 지휘관에 성장 없음, 플레이어 회사만).
6. **A-3.2b.2 시험의 시드 의존성**: 고유 장교 등장 판정이 난수 한 번을 더 쓰자 `a32b2` 저장·복원 시험(판매 재시도 대기)이 깨졌다. B-1은 난수 중립으로 고쳤지만, 그 시험이 특정 난수열에 기대고 있다는 점은 별도로 견고하게 만들 필요가 있다.
