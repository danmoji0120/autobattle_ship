# DEV-1 개발자 전투 실험실

## 범위

기준은 P9.6.3.1 `ae8996f8d18dc1d63606924ea893ea83811ebf3b`이다. `/?devskirmish=1`은 일반 메뉴와 기존 `?skirmish`와 별도의 인증 화면으로 진입한다. 함대·피팅·전투·반복 실험은 브라우저에서 독립적으로 실행하며 계정의 PMC 생성, 월드 명령, 자산, 전투 기록 또는 저장을 사용하지 않는다. 일반 메뉴에는 진입 버튼을 추가하지 않았다.

## 서버 인증과 운영 설정

- 기존 계정 쿠키의 서버 세션을 조회하고 `ANALYTICS_ADMIN_ACCOUNTS`의 계정 UUID를 확인한다. 클라이언트의 UUID·관리자 여부·URL은 권한 근거가 아니다.
- 별도로 `DEV_COMBAT_LAB_PASSWORD_HASH`의 scrypt 해시를 검사한다. 계정 시스템과 동일한 `scrypt$N$r$p$salt$hash` 형식이며 잘못되거나 없는 해시는 거부한다. 평문은 빌드·URL·저장·로그에 넣지 않는다.
- 해시는 터미널에서 `npx vite-node scripts/dev1-password-hash.ts`를 실행해 비밀번호를 **표시하지 않고** 입력해 생성한다. 출력된 해시만 서버의 비밀 환경변수에 설정한다. 운영 비밀번호를 명령 인자나 셸 기록에 넣지 않는다.
- 성공하면 15분 만료의 별도 256비트 무작위 토큰을 `HttpOnly; SameSite=Strict` 쿠키로 전달하고 서버 메모리에 해시만 저장한다. HTTPS 요청에서는 `Secure`를 추가한다. 계정 세션·관리자 목록·계정 비밀번호 변경 시각·실험실 비밀번호 해시가 모두 일치해야 한다. 같은 계정 세션에서 토큰을 재발급하면 이전 토큰을 폐기한다. 계정 로그아웃, 비밀번호 변경·복구, 실험실 잠금, 서버 재시작 또는 만료 시 무효화된다.
- 로그인 POST는 정확한 동일 출처 `Origin`과 JSON을 요구한다. 계정과 IP 각각 15분 내 다섯 번의 시도를 허용하고 다음 요청을 제한한다. 비동기 scrypt 전에 시도를 기록해 동시 요청도 제한한다. 기존 계정 인증과 관리자 분석 권한은 변경하지 않는다.
- 운영 빌드의 `devCombatLab-*`과 `combatLabWorker-*` JavaScript는 서버가 두 세션을 확인한 뒤 `private, no-store`로 제공한다. 실험 시작·재현 전 서버에 세션을 다시 확인하고, 열린 화면은 30초마다 확인한다. 실험 자체는 서버에 요청하지 않는다.
- **배포 전제:** TLS 종단 프록시는 신뢰할 수 있는 `Host`와 `X-Forwarded-Proto: https`를 전달해야 한다. 두 보호 JavaScript 파일은 이 Node 서버를 통과해야 하며, 인증을 우회하는 공개 CDN·정적 호스팅에 직접 게시하면 안 된다. 쿠키·세션과 실패 제한은 프로세스 메모리이므로 다중 인스턴스는 세션 고정 또는 공유 인증 저장소와 전역 제한이 필요하다. 서버 재시작은 전용 세션과 실패 카운터를 초기화한다.
- 브라우저에서 이미 받은 코드나 기존 공개 전투 엔진을 사용자의 기기에서 독립적으로 실행하는 것까지 서버가 막을 수는 없다. 보호 대상은 실험실 진입과 코드 제공이며, 전용 세션은 어떤 PMC 또는 게임 서버 명령 권한도 부여하지 않는다.

## 편성과 전투

`CONTENT.hulls`에서 개발 전용(`dev`) 선체를 제외한 모든 선체를 검색하고, 모든 파생형과 등록 무장·내부 장비를 선택한다. 각 하드포인트·베이에 대한 크기, 종류, 장착 방식, 전력과 질량을 기존 `variantLayout`·`checkFitting`으로 검사한다. 선택지에 호환되지 않는 장비도 남겨 두되 오류를 표시하고 시작을 막는다. 연구·설계도·재고·비용 조건은 적용하지 않는다.

함선 항목마다 수량·편대 이름·초기 명령·피팅을 설정하며 양쪽 복사와 교환을 지원한다. 지휘관 능력과 실제 전투 효과가 있는 연구는 진영별로 설정한다. `shipLoadout`, `fitFx`, `growthFx`로 게임의 모델·무장 배치·능력치를 만들고 `World`, `BattleSession`, `BattleHUD` 및 기존 렌더러로 실행한다. 선택적 `BattleSetup.timeLimit`이 없는 기존 게임 전투는 종전 540초 규칙을 그대로 사용한다.

설정은 콘텐츠 버전과 실제 콘텐츠·전투 데이터의 FNV-1a 식별자를 포함한 JSON으로 가져오고 내보낸다. 식별자가 다르거나 피팅이 유효하지 않은 설정은 가져오지 않는다. 결과 JSON에는 설정과 전투별 시드·배치·결과·상태 해시 및 집계를 포함한다. 실험실 설정을 자동으로 월드 저장이나 localStorage에 쓰지 않는다.

반복 실행은 브라우저 Worker에서 실제 `World`를 렌더링 없이 실행한다. 각 시드를 기본 배치와 교환 배치에서 실행할 수 있고 진행률·취소와 결과별 재현을 제공한다. 브라우저 자원 보호를 위해 한 전투 최대 200척, 반복은 최대 10,000개 시드(교환 시 20,000회)로 제한한다. 비용 예산은 없다. 관전·반복 결과는 같은 전투 조건을 공유한다.

진영별 표시 수치는 전투당 평균이다. 생존은 살아 있거나 이탈한 함선, 손실은 침몰 중이거나 침몰한 함선, 격침은 엔진의 함선별 `kills` 기록이다. 피해는 엔진이 기록한 선체 피해로 방어막 흡수량은 포함하지 않는다. 유폭 피해는 받은 쪽에만 기록될 수 있다. 무장별 피해나 최초 격침 시각은 별도로 추정하지 않는다.

## 검증과 제한

- 최종 코드의 단일 워커 전체 회귀는 **347개 통과, 0개 실패, 9개 건너뜀**이다 (44개 파일 통과, 약 1,026초). 건너뛴 9개는 아래 일회용 PostgreSQL에서 별도로 모두 통과했다. 타입 검사·운영 빌드 통과, 콘텐츠 검사 오류·경고 0개. `artifacts/dev1/full-regression.txt`, `typecheck.txt`, `build.txt`, `content.txt`.
- 표적 테스트는 관리자·일반 계정, 해시 누락, 잘못된 비밀번호·동시 요청 제한, 세션 만료·로그아웃·계정 비밀번호 및 전용 해시 변경을 검사한다. 동일 출처와 보호된 빌드 파일 제공은 임시 파일 저장소의 실제 Node 서버에서 검사한다.
- 계정·OBSERVATORY 분석·피팅·전투를 포함한 관련 검사 72개와 별도의 신규 1,000회 엔진 집계 검사가 통과했다. 루프백에만 바인딩한 일회용 PostgreSQL에서 신규 관리자 인증 1개와 기존 저장·복원 회귀 8개가 통과했다 (`artifacts/dev1/targeted.txt`, `final-focused.txt`, `postgres.txt`, `postgres-regression.txt`).
- 운영 빌드 브라우저 검사 46개가 통과하고 런타임 오류는 0개였다. 실제 로그인·피팅 검증·함대 복제/교환·JSON·실시간 전투·일시정지·재시작·리플레이·Worker·결과 재현을 사용한다. 1440px과 390px 화면을 확인하고 임시 계정과 임시 월드만 사용한다. [편성 1440px](../artifacts/dev1/setup-1440.png), [편성 390px](../artifacts/dev1/setup-390.png), [전투 1440px](../artifacts/dev1/battle-1440.png), [전투 390px](../artifacts/dev1/battle-390.png).
- 브라우저 검수 중 입력값 변경과 화면 재그리기가 중첩되어 DOM 오류가 발생했고 (`artifacts/dev1/browser-diagnostic.txt`), 재진입 방지 후 재검증했다. 기존 HUD의 작은 화면 배속 버튼이 화면 밖에 있던 문제는 실험실 관전에 한정해 배치했다. GPU 가속이 없는 테스트 환경의 관전 프레임 속도는 실제 GPU 성능 수치가 아니다.
- 개발자 계정·전용 해시의 실제 운영 설정과 배포는 수행하지 않았다. 다중 서버 인증 공유, 무장별 통계와 장시간 실제 GPU 부하는 이번 검증 범위 밖이다.
