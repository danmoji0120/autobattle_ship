# 경제 B안 (가치 사슬 가격) — 실게임 적용 준비와 검증

작업 브랜치: `ccr-f3f46604-1jievd` (기준 `feature/company-ops`). 이 문서의 모든 월드·저장은 격리된 개발용이다.
운영 배포, `deploy/production` 병합, Render 배포, 운영 Supabase DB 변경, 운영 월드 이관은 **하지 않았다**.
B안은 **월드별 선택(opt-in)** 이며 기본값은 꺼져 있다. 아래의 실험값은 승인 전까지 운영 기본값이 아니다.

배경 분석과 B안 선정 이유는 `INDUSTRY_ECONOMY_BALANCE.md`, 확장 우주(P10)에서의 재검증은 `P10_UNIVERSE_FACTIONS.md` 6.4절.

## 1. 규칙

| 대상 | 기준가 |
|---|---|
| 원자재 | 기존 기준가 × 0.25 |
| 가공품 | (투입 가치 × 1.15 + 레시피별 부가가치율 × 생산 시간) ÷ 산출량 |

| NPC 함선 가격, 수리비, 함선 가치 | **변경 없음** (`valuation.ts` c4-b1 고정 — 선택지 A) |

## 2. 켜는 방법 (개발용)

| 상황 | 방법 |
|---|---|
| 새 월드 | `WorldSim.create(seed, { econ: 'chain', eq?, alloyDirect? })`, 서버는 `ECON_PRICING=chain` (첫 시작·`WORLD_RESET` 때만) |
| 기존 c4 저장 | 서버 `ECON_MIGRATE=apply` (원자적 백업 → 변환 → 검증 → 기록), 개발 사본은 `scripts/econ/migrate-save.ts` |
| 끄기 | 아무 것도 설정하지 않음. 플래그 없이 시작하면 이관 사전 점검 결과만 로그로 남긴다 |

c0~c3 저장은 이관을 거부하고 바이트 단위로 그대로 둔다(테스트). 콘텐츠 이관(`CONTENT_MIGRATE`)과 함께 지정하면 콘텐츠 이관 후 같은 트랜잭션 안에서 적용된다.

## 3. 기존 저장 이관 (c4 → e1)

**바뀌는 것**: 공개 NPC 시장 품목의 `base`, `st.econ`(규칙·정책), `st.econLog`(이전 기준가 전부 — 서버 전용, 클라이언트에 보내지 않음).
**보존되는 것**: 시장 재고·목표 재고, NPC 예산, 모든 회사의 현금, 창고, 화물, 예약, 생산·건설·조선 대기열(진행 중 배치는 시작 당시 산출 유지), 연구, 업무·결재·예산, 함선·장비. 자산 센서스가 이관 전후 동일해야 기록된다.

| 성질 | 확인 방법 | 결과 |
|---|---|---|
| 전부 아니면 전무 | 모든 기준가를 먼저 계산·검증한 뒤에만 기록 | 테스트 |
| 멱등 | 두 번째 실행 변경 0, 저장 동일 | 테스트, 리허설, PG |
| 재시작 안전 | 플래그를 둔 채 재시작해도 재이관 없음 | 리허설, PG |
| 백업 | 서버 이관은 기존 백업 경로(`backup-pre-v….c4.e0`), 내용 검증 후 기록 | 리허설(sha256 일치), PG(백업 행) |
| 구 인스턴스 덮어쓰기 차단 | 월드 세대 증가 → 구 인스턴스의 자동·종료 저장 거부 | PG |
| 롤백 (데이터) | 백업을 되돌려 놓고 플래그 없이 시작 | 리허설, PG — 기준가 완전 복원 |
| 롤백 (econ) | `migrate-save.ts rollback` 또는 `rollbackEconChain`: 기록된 기준가 복원, 규칙 제거 | 리허설 — 124개 기준가 전부 백업과 일치 |
| 롤백 (코드만) | 이전 빌드로 이관된 저장을 열기 | 열리고 저장도 유지되지만 **혼합 상태**(B 기준가 + 옛 규칙: 직접 합금 14, 옛 정비 단가) — 코드 롤백만으로는 부족, 데이터 또는 econ 롤백을 함께 해야 함 |

롤백의 한계: 이관 이후 새 가격으로 체결된 거래는 되돌리지 않는다(데이터 롤백은 그 시점 이후 진행 전체를 잃는다). econ 롤백 후 `ECON_MIGRATE=apply`를 그대로 두면 다시 이관되므로 플래그를 먼저 내려야 한다.

### 운영 이관 절차 (승인 후, 이번 작업에서는 실행하지 않음)

1. 운영 DB 스냅샷을 별도로 확보한다.
2. 새 빌드를 플래그 없이 배포 → 로그의 `econ migration DRY RUN e0→e1: … census OK` 확인.
3. `ECON_MIGRATE=apply` 로 재시작 → `save migration committed: backup backup-pre-v4.2.c4.e0 verified` 확인.
4. 구 인스턴스 종료 후 로그에 `저장 거부: 더 새로운 월드 세대` 가 남는지 확인.
5. 문제가 생기면: 플래그 제거 → 백업 행을 `main`에 복원(데이터 롤백) 또는 econ 롤백 도구 사용 → 재시작.

## 4. 결정이 필요한 6가지 (보류 — 실험값으로만 구현)

### 4.1 함선 가격: A (현행 유지) / B (부품 연동) / A′

- **A (구현됨)**: NPC 함선 가격·수리비 불변. 자체 건조 대비 NPC 구매 비율이 바뀐다 — 구축함 자체 건조/NPC 0.53 → 0.84, 무장 포함 0.60 → 1.01(장비 정책 chain). 순양함 0.35 → 0.48, 전함 0.26 → 0.33. 소형 선체는 이미 NPC보다 2~2.7배 비싸다.
- **B (비교만)**: 부품 가치로 NPC 가격 산정 시 구축함 191.2k(현 116.5k), 순양함 947.9k, 전함 3.288M, 호위함 24.6k, 초계함 17.7k. 수리비·함선 가치·임대·보험이 함께 오르므로 영향 범위가 크다.
- **A′ (제안)**: 선체 가격은 유지하고 기본 무장분만 현재 장비 가치로 더한다. 아래 "무장 분해" 문제를 근본적으로 막는다.
- 무장 분해 검증(`scripts/econ/strip-probe.ts`, 실제 명령, 3시간, 순간이동 운송 = 상한): NPC 함선을 사서 기본 무장을 떼어 NPC 시장에 팔면, 정적 첫 단위 비율은 chain에서 초계함 1.19로 이익이지만 실제로는 시장 포화·NPC 예산 때문에 모든 정책에서 손실이다 — chain −237k, margin −381k, keep −680k, 기존 −649k (지출 990k, 선체는 남음). 지속 가능한 무한 루프는 아니지만 chain에서는 "무장을 판 뒤 남는 선체"가 매우 싸진다(구매가의 24%).

### 4.2 장비 가격 정책: chain / keep / margin

| 정책 | 장비 시장가 | 장비 생산 라인 이익/h (회수) | 재무장 비용 |
|---|---|---|---|
| chain (실험 기본) | +92~152% | +7k~13.7k (11~52h) | 약 2배 (구축함 무장 8.6k → 17.9k) |
| keep | 0% | 적자 −4.6k~−8.4k (mod_ecm만 +1.2k) | 불변 |
| margin (투입×1.4 + 노무) | +37~113% | +2.4k~11k (21~108h) | 1.4~2배 |

### 4.3 스프레드·세금

변경하지 않았다. 원자재가 0.25배가 되면서 싼 원자재(광석)는 과잉 재고일 때 0.1 cr 반올림으로 매수=매도가 되는 경우가 있다(이익 0, 손실 아님 — 테스트로 "이익 불가"만 보장). 스프레드 변경은 비교 대상일 뿐 적용하지 않음.

### 4.4 직접 합금(alloy_direct) 산출

정적 분석(정제소, 시장 광석): 산출 4 −1.5k/h, 5 +1.0k(회수 62h), 6 +3.5k(18h), **7 +6.0k(10.5h)**, 8 +8.5k(7.4h), 10 +13.5k, 14 +23.5k. 참고: 금속 라인 +6.5k/h(9.7h), 정식 합금 공장 +15.9k/h(7.6h).
7은 "금속 라인과 비슷하고 정식 합금 공장보다 확실히 나쁜 대체 경로"가 되는 값이다(잠정 권고). 실측은 5절.

### 4.5 기존 저장 처리 방식

구현: 기준가만 바꾸는 이관 + `econLog` 기반 롤백. 대안: 기존 저장은 그대로 두고 새 월드만 B(가장 안전, 대신 월드 간 가격 체계가 갈림). 영향은 6절.

### 4.6 새 P9/P10 월드의 B 기본 적용

현재 꺼져 있음(`ECON_PRICING` 미설정). 켜려면 승인 필요.

## 8. 알려진 문제·주의

- **정비 서비스 단가 vs 다른 지역 매입가 (기존 문제)**: 장착 화면에서 부족한 장비를 서비스로 사는 단가(기준 가치 × 1.2)가 일부 무기에서 다른 지역의 최고 매입가보다 낮다. 기존 월드에서도 같은 비율(예: 중형포 1.205)로 존재하며 B안이 넓히지 않는다(테스트로 고정). 해결하려면 정비 단가 규칙 변경이 필요 — 별도 결정 사항.
- 싱글플레이 저장은 브라우저의 `siderarium.sp.token`에 묶여 있다. 저장 키만 다른 브라우저 프로필로 옮기면 새 회사가 만들어진다(기존 동작, B와 무관).
