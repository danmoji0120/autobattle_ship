## 마이그레이션 원자성·세대 보호 (2026-11-06, 운영 적용 전 수정)

**문제 (검증됨):** `CONTENT_MIGRATE=apply` 경로는 백업만 별도로 쓰고, 마이그레이션은 메모리에서 한 뒤 첫 자동 저장(30초 후)에
**같은 `gen`** 으로 썼다. 그래서 Render 무중단 배포 중 남아 있는 이전 인스턴스(c0)의 자동 저장·종료 저장도 `WHERE gen = …`를
통과했다. 로컬 Postgres + 수정 전 빌드(04df46d)로 재현:
```
 8.3s [B] 백업 → 메모리 마이그레이션 (DB는 gen 0, c0 그대로)
38.6s DB main → gen=0 contentV=2   (B 첫 자동 저장)
51.3s SIGTERM A → A 종료 저장
51.4s DB main → gen=0 contentV=0   ← 이전 인스턴스가 c2를 c0으로 덮어씀
68.4s DB main → gen=0 contentV=2   (B 다음 자동 저장까지 17초간 c0)
```
그 사이 B가 재시작되면 c0을 다시 읽는다. 백업도 B의 로드 시점 데이터일 뿐 실제로 덮어쓴 데이터와 같다는 보장이 없었다.

**수정 (`src/server/node.ts` `Storage.migrate`):** 잠금(`FOR UPDATE`) → 잠근 데이터의 서버 측 백업 복사·md5 검증 → 변환·센서스·왕복
검증 → `gen + 1`로 쓰기·재조회 비교 → `meta:migrate` 기록 → COMMIT을 한 트랜잭션으로 묶었다. 실패하면 전부 ROLLBACK되고 서버는
시작하지 않는다. 이전 인스턴스의 저장은 잠금을 기다렸다가 거부되고, 그 인스턴스는 펜스된다(종료 저장도 건너뜀). 파일 저장소도 같은
인터페이스(백업 파일 → 원자적 rename)를 쓴다. `WORLD_VERSION`·`INDUSTRY_VERSION` 마이그레이션도 같은 경로를 탄다.
dry-run(기본) 경로는 바뀌지 않았다. 부가: `SAVE_INTERVAL_S`(기본 30), 테스트 전용 `SIDERARIUM_TEST_MIGRATE_HOLD_MS`.

  - 조선소 4급 선체(드레드노트)는 NPC가 팔지 않는다.
  - 재입고에는 지역 시장의 자재를 쓴다.
- **자체 조선소는 실제로 비용을 낸다** (인건비 + 운영비). 착공 전 취소하면 정확히 환불된다.
- **플레이어 간 함선 거래는 가치를 보존한다.** 구매자가 낸 금액 = 판매자 수령액 + 세금. 함선과 피팅은 그대로 옮겨지고, 같은 매물을 두 번 살 수 없다.
- **차익·복제 루프가 없다.**
  - 레시피 그래프의 모든 순환은 수량 이득이 1 미만이다.
  - 시장에서 같은 물건을 샀다 되팔면 항상 손해다.
  - NPC는 함선을 되사지 않는다.
- 근거 테스트는 `tests/econ-baseline.test.ts` (8건)이다.
- 지시대로 8/24/72h 반복 시뮬레이션은 하지 않았다. 확인용으로 8h ×1을 한 번 돌렸다: 순익 133k, 회수 2.4h. 초보자 성장이 가능함을 확인했다.
- **수정한 버그 2건**
  - rev 2의 c0 회귀: c0 건조에 성장 산업 기반(TIER_BASE)이 걸리던 문제. `hullBuild(…, growth)` 로 고쳤다.
  - `SALE_BY_CLASS['constructor']` 가 프로토타입을 읽어 가격이 NaN이 되던 문제. `Object.hasOwn` 으로 고쳤다.

### 2. 로더 (`src/render/modelLoader.ts`)

- 에셋 id → GLTFLoader 로 1회 로드 (파일 단위·길이 단위 Promise 캐시, 중복 요청 없음).
- 정규화: 함급 길이 × `mesh.scale` 로 균일 축척(원점 기준), 선택적 `recenter`.
- 모델을 재질별 기하로 굽고, 삼각형 중심 z 로 앞·뒤 반쪽을 나눈다. `sid_*` 재질은 진영 재질로 바꾸고, 진영 재질에는 박스 투영 UV를 붙인다.
- `engine_*`(노즐 반지름 = 노드 크기)·`light_*` 마커 → 엔진 불빛·분사·항법등 위치.
- LOD 에셋이 있으면 `THREE.LOD` (선체 길이 × 14 이상에서 전환).
- 로드 중에는 절차적 선체를 그리고, 완료되면 같은 객체 안에서 교체한다. 실패(404·형식 오류)하면 경고 1회 후 절차적 선체를 유지한다. 함선이 사라지거나 예외가 나지 않는다.
- 끄는 스위치: `?models=0` 또는 `localStorage sid.models=0`.
- 미리보기: `?modelview=<hullId>` (`src/render/modelPreview.ts`).
- c0 보호: 모델은 core 팩 선체에 연결할 수 없다(검증 오류). c0 함선의 로드아웃에는 `mesh.model` 이 생기지 않는다.

### 3. 모델 규격·검증 (`src/content/modelSpec.ts`, `validateModels.ts`)

- 규격: glTF 2.0 GLB, +z 선수, 1 단위 = 게임 1 단위, 원점 = 선체 중심, `hp_`/`engine_`/`light_` 마커, `sid_*` 진영 재질.

  - 마커

  - `hp_` 마커와 하드포인트 `pos` 의 거리
  - 함급별 예산
- 해시·환경 검사:
  - sha256 불일치
  - 파일 없음 (다른 환경에서 파일이 빠진 경우)
- 테스트용 모델 분리:

### 4. 자산 저장 방식 — 저장소 직접 커밋 + sha256 고정 (선택)

| 방식 | 판단 |
|---|---|
| 저장소에 최적화된 작은 GLB 커밋 (선택) | 클라우드 세션·CI·Render 빌드 모두 clone 만으로 파일이 있다. 인증·비용 없음. 파일당 2 MB 한도, 목표 0.1~1 MB |
| Git LFS | 미채택. LFS 를 받지 않는 환경에서는 포인터만 남는다 (이전에 GLB 가 클라우드에서 빠진 것과 같은 유형). 대역폭 과금 |
| 외부 객체 저장소 | 미채택. 인증 정보·유료 서비스가 필요하다 (승인 대상) |

데이터의 `file` + `sha256` 이 버전이 된다. 클라이언트는 `?v=<sha12>` 로 받으므로 캐시 문제가 없다. 검증기는 파일이 없거나 내용이 다르면 오류를 낸다. 도구: `npm run models:hash [-- --write]`, `npm run models:fixtures`.

### Partial / 남은 일

- **최종 함선 모델은 없다.**
  - 테스트 모델 2개는 로더 검증용이며 최종 자산이 아니다.
  - 대표 함선 모델 제작과 품질 검수는 P8 본 작업(Codex) 범위다.
- **변형 전용 모델(`VariantDef.model`)**
  - 코드 경로(`shipLoadout` 의 변형 우선 선택)와 검증기 규칙은 있다.
  - 실제 변형 모델 파일로 브라우저 확인은 하지 않았다. 선체 모델과 같은 경로를 쓴다.
- **텍스처가 있는 GLB**
  - 검증기 검사(크기·개수·embed)와 로더 경로(작성 재질 그대로 사용)는 있다.
  - 테스트 모델은 텍스처를 쓰지 않으므로, 텍스처 GLB 의 브라우저 확인은 하지 않았다.
- **파괴 장면 확인 방식**
  - 서버 권한 전투에서 자연 격침을 기다리지 않았다.
  - 클라이언트 전투 월드에서 격침을 강제해 확인했다 (`startDying`).
  - 피격은 실제 전투에서 일어난 것이다.
- **성능 측정 환경**
  - 측정은 소프트웨어 GL(swiftshader)에서만 했다. 실제 GPU 수치는 측정하지 않았다.
  - 그리기 호출을 줄이는 인스턴싱은 하지 않았다. 함선 수백 척 규모가 필요해지면 검토한다.
- **초상화·아이콘 표시**: 등록·검증만 된다. 화면 표시는 이번 범위 밖이다.
- **운영 반영 없음**
  - 운영 월드는 c0 이다. 모델은 성장 월드(contentV ≥ 3)의 성장 선체에만 쓰인다.
  - dev 선체는 어느 월드에서도 얻을 수 없다.
