# 물류 자동화 P2 개발 기록

기준: 사용자 2차 지시서(2026-11-08). 기준 브랜치 `codex/storage-world-analytics` / `f108438`, 작업 브랜치 `codex/logistics-automation-p2`. 이번 명시적 시스템 작업 지시가 과거 콘텐츠 전용 작업 경계를 대체한다. P8 콘텐츠와 운영 DB·배포는 변경하지 않는다.

## 진행 순서

1. 통계 병목을 프로파일링하고 정확성을 유지한 채 개선한다. CPU 중앙값 추가 부하 5%를 목표로 하며 p95·최악 틱·메모리·저장량을 함께 기록한다.
2. 기존 `haul`, 채굴선→수송선 회수, 도킹·게이트 경로와 창고/시장 처리를 확장한다. 서버가 관리하는 선택적 운송 노선으로 기존 저장과 c0 경로를 보호한다.
3. 기존 HUD에서 노선 설정·관리·장애 해결과 정거장 화면 연결을 제공한다. 네 해상도에서 실제 조작한다.
4. 자산·권한·저장·재시작·실제 플레이와 1/10/50노선 성능을 검증하고 결과를 기록한다. 전체 회귀는 구현 안정화 후 필요한 시점에 한 번 실행한다.

## 확인한 기존 구조

- `Op.haul`은 반복 창고 운송과 물류센터 기반 `*auto` 생산/건설 보급을 지원한다. 목표 수량·판매 목적·노선 수명주기·명확한 장애 재시도 정책은 없다.
- 동일 채굴 편대의 수송선이 광구에서 채굴선의 화물을 받아 돌아오는 기능과 귀환 시 채굴선 정비가 이미 있다. 새 자동 채굴 시스템을 중복 작성하지 않는다.
- 건설 예약품은 이미 창고에서 분리된다. 운송은 자유 재고만 사용한다. 기존 물류센터 게이트를 생산 공급 모드에서도 유지한다.
- 물류는 가격·함선 성능·생산량·연구 시간을 바꾸지 않으며 명시적으로 선택한 물품·목적지만 처리한다.

## Stage 1 설계

프로파일에서 반복 이벤트의 키 생성·성계 탐색·중복 계측과 NPC 시장 관측의 임시 객체가 확인됐다. 스칼라 관측의 안정된 식별자를 재사용하되 매 사건의 양·횟수와 합산 순서는 보존한다. 버킷 변경 시 캐시를 비워 만료 기록이 메모리에 남지 않도록 한다. 수집 비활성화 시 관측 스냅샷과 기록 계산은 수행하지 않는다.

저장 상한에서는 오래된 상세 구간을 먼저 시간·일 집계로 합친다. 보존 상한으로 만료되는 자료는 기존처럼 명시하며 성능 수치를 맞추려고 사건을 삭제하지 않는다.

재현: `node scripts/p2-analytics-perf.mjs`는 기준 커밋과 현재 코드를 각각 빌드해 같은 채굴·시장·후불 임대 월드에서 교대 실행한다. 전체 게임 상태와 통계 정합성을 비교하며 `artifacts/logistics-p2/`에 기록한다.

### Stage 1 검증 결과

- 기존 분석·저장·권한 검증과 추가 최적화 검증에서 수량·횟수·재시작·압축의 일치를 확인했다. 성능 비교의 기준/변경 후 게임 상태와 통계 JSON SHA-256이 모두 일치했다.
- 단독 측정 추가 CPU 중앙값: 기준 19.19% → 변경 후 9.53%. 5% 목표는 **Partial**. p95·최대값을 원자료의 각 쌍에 기록했으며 GC/JIT를 포함한 편차가 남아 지연 개선을 단정하지 않는다.
- 다른 시험과 겹친 측정은 `analytics-preliminary-contended.json`에 미채택으로 구분했다. 가격·경제 규칙·사건 수를 줄여 수치를 맞추지 않았다.

## Stage 2 — 서버 노선

- `WorldState.logistics` 선택 필드와 `Op.haul.route`를 사용한다. 서버 명령 `putRoute`, `routeControl`이 자사 편대·노선·정거장·물품·정박 규격·수량을 확인한다. 생산 공급의 기존 물류센터 요건을 유지한다. SQL/contentV 마이그레이션은 없다.
- 운송 명세는 실제 적재한 물품·남은 양만 추적한다. 기존 화물·건설 예약 자재는 건드리지 않는다. 단순 운송은 자사 보관함으로, 판매는 실제 시장 예산까지 판매하고 미판매분을 함선에 보존한다. 계약에 임의로 소비하지 않는다.
- 생산 공급은 활성 생산 주문의 실제 원료를 확인한다. 보충 시작 재고에 도달하면 목표 재고까지 보충 주기를 유지하고, 다른 노선의 운송 중 물량을 포함해 과잉 적재를 막는다. 도착 시에도 목표·창고 용량까지만 하역한다. 한 배치보다 낮은 설정 때문에 생산이 기다리면 실제 수치와 설정 수정 경로를 제공한다.
- 일시정지는 이동·적재·하역을 멈추되 화물과 명세를 유지한다. 취소도 화물을 없애지 않는다. 수동 작전·함선 편대 이동·부모 편대 변경이 우선이며 관련 노선은 일시정지한다. 재개는 명시적인 운송 명령 복귀다. 편도 완료선이 부분 일시정지/재개 때문에 중복 운송하지 않도록 완료 함선을 보존한다.
- 목적지 수정은 현재 화물에도 적용한다. 운송 중 품목·판매 방식 변경은 거부한다. 이를 바꾸려면 배송을 마치거나 취소한 뒤 기존 화물을 정리한다. 정박 함선은 `unloadCargo`로 자사 창고에 수동 하역할 수 있다. 이 명령은 판매·계약 소비를 하지 않고 관련 노선을 일시정지한다.
- 창고/예산/경로/규격 등 해결 가능한 장애는 4~15초 간격으로 재확인한다. 사라진 정거장·편대는 명확한 사유로 일시정지한다. 게이트 탐색은 기존 BFS에 사용 가능한 양방향 연결 검사를 추가해 재사용하며, 기존 이동의 기본 경로는 바꾸지 않는다.
- 화물 손실을 새로 보상하거나 생성하지 않는다. 함선 파괴는 기존 전투 규칙을 따르고 명세의 중복 지급을 막는다. 수동 하역·편대 이탈로 운송에서 회수된 물량은 별도로 기록한다. 최근 처리 이력은 노선당 최대 60개 분 구간이다.
- 정거장 삭제 검증에서 기존 NPC 교역이 없는 목적지의 이름을 읽어 서버가 중단되는 문제가 확인됐다. 이용 불가 지점만 건너뛰고 교역 가능한 기존 경유지를 사용하도록 수정했다. 정상 c0 경로의 규칙·수치는 유지한다.

집중 검증: 노선·분석·임대·창고 5개 파일 43개 통과. 실제 PostgreSQL/HTTP/WebSocket/브라우저 통합과 최종 회귀는 Stage 4 결과에 별도로 기록한다.
