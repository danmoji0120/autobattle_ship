## 통계 성능

`scripts/p2-analytics-perf.mjs`는 기준 커밋과 최적화 코드를 별도 자식 프로세스로 빌드한다. 세 회사의 실제 채굴·시장·후불 임대 시나리오를 120초씩 예열하고, 활성/비활성을 교대하며 각각 600게임초 × 3쌍 측정했다. 다른 무거운 검증과 겹치지 않은 결과만 채택했다.

| 항목 | 변경 전 | 최적화 후 |
|---|---:|---:|
| 추가 CPU 중앙값 | 19.1930% | 9.5331% |
| 활성 상태 틱 p95 범위 | 2.976~3.346ms | 3.017~3.978ms |
| 활성 상태 최악 틱 최대 | 10.469ms | 44.962ms |
| 활성 상태 GC 후 힙 증가 범위 | 1.25~1.32MiB | 1.30~1.54MiB |
| 통계 JSON | 87,904B | 87,904B |
| 수집 누락 | 0 | 0 |

게임 전체 JSON 해시와 통계 JSON 해시가 모든 쌍에서 기준과 일치했다. 화폐 대사 잔차는 약 4.9×10⁻¹¹cr이다. 메모리·지연에는 GC/JIT 편차가 있으므로 지연까지 개선됐다고 판정하지 않는다. 추가 CPU 목표 5%는 **Partial**이다. 기존 1차의 15.4%와 이번 19.19%는 측정 조건이 달라 직접 비교하지 않는다.

프로파일에서 반복 키·메타데이터 생성, NPC 시장 관측 객체, 중복 계측을 줄였다. 남은 거래 관측·정기 샘플·직렬화 비용과 실행 편차의 추가 최적화가 후속 과제다. 수집을 끄면 NPC 시장의 관측 스냅샷·집계를 건너뛴다. 기존 기록은 보존 상한 안에서 상세→시간→일 집계로 먼저 압축하고, 만료·누락은 기존처럼 표시한다. 2,000구간 압축·보존 상한 회귀와 새 바이트 압력 회귀를 통과했다.

[채택한 전후 측정](../artifacts/logistics-p2/analytics-performance.json). 다른 검증과 겹친 초기 측정은 `analytics-preliminary-contended.json`에 미채택으로 표시했다. 프로파일링 측정은 `analytics-before-profile.json`이며 성능 판정의 분모로 사용하지 않았다.

## 1/10/50노선 부하

3회사, 동일 함대의 정지/활성 대조군, NPC 경제와 실제 6척 전술 NPC 전투를 함께 실행했다. 각 경우를 독립 프로세스에서 60게임초 예열 후 600게임초 측정했다. 통계 수집은 활성 상태다. 이 표는 노선 확장성 시험이며 앞의 수집 활성/비활성 추가 CPU 목표와 다른 측정이다.

| 활성 노선 | CPU 시간 | 실제 소요 | 틱 p95 / 최악 | GC 후 힙 증가 | 통계 / 노선 JSON | 도착량 |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 9.044s | 7.016s | 4.067 / 12.503ms | 6.39MiB | 94,076 / 1,542B | 1,500 |
| 10 | 10.160s | 7.910s | 4.889 / 16.336ms | 6.91MiB | 106,886 / 15,418B | 15,000 |
| 50 | 12.749s | 9.692s | 6.634 / 15.578ms | 10.08MiB | 193,575 / 72,373B | 50,000 |

50노선 정지 대조군은 CPU 11.264s, p95 5.646ms, 최악 11.693ms였다. 활성 50노선의 최대 RSS는 약 151.8MiB이며, 월드 JSON은 322,683B다. 실제 NPC 교전이 진행 중인 2,282틱의 p95/최악은 6.623/15.578ms, 관측된 NPC 전투 평균 계측의 최대값은 1.223ms였다. 자원 보존 오차 0, 수집 실패·누락 0, 화폐 대사 잔차 약 2.3×10⁻¹⁰cr였다. 전투 예산·상한을 늘리지 않았다.

원자료에 정지 대조군 1/10/50과 전투·메모리·바이트를 모두 남겼다: [노선 부하 결과](../artifacts/logistics-p2/logistics-performance.json). 노선별 최근 이력은 60개 분 구간으로 제한되며 노선 자체 수를 50개로 제한하지 않는다. 취소된 노선은 제거한다. 장기간 실제 운영 부하는 이번 600초 부하 시험만으로 보장하지 않으며, 운영 적용 후 측정은 별도 승인 범위다.

## 수정한 문제와 영향

기존 경로를 재사용하면서 다음 실제 문제를 수정했다: 생산 보충 주기가 시작 재고를 넘자마자 멈춰 목표까지 공급하지 못하는 경우, 한 배치보다 낮은 기준으로 생산이 기다리는 이유가 표시되지 않는 경우, UI 갱신마다 제출 핸들러가 누적되는 경우, 정거장 삭제 시 기존 NPC 교역이 중단되는 경우, 두 노선 편대 사이의 함선 이동에서 한쪽만 정지하는 경우, 수동 부분 하역 직후 재개의 명세 정산 경계. 낮은 재고 기준을 서버가 임의로 바꾸지 않고 실제 배치량과 수정 경로를 제공한다.

주요 파일: `src/world/logistics.ts`(권위 노선·예외·정산), `sim.ts`·`geom.ts`·`types.ts`(기존 운항 연결), `src/server/core.ts`(회사별 전달), `observe.ts`·`analytics.ts`(수집), `logisticsUi.ts`·`hud.ts`·`style.css`(기존 UI 통합), `analyticsUi.ts`(중복 조회/핸들러 제거), 해당 테스트와 `scripts/p2-*`.

새 SQL 마이그레이션은 없다. 기존 저장은 선택 필드 없이 읽고 기존 명령도 유지한다. **새 저장을 구버전 바이너리로 실행하는 역호환은 보장하지 않는다.** 구버전은 새 노선의 실행·비공개 필드 가림을 모른다. 향후 롤백은 새 저장을 구버전으로 그대로 여는 방식 대신 호환 백업·정지 절차가 필요하다. 이번에 운영 데이터는 변경하지 않았다.

## 남은 항목

- **Partial:** 통계 추가 CPU 중앙값 5% 달성 및 GC/JIT를 포함한 최악 지연 개선. 실제 수량·사건을 줄여 목표를 맞추지 않았다.
- **검증 범위 한계:** 소프트웨어 렌더링 Chromium 사용. 실제 GPU·장기 재미·수주간 운영 부하는 검증하지 않았다. 1024px 두 브라우저 동시 접속의 초기 시간 초과는 위에 별도 기록했다.
- **미실행(승인 범위 밖):** 운영 DB 적용, 운영 콘텐츠 마이그레이션, 원격 배포·푸시.


## 재현

격리된 테스트 환경에서 실행한다. `PG_TEST_URL`은 **초기화 가능한 테스트 DB**만 가리켜야 한다. `tests/pg-migrate.test.ts`는 그 DB의 테스트 테이블을 지운다.

```bash
npm run typecheck
npm run build
npm run content:check
npx vitest run --maxWorkers=1
PG_TEST_URL='postgresql://postgres:TEST_PASSWORD@127.0.0.1:55432/siderarium_test' npm run test:pg -- --maxWorkers=1
node scripts/p2-logistics-browser.cjs
node scripts/p2-logistics-multiplayer.mjs
node scripts/p2-analytics-perf.mjs f108438
npx esbuild scripts/p2-logistics-perf.ts --bundle --platform=node --format=esm --outfile=/tmp/p2-logistics-perf.mjs
node --expose-gc /tmp/p2-logistics-perf.mjs
C0_OUTPUT_DIR=artifacts/logistics-p2 node scripts/verify-c0.mjs
```

기존 `scripts/mptest.mjs`는 상대 경로 `data/`를 초기화하므로 이번에는 임시 작업 디렉터리에 `dist`·`dist-server` 심볼릭 링크만 두고 실행했다. 로컬 작업 디렉터리의 기존 계정·월드 파일을 건드리지 않았다. 새 P2 브라우저·MP 스크립트는 자체 임시 저장 디렉터리를 사용하고 운영 DB 연결을 빈 값으로 차단한다. 성능 스크립트는 다른 무거운 작업과 겹치지 않게 단독 실행한다. 브라우저 시험에는 Playwright와 Chromium이 필요하다. 이번 측정 환경은 [환경 기록](../artifacts/logistics-p2/verification-environment.json)을 참조한다.
