# P11 전투 시스템 개편 — 다자간 교전·실시간 증원·PvP

브랜치 `feature/combat-multiside-reinforcement` (기반 `feature/faction-economy-stab`).

P11은 **옵트인**이다. `COMBAT_P11=1`로 새로 만든 월드(`WorldSim.create(seed, { combat: 'p11' })`,
`state.combatV === 2`)에서만 켜진다. 기존 저장은 변환하지 않는다. 레거시 월드와 레거시 2진영 전투는
바이트 단위로 동일하게 동작한다(아래 검증 참조). 운영 서버·DB·배포 설정은 변경하지 않았다.

## 1. 개념

| 개념 | 내용 |
|---|---|
| 진영(side) | 회사 하나 = 진영 하나. 전술 월드에서 `co:<회사id>` 구조 루트 아래에 그 회사의 편대만 들어간다. 여러 회사를 공통 루트로 묶어 지휘하지 않는다. |
| 관계 | 진영 쌍마다 적대(-1)·중립(0)·동맹(1). "나 빼고 전부 적"이 아니다. C가 A에게만 적대이면 C는 A만 공격하고, B와 자동으로 동맹이 되지 않는다. |
| 회사 관계 (`coRelation`) | 같은 회사 1. 해적끼리 1. 해적 ↔ 비해적 -1. PMC 사이에서는 어느 한쪽이 적대를 선언하면 -1, 양쪽이 모두 동맹을 제안하면 1, 그 밖에는 0. 시스템 NPC 세력과 PMC 사이 기본값은 0. |
| 관계 변경 | 전략 명령 `{c:'stance', target, v:-1/0/1}`. 다른 PMC 편대에 공격 명령을 내리면 선제 공격(적대 선언)으로 기록된다(`attackLog`). 진행 중인 전투에는 관계 변경이 `rel` 전투 이벤트로 즉시 반영된다. |
| 전투 이벤트 | `join`(증원)·`rel`(관계 변경)·`withdraw`(진영 철수)는 일반 명령과 같은 `OrderRecord`(`groupId -1`, `ev` 필드)다. 서버가 틱을 찍고 `e.orders`·`binit`/`border`·전투 기록으로 전파한다. 리플레이와 복원은 setup + 주문 로그만으로 재현된다. |

## 2. 월드 동작 (`src/world/sim.ts`)

1초마다 `detectEngagementsP11`이 다음 순서로 판정한다.

1. **증원**
   - 대상: 진행 중인 전투(`joinOpen`)의 `JOIN_R`(1700) 안에 있는 자유 편대.
   - 조건: 그 회사가 전투에 남아 있는 진영 중 하나와 적대여야 한다.
   - 처리: 같은 전투 인스턴스에 `join` 이벤트로 합류한다. 실제 위치에서 진입하며 순간이동은 없다. 이미 교전 중인 함선, 삭제된 함선, 철수한 회사(`e.left`)는 제외한다. 같은 편대는 중복으로 합류할 수 없다.
2. **신규 접촉**
   - `ENGAGE_R`(420) 안에서 서로 적대인 자유 편대 쌍이 만나면 전투가 시작된다.
   - 기존 전투가 `JOIN_R × 1.5` 안에 있으면 새 전투를 만들지 않고 그 전투에 합친다(교전 구역 중첩).
3. **해적 은신처**는 모든 비해적 편대에 대해 스스로 방어한다.

중립 회사는 끌려 들어오지 않는다. 어느 회사도 선택하지 않은 진영에 배치되지 않는다.

### 지휘 권한 (`src/world/battleAuth.ts`, 서버·클라이언트 공용)

- `canCommandGroup(st, w, g, company)`
  - 요청 회사가 플레이어여야 한다.
  - 하위 트리의 모든 ref가 그 회사 소유여야 하고, 최소 하나는 소유해야 한다.
  - 그래서 다른 회사의 편대나 진영 루트는 지휘할 수 없다.
- `validateTacticalOrder`
  - `escort`는 자사·동맹만 대상으로 한다.
  - `attack`·`flank`는 적대 진영만 대상으로 한다.
- 서버 `battleOrder`가 이 두 검사를 모두 수행한다. 클라이언트 UI는 같은 함수로 버튼을 결정할 뿐이며, 권한 보호는 서버에서 한다.

### 철수·종료

- **철수**
  - `border` `opts.withdraw`로 그 회사의 진영 전체가 철수한다.
  - 다른 진영은 같은 전투에서 계속 싸운다.
  - 이탈한 함선은 즉시 월드로 돌아간다(`e.released`). 격침된 함선은 최종 정산을 기다린다.
  - 철수한 회사는 그 전투에 다시 합류할 수 없다.
- **종료**: 서로 적대인 활성 진영 쌍이 하나도 남지 않거나 시간 제한에 도달하면 끝난다.
  - 승자(`winner`)는 혼자 남았고, 실제로 적대 진영을 격멸하거나 패주시킨 진영뿐이다.
  - 모든 상대가 자발적으로 철수해서 혼자 남은 진영은 `survived`(잔존)다. 자발적 철수는 패배가 아니므로, 다른 계정을 철수시켜 승리를 얻을 수 없다.
- **시간 제한**
  - 기본값은 540초다.
  - 증원이 들어오면 `lastJoin + 180초`까지 연장되며, 상한은 기본값의 2배다.
  - 상한 60초 전부터는 증원을 받지 않는다.
  - 시간이 다 되면 모두 `survived`다. 전력 비교로 승자를 정하지 않는다.
- **부하 예산**: NPC끼리의 전투는 기존과 같은 `NPC_BATTLE_CAP`(160척)·`NPC_BATTLE_BUDGET_MS`(8ms)를 따른다.
  - 초과분은 경량 판정(`quickResolveP11`, N진영)으로 처리한다.
  - 플레이어가 포함된 전투는 항상 실시간으로 처리한다.

### 정산 (회사별 1회)

- 진영 상태: `victor`·`survived`·`withdrawn`·`routed`·`destroyed`. 전투 기록 `sides[]`에 회사별로 남는다.
- **해적 현상금**: 해적에게 실제 피해를 준 회사(`e.dmg[company].pirates > 0`)만 받는다. PvP 격침에는 해적 현상금이 없다.
- 정산은 `finishEngagementObserved`에서 한 번만 일어난다. 복원 후 같은 전투를 다시 정산해도 아무 효과가 없다.

## 3. 클라이언트

- `src/ui/perspective.ts`: 보는 사람의 진영 기준으로 자사·동맹·중립·적대를 판정한다.
  - 같은 시뮬레이션이라도 참가자마다 다른 라벨과 색으로 보인다.
  - 관전자는 진영별 팔레트로 보며, 특정 시점을 강요받지 않는다.
- 전투 HUD
  - 진영 패널: 이름, 관계, 남은 전력, 상태.
  - 지휘 트리: 자사 → 동맹 → 중립 → 적대 순으로 묶는다.
  - 마커: 중립은 원형으로 표시한다.
  - 통신 태그에 관계를 붙인다.
  - 결과 화면에 진영별 결과 표를 둔다.
  - 레거시 2진영 전투는 기존 모습 그대로다.
- `BattleLink`
  - 지휘 가능 여부는 `canCommandGroup`으로 판정한다.
  - P11 참가자에게만 **전 함대 철수** 버튼을 보여준다.
  - 전투 중 합류한 함선도 즉시 렌더링한다.
- 전략 HUD
  - 다른 PMC 함선 정보에 관계를 표시한다.
  - **적대 선언 / 적대 철회 / 동맹 제안 / 동맹 해제** 버튼을 제공한다.
  - **선택 편대로 공격**은 확인 후 적대 선언으로 기록된다. 공격 모드에서 PMC 함대를 클릭해도 동작한다. 모두 P11 월드에서만 동작한다.
  - 전투 목록과 기록은 N진영을 지원한다.

## 5. 설계 결정 (보고 사항)

1. **자발적 철수는 상대의 승리가 아니다.** 남은 진영은 `survived`(잔존)이고, 승리 통계와 마일스톤은 오르지 않는다. 다른 계정을 철수시켜 승리를 쌓는 악용을 막기 위해서다. 철수한 상대도 승리로 쳐야 한다면 `beat()` 조건 한 줄만 바꾸면 된다.
2. **PvP 관계 규칙.** 적대는 일방 선언으로 성립하고, 동맹은 쌍방 제안이 있어야 성립한다. 시스템 NPC 세력과 PMC 사이 기본값은 중립이다. 보안 등급이 높은 성계에서 PvP를 제한하거나 처벌하는 규칙은 없다. 이는 외교·세력 전쟁 범위라 보류했다.
3. **PvP 격침 보상 없음.** 해적 현상금은 해적에게 준 피해에만 지급된다. PvP 전리품이나 보상 체계는 경제 V2 수치 변경 금지 범위라 추가하지 않았다.
4. **레거시 2진영 전투 경로는 그대로 두었다.** `World.dynamic`이 꺼져 있으면 기존 코드 경로를 쓴다. P11 월드에서도 해적과의 전투는 N진영 경로(`e.v=2`)로 기록된다.

## 6. 미완료·한계

- 운영 배포와 운영 DB 마이그레이션은 하지 않았다(지시서 범위 밖이며 별도 승인이 필요하다). `COMBAT_P11`을 켜지 않으면 동작이 바뀌지 않는다.
- 보안 성계의 PvP 규칙, 외교 UI(동맹 수락 알림, 관계 목록 화면), PvP 전리품은 범위 밖이라 보류했다.
- 레거시 전투 스텝 시간 +5~8%는 단일 환경의 측정값이며, 운영 하드웨어에서는 확인하지 않았다.
- 실서버 멀티플레이 검증은 3계정으로 했다. 4계정 동시 시나리오(§14 전체: D 적대 증원, 늦은 관전자, 재접속)는 `tests/p11-server.test.ts`에서 실제 `GameServer`와 프로토콜 2 연결로 검증했다. 다만 실제 WebSocket 프로세스로는 실행하지 않았다.
