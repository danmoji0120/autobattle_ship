# P12 함대 작전 및 자율 지휘

- 작업 브랜치: `feature/p12-fleet-operations`
- 기반 브랜치: `feature/combat-multiside-reinforcement` (P11)
- 원칙: 플레이어는 작전의 **목적**을 지시하고, 지휘관이 **수행 방법**을 정한다. 명시적인 플레이어 명령이 항상 우선한다.

## 0. 적용 범위 (옵트인)

P12 작전은 `WorldSim.create(seed, { ops: 'p12' })` 또는 서버 환경변수 `FLEET_OPS_P12=1`로 만든 **새 월드**에서만 켜진다. 이런 월드는 `state.opsV === 1`이다.

- 적대 판정이 P11 `coRelation`에 의존하므로, `ops: 'p12'`이면 P11 전투(`combatV = 2`)도 함께 켜진다.
- 레거시 월드와 P11 단독 월드(`opsV`가 없음)에서는 새 작전 명령을 거부한다. 기존 순찰·NPC 동작도 바이트 단위로 그대로다(월드 해시로 검증).
- 기존 저장은 변환하지 않는다. 운영 서버·DB·배포 설정은 건드리지 않는다.

## 1. 기존 코드 조사 결과 (재사용 대상)

| 기능 | 위치 | P12에서의 사용 |
|---|---|---|
| 명령 상속 | `opOf` / `opOwner` / `override` (`sim.ts`) | 그대로 사용한다. 작전 상태는 명령을 가진 그룹(op owner)에 저장한다. |
| 함대 동기 이동 | `fleetMarch` / `marchRoute` / `marchShip` (`sim.ts`) | 집결 → 최저속 함선 기준 이동 → 게이트 전후 재집결. 목표 좌표를 받을 수 있도록 일반화해서 복귀·집결·공격 이동·방어/봉쇄 진입에 재사용한다. |
| 성계 간 이동 | `moveTo` → `nextGate`(BFS, `gateOpen` 반영) → `jump`; `fly`(워프) | 그대로 사용한다. 순간이동은 없다. |
| 정박 | `canDock`(권한·소유·핵심 모듈·세력 거부), `berthFits`(규격), `stationBerths`/`occupiedBerths`(정박 공간), `goDock`/`dockShip` | 복귀 후보를 거르는 필수 조건으로 쓴다. |
| 정비 | `dockShip` → `maintainOnDock`(성장 월드: 시설 능력·자재 소비), `repairQuote`/`canRepairAt`, `repair` 명령(유료) | 복귀 후 정비는 이 경로만 사용한다. 무료 회복은 없다. |
| 호위 | `escort.ts` + `escortPlan`/`behaveEscort` | 그대로 사용한다. P12 월드에서는 위협 판정을 P11 적대 관계(해적 + 적대 PMC)로 넓힌다. |
| 공격 | `attack` op + P11 적대 선언 | 그대로 사용한다. |
| 교전 | P11 `detectEngagementsP11`(`ENGAGE_R` 420 접촉, `JOIN_R` 1700 증원, 중첩 병합), 전투 중 함선은 `state:'battle'` | 작전은 교전을 "일으키지" 않는다. 적대 함대에 접근하면 P11이 교전을 시작한다. 전투 중에는 `runGroup`에서 빠지고 작전(`g.op`)은 유지된다. |
| 지휘관 | `cmdr(g)`: 부상 중이거나 미배치면 `ACTING_CAPTAIN`(선임 함장). 판단력 `skill`, 공격성 `aggression`, 규율 `discipline` | 위협 평가와 복귀 지점 평가의 가중치로 쓴다. 새 능력치는 만들지 않는다. |
| NPC 작전 | `guard`(경로 순찰), `garrison`(주둔), `respond`(신속대응), `raid`(해적 습격) | **구현 결과(설계와 다름)**: P12 월드에서는 NPC의 위협 인식(`nearestHostile`)과 호위 위협 판정을 공통 관계 규칙(`coRelation === -1`)으로 통일했다. 이동 처리기(주둔 수리 왕복, 신속대응 출동 등)는 기존 것을 그대로 둔다. 기존 처리기에도 기준점·추격 한계가 있고, 처리기를 바꾸면 NPC 균형이 바뀌기 때문이다. 해적 `raid`는 그대로다(약탈은 P13). NPC 편대에도 P12 작전 명령을 줄 수 있다(소유자를 가리지 않는 공통 처리기). 처리기 교체 여부는 세력 전략 AI(P14)와 함께 정한다(보류). |
| 정찰 정보 | `intel.ts`(fog 월드의 성계·광맥 지식), 함대 위치는 원래 공개 정보 | 정찰은 정찰 함선의 감지 범위 안에서 본 함대·정거장만 보고서에 기록한다. 미발견 광맥·성계 정보는 공개하지 않는다. 성계 방문 기록은 기존 이동 경로가 남기는 그대로다. |

## 2. 작전 모델

### 정의(`Op`, 플레이어 명령)

| 명령 | Op | 비고 |
|---|---|---|
| 이동 | `{k:'move', to}` | 기존 |
| 집결 | `{k:'rally', at}` | 신규. 함대가 모일 때까지 기다린 뒤 대기 |
| 순찰 | `{k:'patrol', at, radius, route?}` | 기존 확장. `route`(경유지)가 있으면 경로를 반복 순찰 |
| 지역 방어 | `{k:'defend', at, radius}` | 신규 |
| 호위 | `{k:'escort', group, focus?}` | 기존 |
| 공격 | `{k:'attack', group?/lair?}` | 기존 |
| 공격 이동 | `{k:'amove', to}` | 신규 |
| 차단 요격 | `{k:'intercept', group}` | 신규 |
| 관문 봉쇄 | `{k:'blockade', system, gate}` | 신규 |
| 항로 습격 | `{k:'harass', at, radius, route?}` | 신규 |
| 증원 | `{k:'reinforce', eng?}` 또는 `{k:'reinforce', group?}` | 신규 |
| 정찰 | `{k:'recon', at, radius}` | 신규 |
| 복귀 | `{k:'return'}` | 신규. **정거장 ID 없음** |
| 정박 | `{k:'dock', station}` | 기존. 플레이어가 정거장을 지정 |
| 대기 | `{k:'idle'}` | 기존 |

### 실행 상태(`WGroup.opx`, 서버 전용, 저장됨)

```
{ key        // 작전 정의의 지문 — 바뀌면 상태를 초기화
  phase      // 'transit' | 'hold' | 'engage' | 'chase' | 'resume' | 'evade' | 'docking' | 'blocked' | 'done' ...
  dest?      // 현재 목적지 좌표
  anchor?    // 원래 작전 위치(추격 후 돌아갈 곳)
  target?    // 일시 추격 대상 그룹 id
  chaseFrom?, chaseT?   // 추격 시작 지점·시각 (추격 한도 판정)
  ignore?    // 놓친 목표: 재추격 금지 만료 시각
  leg?       // 순찰·습격 경유지 인덱스
  station?, split?   // 복귀 목적지(단일) 또는 하위 편대별 목적지
  score?, evalT?     // 현재 복귀 점수·마지막 평가 시각
  reason?    // 대기·불가 사유 (UI 표시)
  report?    // 정찰 보고
  next       // 다음 판단 시각 (판단은 1초 간격)
}
```

- 판단(목표 선택·위협 평가·목적지 재평가)은 함대당 **1초에 한 번** 한다. 매 틱 실행되는 것은 이동뿐이다.
- 지난 목적지와 상태는 `opx`에 남는다. 따라서 저장·복원 후에도 같은 단계에서 이어 간다.
- 작전 정의가 바뀌면(`key`가 다르면) 상태를 새로 만든다. 같은 명령을 반복해서 보내면 `key`가 같으므로 상태를 유지한다.

## 3. 지휘관 판단

### 적대 판정

- `coRelation(owner, other) === -1`인 대상만 공격·요격·추격한다.
- 중립·동맹은 접근만으로는 공격하지 않는다.
- 순찰·방어·봉쇄·습격 명령은 적대를 선언하지 않는다. 선언은 P11의 공격 명령과 `stance` 명령으로만 일어난다.

### 위협 평가 (`fleetops.ts` `assessThreats`)

1. 감지 반경 안의 적대 그룹을 모은다. 반경은 작전 종류에 따른 기본값과 지휘관 판단력 보너스(`+skill × 1500`)의 합이다.
2. 각 후보를 평가한다.
   - **임무 관련성**: 작전 위치(anchor)까지의 거리. 방어·봉쇄는 anchor에 가까운 위협을 우선하며, 함대에서 가장 가까운 적이 아니다.
   - **전력비**: 적 군사 가치 / 아군 군사 가치(손상도 반영).
3. 교전 여부를 결정한다. 교전 한계는 `limit = 1.1 + 0.8 × aggression − 0.3 × (1 − 아군 평균 체력)`이다.
   - 전력비 ≤ `limit`: 교전(요격)한다.
   - 그보다 크면: 방어·봉쇄는 위치를 지키며 대기하고(경보 보고), 습격·정찰은 회피한다.
4. **추격 한계**
   - 목표가 anchor에서 `leash`보다 멀어지면 추격을 중단한다. `leash`는 작전별로 정한다(방어: 반경 × 1.5, 봉쇄: 2600, 순찰: 반경 + 1500 등).
   - 목표를 놓친 경우(소멸, 정박, 다른 성계로 이동, 감지 범위 이탈)에도 중단한다.
   - 추격이 90초를 넘겨도 중단한다.
   - 중단한 목표는 60초 동안 다시 쫓지 않는다(`ignore`).
   - 추격 중단 후에는 anchor로 돌아가 작전을 재개한다.

## 4. 자동 복귀 (`return`)

### 입력

`{k:'return'}` 하나뿐이다. 버튼 한 번으로 명령이 끝나며, 정거장은 서버가 정한다.

### 후보 필수 조건

필수 조건을 하나라도 어기면 후보에서 제외한다.

1. `canDock(S, owner)`: 공용 정거장이면 세력 거부가 없어야 하고, 자사 정거장이면 핵심 모듈이 완성돼 있어야 한다.
2. 모든 함선에 대해 `berthFits(S, berth)`: 정박 규격.
3. 정박 공간: `stationBerths(S)`가 제한이 없거나, 남은 칸이 귀환할 함선 수 이상이어야 한다.
4. 경로: 현재 성계에서 정거장 성계까지 `gateOpen`인 게이트만으로 이어지는 경로가 있어야 한다.
5. 정거장 주변(`JOIN_R`)에서 진행 중인 교전이 없어야 한다.

### 점수 (낮을수록 좋음, 단위 ≈ 초)

```
time    = 경로 거리 / 함대 속도 + 점프 수 × 30
risk    = Σ_경로 성계 (100 − 실효 보안)/100 × 60
        + min(600, 정거장·경로 주변 6,000 내 적대 군사 가치 / 아군 군사 가치 × 120)
service = 손상도(평균 1−hp, 마모 포함) need가 0.1을 넘을 때:
            수리 가능 정거장이고 견적을 낼 자금이 있으면  −need × 400
            수리 불가 정거장이면                         +need × 400
cost    = 공용 정거장 정박 거부·임대 같은 금전 조건은 필수 조건에서 처리.
          자금 부족이면 수리 보너스 없음
score   = time + riskW × risk + service
riskW   = 1.6 − 0.8 × aggression + 0.4 × skill   (신중한 지휘관일수록 위험을 크게 본다)
```

- 자사 정거장이나 공용 정거장에 고정 우선순위는 없다. 위 항목만으로 비교한다.
- 거리만 짧고 정박할 수 없는 정거장은 필수 조건에서 이미 빠지므로 선택되지 않는다.

### 재평가

- 15초마다 재평가한다. 다음 경우에는 즉시 재평가한다.
  - 현재 목적지가 필수 조건을 어기게 됨: 파괴, 권한 상실, 적대화로 인한 거부, 게이트 봉쇄, 정박 공간 부족.
- 목적지는 다음 두 경우에만 바꾼다.
  - 현재 목적지가 무효가 된 경우.
  - 새 후보의 점수가 현재 점수의 75% 미만인 경우(오락가락 방지).
- 교전 중에는 판단을 멈춘다(작전은 유지된다).

### 함대 단위 귀환

- 함대 전체를 수용하는 정거장이 있으면 모두 같은 목적지로 간다. 이동은 `fleetMarch` 경로를 따른다: 집결, 최저속 함선 기준 이동, 게이트 전후 재집결.
- 그런 정거장이 없으면 편대(그룹) 단위로 목적지를 나눈다(`split`).
- 소유권과 지휘 계층은 바꾸지 않는다.

### 목적지 없음

- 함선을 삭제하거나 이동시키지 않는다. 현재 위치에서 대기한다.
- 대기 사유를 표시하고(`reason`), 60초마다 보고하며, 15초마다 재탐색한다.

### 완료

- 모든 귀환 함선이 정박하면 op owner의 명령을 `{k:'idle'}`(정박 대기)로 바꾼다. 이전 임무는 다시 시작하지 않는다.
- 정비는 정박 시 기존 자동 정비 경로(성장 월드: 시설 능력·자재·비용)만 적용한다. 체력·탄약을 무료로 회복시키지 않는다.

### 교전 중 복귀

- 그 편대(와 명령을 상속하는 하위 편대)의 전술 그룹에만 P11 `retreat` 명령을 보낸다. 서버 권한 검사를 거친다.
- 회사 진영 전체 철수(`withdraw`)는 쓰지 않는다. 다른 편대의 명령도 바꾸지 않는다.
- 이탈한 함선은 전투가 끝나 월드로 돌아오면 복귀를 계속한다.

## 5. 작전별 동작 (요약)

| 작전 | 동작 |
|---|---|
| 집결 | `fleetMarch`로 지점에 모인다. 도착 후 대기한다(작전 유지). |
| 순찰 | 경유지(또는 원 둘레 8개 지점)를 반복한다. 위협 평가 → 요격 → 추격 한계 → 원래 경유지로 돌아간다. 경유지 인덱스는 저장된다. |
| 지역 방어 | 중심에서 경계한다. 반경 안의 적대 함대만 요격하고 추격은 반경 × 1.5까지다. 위협이 없으면 위치를 유지한다. |
| 공격 이동 | 목적지까지 행군한다. 감지 범위(1600)의 적대 함대 중 감당할 수 있는 상대와 교전하고, 교전 후 행군을 재개한다. |
| 차단 요격 | 목표의 속도로 요격점을 예측한다: `|T + V·t − P| = 속도·t`, t ≤ 120초. 요격점으로 가서 목표 진로를 막는다. 목표가 적대면 접촉 시 P11 교전, 중립이면 진로 차단 위치만 유지하고 공격하지 않는다. 목표가 소멸하면 작전을 끝낸다. |
| 관문 봉쇄 | 게이트 앞 400 지점에 포진한다. 게이트 2,000 이내의 적대 함대에 접근해 교전하고, 추격은 게이트에서 2,600까지다. 전투 후 포진 위치로 돌아간다. 함대가 실제로 그 자리에 있을 때만 효과가 있다. 중립·우호 선박은 통과한다(검문·통행료는 P13). |
| 항로 습격 | 구역이나 경로를 돌며 취약한 적대 목표를 찾는다. 대상은 전력비 ≤ 0.7, 비무장·화물선을 우선한다. 공격 → 위험(강한 적대 군사력 접근, 아군 체력 < 45%) 시 반대 방향으로 이탈 → 30초 뒤 재개한다. 약탈·나포는 없다(P13). |

### 설계와 달라진 점

- NPC `guard`·`garrison`·`respond`의 이동 처리기는 교체하지 않았다. 위협 인식만 공통 규칙으로 바꿨다(§1 표). P14로 보류한다.
- `dock` 작전에 별도 P12 검증을 추가하지 않았다. 기존 `canDock`·`goDock`의 규격·공간 상태 표시를 그대로 쓴다.
- 증원은 아군 함대를 지정할 수도 있다(`reinforce{group}`). 그 함대가 교전에 들어가면 같은 교전으로 합류한다.

### 성능 (P12-20)

`scripts/combat/p12-perf.ts`로 측정했다. 시뮬레이션 120초, 시뮬레이션 1초당 전략 틱 비용이다. 같은 함선을 대기시킨 경우와 비교했다. 10척씩 편대를 짜고 모든 작전을 섞었으며, 해적과 적대 PMC를 함께 두었다.

| 경우 | 평균 ms/시뮬초 | p95 | 최대 | 실시간 대비 |
|---|---|---|---|---|
| 100척 대기 | 13.3 | 25.7 | 32.5 | 1.33% |
| 100척 P12 작전 | 18.2 | 29.0 | 50.8 | 1.82% |
| 200척 대기 | 17.3 | 26.9 | 35.5 | 1.73% |
| 200척 P12 작전 | 31.9 | 54.3 | 70.8 | 3.19% |

측정은 두 번 했다.

- 위 표는 1회차다. 실서버 시나리오가 함께 실행되던 중에 측정했다.
- `docs/combat-results/p12-perf.jsonl`은 2회차다. 전체 vitest와 동시에 측정했다. 200척 작전은 31.0 ms, 실시간 대비 3.1%다.

두 측정 모두 다른 작업과 CPU를 나눠 쓴 상태라 값은 보수적이다.

작전 쪽은 실제 교전이 더 많이 일어난다(5건 대 2건). 결정은 명령 보유 그룹당 1초에 1회다. 복귀 후보 평가는 15초마다 하고, 목적지가 무효가 되면 즉시 한다.
