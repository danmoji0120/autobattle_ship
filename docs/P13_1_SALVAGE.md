# P13.1 실물 전장 잔해 및 통합 인양

기준 브랜치 `feature/p12-5-logistics-simplification`(`008dba5`), 작업 브랜치 `feature/p13-1-salvage-overhaul`.
옵트인: 새 개발 월드 전용(`SALVAGE_P131=1` / `WorldSim.create(seed, { salvage: 'p131' })`, P11·P12·P12.5 포함). 운영 월드·기존 저장에는 적용하지 않는다.

## 1. 조사 결과 (작업 전 코드 기준)

### 1.1 인양·잔해가 생기는 경로는 넷이다

| 경로 | 코드 | 동작 | 문제 |
|---|---|---|---|
| 무작위 유기선 | `explore.ts` `seedSites`·`surveyStep`·`surveyLeft`·`salvageLoot`·`retireSite`, `sim.ts` `behaveSurvey`·`behaveSalvage`, `Op.survey`·`Op.salvage{site}` | 성계마다 2개 지점을 해시 위치에 만들고, 탐사 시간이 차면 발견. 인양 완료 시 RNG로 합금·희귀금속·전자·정밀·센서·설계도 조각·완성 설계도(`explore` 출처) 지급 후 4시간 뒤 재생성 | 전투와 무관한 무한 보상원. 잔해가 실제 자산이 아님 |
| 전투 잔해 광구 | `finishEngagementObserved` 끝부분 | 격침 함선 `shipValue×2.2`를 합산해 300 초과면 `Field{salvage:true}`(합금 혼합 `SALVAGE_MIX`)를 교전 중심에 생성, 1,500초 후 삭제. 채굴선이 채굴 | 화물·장비와 무관한 합금 광구. 아래 원격 회수와 같은 격침에서 이중 생성 |
| 원격 전장 회수 | `salvageWrecks`·`recoverLoot`, `research.ts` `wreckLoot`, `blueprints.ts` `wreckFragments` | `salvage_ops` 연구가 있으면 **해적** 격침 함선마다 피해 지분 확률로 부품·장비(장착 무장 중 무작위 1개 35%)·설계도 조각을 생성해 가장 가까운 정거장 창고 또는 `co.pendingLoot`에 지급 | 함선을 보내지 않아도 순간이동 지급. 무장 수량이 실제 장착과 무관하게 생성 |
| 격침 함선 화물 | `finishEngagementObserved` `r.dead` | 격침 함선의 `cargo` 전량을 `consume/combat_cargo_loss`로 소멸 처리 | 실제 화물이 남지 않음 |

### 1.2 탐사 기능의 의존 관계 (분리 대상)

- `behaveSurvey`는 두 가지를 같이 한다: ① P10 안개 월드의 광구 정보 조사(`surveyIntel` → `intel.ts`), ② 유기선 발견(`surveyStep`). P13.1에서는 ②만 끄고 ①은 그대로 둔다.
- 성계 방문 기록(`exploreStep` → `visit`), P10 회사별 정보(`intel`), 광구 시험 채굴 표본(`recordSample`), `survey_field`·`develop_field` 회사 목표(`fieldOps.ts`), P12 정찰(`recon`, `fleetops.ts`), 센서 기술(`long_sensors`)은 유기선과 무관하며 **보존**한다.
- 클라이언트: `hud.ts` 성계 탐사 버튼(`st.sites` 있을 때만 표시)과 유기선 인양 버튼(`data-salvage`), `growthUi.ts` 성계 탐사 요약이 `sites`에 의존.
- 마이그레이션: `migrate.ts`(c4)와 `worldgen-p9/p10`이 `seedSites`를 호출한다. 레거시 월드에서는 유지.

### 1.3 탐사 출처 설계도 (`kind: 'explore'`)

14종이 탐사 출처를 가진다. **탐사로만 얻을 수 있는 설계도는 없다** — 모두 상업 라이선스·세력·계약·잔해 조각 중 하나 이상이 있다. 따라서 폐지로 획득 불가능해지는 설계도는 없고, 탐사 출처는 향후 정식 탐사 콘텐츠용으로 데이터에 남겨 둔다(P13.1 월드에서는 지급 경로만 없음).

| 설계도 | 다른 출처 | 탐사 |
|---|---|---|
| 중순양함 | 상업 | 3등급 12% |
| 순양전함 | 세력·계약 | 3등급 5% |
| 전함 | 세력·잔해 조각 | 3등급 3% |
| 창살급 미사일 구축함 / 연장 발사관형 | 상업 | 2등급 8% / 6% |
| 채굴선 L / 채광모함급 드론형 | 상업 | 2등급 6% / 1등급 5% |
| 수송선 L | 세력 | 1등급 5% |
| 공작선 XL | 상업 | 3등급 4% |
| 철퇴급 장갑 강화형 | 잔해 조각·계약 | 2등급 7% |
| 침봉급 구축함 | 상업 | 2등급 6% |
| 자오선급 수송선 | 상업 | 1등급 5% |
| 감시자급 경순양함 / 지휘형 | 상업(·잔해 조각) | 2등급 4% / 5% |

잔해 조각(`salvage`) 출처 설계도 5종(전함, 철퇴급, 철퇴급 장갑 강화형, 채굴선 XL, 감시자급)은 기존에 원격 회수(`wreckFragments`)로만 조각을 얻었다. P13.1에서는 같은 확률로 **실제 잔해에 조각을 남기고**, 인양해야 얻는다.

### 1.4 기타 확인 사항

- BB-EX: 격침 시 삭제·잔해·조각 없이 `exclusiveLost`로 복구 대기(`isExclusiveShip`). 전용 장비는 `isExclusiveEquip`, `enforceExclusive`가 비정상 사본을 제거.
- 화물 용량: 군함(코르벳~드레드노트)의 `econ.cargo`는 0. 채굴선 140, 공작선 300, 수송선 450.
- 범죄 시스템은 없다. 기존 장치는 치안도(`effSec`/`secAt`), 회사 평판(`rep`), P10 세력 우호도(`bumpStanding`, `DOCK_REFUSE` -25에서 입항 거부), P11 회사 관계(`coRelation`, 적대 선언)다.
- P12.5: 격침된 수송선의 운송은 `maintainPool`이 `lost`로 처리하고 남은 물량을 재배차한다. 회수된 미추적 화물은 `stowCargo`가 가까운 창고로 하역한다.
- 함선 장착 장비: 플레이어 함선은 `fitting`(하드포인트·베이 → 장비 id, `fittingItems`), NPC 함선은 프리셋(`loadoutEquipment(getLoadout(...).mounts)`).

## 2. 설계 (P13.1 월드)

코드: `src/world/wrecks.ts`(잔해 생성·수명·가시성), `src/world/salvage.ts`(인양 엔진), `src/world/salvageMigrate.ts`(저장 전환), `src/client/strategic/salvageUi.ts`(UI). 게이트는 `st.salvageV === 1`. 레거시 월드는 기존 코드 경로를 그대로 탄다.

### 2.2 WreckSite (§3·§4)

- 격침된 실제 함선으로만 만든다(`finishEngagementObserved`에서 함선 삭제 직전 `makeWrecks`). 교전 id로 멱등 — 같은 교전으로 두 번 만들지 않는다.
- 위치: 함선이 마지막으로 있던 곳(전술 전투는 실시간 위치 반영). 1,500m 안에서 죽은 함선끼리 한 잔해장으로 묶고, 교전당 최대 6개(초과분은 가장 가까운 잔해장에 합침). 출처 함선(`sources`)·원소유(`lot.owner`)는 합쳐도 보존.
- 내용물(로트 = 종류·품목·원소유):
  - 화물: 함선별 생존 비율 민간 50%·군함 35% ±15%(월드 RNG), 정수 내림. 남은 양은 `salvage/to_wreck`, 나머지는 `consume/combat_cargo_loss`로 기록 → **격침 전 화물 = 소멸 + 잔해** (A03 테스트).
  - 장비: 실제 장착(`fitting`, NPC는 프리셋)의 각 단위가 30% 확률로 온전히 남음. 장착 수를 넘지 않는다.
  - 선체 고철: `shipValue × 2.2`를 `SALVAGE_MIX`(합금 45·금속 35·전자 10·무기 부품 10)로 — 레거시 잔해 광구와 같은 총량.
  - 설계도 조각: 해적 선체에서만(기존 `wreckFragments` 확률). 플레이어·연합 함선은 조각을 남기지 않음.
  - BB-EX 선체, 전용 장비, 지휘관, 완성 설계도는 절대 들어가지 않음(서버에서 `isExclusiveShip`/`isExclusiveEquip`로 걸러냄).
- 수명: 2시간 + 격침 함선당 10분, 최대 4시간. 만료 시 남은 양은 `consume/wreck_decay`로 소멸 기록 후 삭제. 다 회수되면 다음 1초 정리에서 삭제. 삭제된 잔해를 쫓던 함대는 「인양 완료 — 잔해가 소멸…」 후 대기.
- 서버에 하나만 존재. 회사별 사본 없음. `taken[회사][품목]`에 회수량 기록.

### 2.3 인양 엔진 (§5·§7)

- 이동 → 작업(잔해 중심 380m 이내) → 실제 화물칸 적재 → 정거장 정박 → 하역. 순간이동 없음. 작업 단위는 정수(함선별 누적기 `salvAcc`).
- 함선 역할별 초당 작업량(보상 배수 없음, 양이 아니라 속도·가능 여부만 다름):

  | 로트 | 수송선 | 공작선 | 채굴선 | 군함 |
  |---|---|---|---|---|
  | 화물 | 8 | 5 | 4 | 2 |
  | 장비 | — | 0.1 | — | 0.02 |
  | 선체 고철 | — | 3 | 5 | — |
  | 설계도 조각 | — | 0.05 | — | — |

  `salvage_ops` 연구: 모든 속도 ×1.5, 수송선·채굴선도 장비 0.02, 모든 함선 조각 0.02. 선체 50% 이하면 절반 속도.
- 군함은 화물칸이 없으므로 인양 전용 적재 공간 = `shipValue × 0.1`(구축함 8, 전함 30). 경제용 `econ.cargo`는 그대로라 P12.5 수송선 판정에 영향 없음.
- 회수분은 `s.salvaged`에 따로 기록하고, 하역 때는 그 양만 창고로 옮긴다(함선의 다른 화물·운송 화물은 건드리지 않음). 정거장 화물 처리 속도(`cargoPermit`)와 창고 공간(`intakeRoom`)을 지키고, 공간이 없으면 다른 정거장, 그것도 없으면 「작업 불가 — 하역 가능한 정거장이 없습니다」.
- 명령:
  - `recover{wreck}`: 그 잔해에서 회수 → 가득 차면 하역 → 복귀 → 회수할 것이 없으면 남은 짐 하역 후 대기.
  - `salvzone{at, radius}`: 반경 안 잔해를 (회수 가능 가치 ÷ (이동+작업 시간)) × 위험 계수로 고르고, 소멸 전에 못 끝낼 잔해는 제외. 하역 후 구역으로 복귀하고 끝나지 않는다. 잔해가 없으면 구역에서 대기하다 새 잔해가 생기면 다시 작업.
  - 대기·정박·귀환 명령이면 정박한 함선의 회수분을 자동 하역.
- 우선순위: 회피(`fleeing`) > 인양. P12 `return`은 별도 명령이므로 인양 상태를 즉시 해제(B08). P12.5 자동 물류는 인양 중(`g.salv`)이거나 회수분을 싣고 있는 수송선을 배차하지 않는다(`haulerAvailability` code `salvage`).

### 2.4 현장 자동 인양 (§6)

- 편대별 설정(`autoSalvage`, 기본 켜짐). 플레이어 편대만.
- 시작 조건: 명령이 대기이거나, 방어·순찰 중 잔해가 작전 반경 안이고 단계가 대기·소탕일 때. 회피 중이 아님. 잔해가 3km 이내. 5km 안에 적대 군함 없음. 회수 가능한 합법 물품과 공간이 있음.
- 하지 않는 경우: 전투 중(함선 상태 `battle`), 이동·공격·추격·봉쇄·귀환·증원 명령, 화물칸 가득, 보호 화물만 남음.
- 제한: 최대 10분, 시작 지점에서 3.5km. 끝나면 이유를 무전으로 보고. 대기 편대는 회수분을 가까운 창고에 하역하러 간 뒤 다시 대기. 다른 명령이 오면 즉시 그 명령을 따른다.

### 2.5 소유권·경쟁·합법성 (§8)

- 같은 잔해에 여러 회사가 붙어도 서버 한 틱 안에서 로트를 감소시키고 동시에 적재하므로 같은 단위를 두 번 가져갈 수 없다(D01: 매 시점 `A 회수 + C 회수 + 잔여 = 생성량`).
- 물리적 가능과 합법성 분리:
  - 선체 고철·장비·조각은 원소유를 기록하지만 누구나 회수 가능(난파 구조물).
  - 화물은 원소유 보호: 자사, 해적, 적대(`coRelation = -1`) 회사 화물만 합법. 중립·우호 회사 화물은 「무단 회수 포함」(`illegal: true`) 명시 명령만 가져간다. 자동 인양은 절대 가져가지 않는다.
  - 무단 회수 시: `w.crime`에 금액 기록, 효과 치안 25 이상이면 평판 −(가치/2000 × 치안/100), 세력 월드면 성계 세력 우호도도 하락, 소유 회사(플레이어)에게 통보(2분 간격). 무법 구역(치안 25 미만)은 기록만.
- 범죄·세관·밀수 시스템은 범위 밖(§17) — 기존 평판·우호도·치안만 사용한 최소 검사다.

### 2.6 가시성·동기화 (§13)

- 잔해 위치·규모·격침 수·소멸 시각은 공개(전투 소식), 안개 월드에서는 시야 안이거나 관련 회사에만.
- 내용물(로트·출처)은 교전 당사자와 8km 안에 함선을 보낸 회사에만. `taken`은 자기 회사 몫만.
- 다른 회사의 편대 인양 상태(`salv`, `autoSalvage`)와 함선 회수분(`salvaged`)은 숨김.

### 2.7 NPC (§12)

이번 단계에는 NPC 인양 함대가 없다. 자동 인양은 플레이어 편대만 수행하고, NPC가 잔해를 쓰게 되면(P14) 같은 `stepSalvage`·합법성 규칙을 따르도록 엔진을 회사 종류와 무관하게 작성했다. NPC 동작은 **미구현**.

### 2.8 저장 전환 (§14)

- 새 개발 월드 전용 옵트인: `SALVAGE_P131=1`(서버) / `WorldSim.create(seed, { salvage: 'p131' })`. P11·P12·P12.5를 함께 켠다.
- 기존 저장은 자동 변환하지 않는다. `enableSalvageP131`(멱등)은 유기선 삭제, 유기선 인양·(안개 없는) 탐사 명령 편대를 대기로, 잔해 광구·`pendingLoot`는 유지, 상품·크레딧·설계도는 변경하지 않는다. `scripts/salvage/p131-convert-check.ts`가 사본에서만 실행해 검증한다. 운영 저장 전환은 별도 승인 전까지 금지.

### 2.9 설정값 요약

`WRECK_CFG`(wrecks.ts), `SALV`(salvage.ts) 참조. 값은 테스트로 확인한 초기값이며 장기 실행 결과에 따라 조정할 수 있다.
