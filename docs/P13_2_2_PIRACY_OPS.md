## 2. 목표 선택 AI (결정 4)

적용 범위: **항로 약탈(`harass`+plunder, `plunder` with `at`)의 비파괴 우선·무력 사용 허용**만.
**직접 지정 대상(`plunder.group`)과 수송망 파괴 우선(`destroy`)은 기존 동작 그대로 — 수익성 제한 없음.** NPC 해적(`pickRaidTarget`)은 변경 없음.

- `judge()`를 `assess()`(순수, 잡음 제외)와 잡음·응답 규칙으로 분리. 결과·RNG 소비 순서 동일 (테스트 Y01: `pressure === base × noise`).
- `complyChance(a)`: 잡음 U(0.9,1.1) 위의 정확한 응낙 확률. 압력이 부족할 때의 규칙(지원 접근 → 버팀, 방어 → 저항, 도주 가능 → 도주, 생존 우선 → 응낙)도 포함. 따라서 **근처 별도 호위 편대(방어 1800m·지원 6000m)** 가 확률에 반영된다 (기존 점수는 대상 편대 자체 군함만 봤다).
- 실회수량: `recoveryRoom`(약탈 편대 + 배정 회수 편대). 화물칸을 넘는 몫은 추가 왕복으로 절반만 인정.
- 예상 실판매가: `saleQuote` — 실제 판매(`sellAt`)와 같은 50단위 호가 하락·세금·정거장 구매 예산을 사본으로 계산 (테스트 Y03: 실제 판매와 일치). 품목별 호가 상위 3개 정박 가능 정거장 중 최댓값.
- 위험: `(1 − p) × min(공격, 방어+지원) × (무력 0.3 / 비파괴 0.03)`.
- 기대 수익 = `p × 실판매가 − 위험`, 점수 = 기대 수익 / (이동 시간 + 240초). 기대 수익 400cr 미만은 제외하고 「수익성 있는 목표 없음 (n척 검토)」을 표시.
- 함대 패널에 선택 근거(응낙 %, 실판매, 위험, 기대 수익) 표시.

기존 테스트 변경 1건: `tests/p132-piracy.test.ts` A10의 두 번째 부분(거부하는 대상에게 한 번만 요구하고 철수)을 항로 약탈에서 **직접 지정 대상**으로 바꿨다. 새 AI는 응낙 확률 0%인 대상을 항로에서 위협하지 않으므로, 이 규칙(재요구 제한·철수)은 직접 지정 경로에서 검증한다. 규칙 자체는 변경 없음.

### 2.1 탐색 비용 절감 (선택 결과 불변)

판단식(`assess`)의 탈출 경로 계산(`nearestDock`·`routeDistance`)이 후보당 약 0.15~0.2ms로 대부분을 차지했다. 결과를 바꾸지 않는 두 단계를 `search()`에 넣었다.

1. **정확한 상한 사전 제외**: 기대 수익 ≤ 요구 화물 전량의 실판매가(응낙 확률 ≤ 1, 위험 ≥ 0, 실회수량 ≤ 요구량, 판매 금액은 수량에 단조). 이 상한이 `aiMinProfit` 미만이면 판단식을 건너뛴다.
2. **분기 한정**: 후보를 상한 점수(상한 ÷ (이동 시간 + 240초)) 내림차순으로 평가하고, 남은 후보의 상한이 현재 최고 실점수보다 작으면 중단. 동점이면 이전과 같이 편대 순서상 앞선 후보.

검증: Y10 — 12개 무작위 월드 × 2정책에서 전수 평가(편대 순서·엄격 비교)와 선택이 동일(실제 목표 선택 10건 이상 포함). 중단 조건을 일부러 틀리게 바꾸면 Y10이 실패하는 것을 확인 후 원복. P10 8시간 중립 2건(중형·분리)을 최종 코드로 재실행 → d1a183f 결과와 **바이트 단위 동일**(태그·코드·이후 추가된 `fights` 기록 필드 제외).

| 측정 (`docs/piracy-results/p1322/search-perf*.json`) | d1a183f (절감 전) | 최종 |
|---|---|---|
| 자연 P10 교통(1시간 후) 성계 전체 탐색 1회 | 0.2~0.3ms (후보 1~2척) | 0.17~0.19ms |
| 한곳에 화물선 40척 — 고가 화물 | 6.46ms | 0.67ms |
| 한곳에 화물선 40척 — 저가 화물(전부 제외) | 6.77ms | 0.45ms |

탐색은 탐색 중인 약탈 편대당 최대 2초에 1회. 전략 틱 7~9ms(P10 40성계) 대비 최악 조건에서도 1ms 미만.

## 3. 22.96 cr/단위 실판매 단가 원인 (결정 2)

P13.2.1 C·중형에서 전자부품 실판매 단가가 22.96(기준가 150)으로 나왔고, 같은 시드의 다른 실행에서는 55~85가 나왔다.

**원인 1 — 실행 궤적이 기계 부하에 따라 달라짐.** `WorldSim.update`는 NPC 전투를 실시간 예산(`NPC_BATTLE_BUDGET_MS` 8ms, `performance.now`)으로 나눠 처리한다. 부하가 다르면 같은 시드·코드라도 전투 진행 시점이 달라지고 이후 세계 궤적 전체가 갈라진다. P13.2.1 표의 단가 차이(22.9 / 55.3 / 85.0)는 동시에 돌린 실행 수에 따라 달랐다. 실험 스크립트에 `DETCLOCK`(시계 고정) 옵션을 넣으니 두 번 실행이 태그 외 바이트 동일해졌다(`salesdiag-*-det1/det2-80869ca.json`). 게임 서버 동작 자체는 변경하지 않았다(실시간 예산은 서버 프레임 보호용).

**원인 2 — 구조적: 단일 시장 과잉 공급.** 고정 시계에서 C·p132는 22.92/단위로 재현(11,250단위 전부 `p9_lyra_port`).
- 첫 투매 1,350단위로 매수가가 137.1 → 하한 21.9(`FLOOR_V3` 0.15 × 150)로 떨어진다.
- 그 정거장의 흡수(재고 소비)는 10분당 145~200단위, 약탈 편대 반입은 10분당 225단위 → 매수가가 하한에 머문다.
- 다른 궤적(d27e749 단독 실행 85.0)에서는 재고가 10분당 420단위 빠져 매수가가 108~135로 회복했지만, 정거장 구매 자금이 바닥나 1,963단위가 팔리지 못했다(미판매는 현금으로 치지 않음).
- 고정 시계 C·중형은 51.13/단위(9,286 판매, 1,964 미판매; 후반에 `exchange`로 판매처 이동).

결론: 22.96은 계산 오류가 아니라 **한 시장에 같은 품목을 계속 투매한 결과 + 부하 의존 궤적**이다. 수익 너프 없음(결정 2). 이번 목표 선택 AI의 `saleQuote`는 이 가격 하락·구매 예산을 그대로 반영해, 이미 하한인 시장의 화물은 낮게 평가한다(Y06).
