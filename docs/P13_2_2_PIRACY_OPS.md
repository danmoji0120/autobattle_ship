## 1. 분리 회수 편대 (결정 3)

새 편대 명령 `{ k: 'lootTender', group: <자사 약탈 편대> }` — UI 이름 **약탈 회수 지원**.

| 항목 | 동작 |
|---|---|
| 배정 | 함대 패널(군함 없는 수송 편대)의 「약탈 회수 지원」 → 자사 약탈 편대 클릭. 서버 검증: piracyV 월드, 자사 편대, 자기·상하위 편대 불가, 회수할 수송선 필요 |
| 평시 | 약탈 편대 뒤 `PIR.tenderTrail`(1500m)를 따라감 (성계 이동 포함). 위협·전투 없음 |
| 회수 | 그 약탈이 받아낸 컨테이너(`CargoDrop.raid` = 약탈 편대 id)를 인양 엔진(`stepCollect`)으로 회수 → 가득 차면 정거장 하역 → 복귀. 약탈 편대가 현재 회수 중인 컨테이너 우선 |
| 판단식 반영 | `judge()`의 회수 능력(room)에 **대상 함선에서 `PIR.tenderR`(4000m) 안**에 있는, **그 약탈에 배정된**, 공간에 있고 도주 중이 아닌 회수 편대의 빈 화물칸을 더함. **공격력(attack)·방어 계산은 불변** |
| 휴전 | 투하 시점 tenderR 안의 배정 회수 편대는 당사자(pa)에 포함. 회수 중(`salv.key = collect:<id>`)인 편대는 기존 규칙으로 당사자 |
| 종료 | 약탈 편대가 사라지면 하역 중인 화물을 마저 내린 뒤 대기로 전환. 지속형 작전(업무 목록에서 연속 작전) |
| 자동 물류 | 대기가 아니므로 자동 물류에 배정되지 않음(기존 규칙) |
| 알려진 동작 | 회수 편대도 민간 편대의 위협 감지(`threatCheck`)를 따른다: 근처 아군 군함 가치가 적 위협보다 약하면 정거장으로 대피 — 약탈 편대 1500m 뒤(1800m 보호 반경 안)에 있으면 약탈 편대가 보호 전력으로 계산된다. 도주 중인 회수 편대는 회수 능력에 반영하지 않는다 |

## 2. 목표 선택 AI (결정 4)

적용 범위: **항로 약탈(`harass`+plunder, `plunder` with `at`)의 비파괴 우선·무력 사용 허용**만.
**직접 지정 대상(`plunder.group`)과 수송망 파괴 우선(`destroy`)은 기존 동작 그대로 — 수익성 제한 없음.** NPC 해적(`pickRaidTarget`)은 변경 없음.

- `judge()`를 `assess()`(순수, 잡음 제외)와 잡음·응답 규칙으로 분리. 결과·RNG 소비 순서 동일 (테스트 Y01: `pressure === base × noise`).
- `complyChance(a)`: 잡음 U(0.9,1.1) 위의 정확한 응낙 확률. 압력이 부족할 때의 규칙(지원 접근 → 버팀, 방어 → 저항, 도주 가능 → 도주, 생존 우선 → 응낙)도 포함. 따라서 **근처 별도 호위 편대(방어 1800m·지원 6000m)** 가 확률에 반영된다 (기존 점수는 대상 편대 자체 군함만 봤다).
- 실회수량: `recoveryRoom`(약탈 편대 + 배정 회수 편대). 화물칸을 넘는 몫은 추가 왕복으로 절반만 인정.
- 예상 실판매가: `saleQuote` — 실제 판매(`sellAt`)와 같은 50단위 호가 하락·세금·정거장 구매 예산을 사본으로 계산 (테스트 Y03: 실제 판매와 일치). 품목별 호가 상위 3개 정박 가능 정거장 중 최댓값.
- 위험: `(1 − p) × min(공격, 방어+지원) × (무력 0.3 / 비파괴 0.03)`.
- 기대 수익 = `p × 실판매가 − 위험`, 점수 = 기대 수익 / (이동 시간 + 240초). 기대 수익 400cr 미만은 제외하고 「수익성 있는 목표 없음 (n척 검토)」을 표시.
- 함대 패널에 선택 근거(응낙 %, 실판매, 위험, 기대 수익) 표시.

기존 테스트 변경 1건: `tests/p132-piracy.test.ts` A10의 두 번째 부분(거부하는 대상에게 한 번만 요구하고 철수)을 항로 약탈에서 **직접 지정 대상**으로 바꿨다. 새 AI는 응낙 확률 0%인 대상을 항로에서 위협하지 않으므로, 이 규칙(재요구 제한·철수)은 직접 지정 경로에서 검증한다. 규칙 자체는 변경 없음.
