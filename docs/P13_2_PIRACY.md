# P13.2 화물 약탈·항로 습격 (piracyV)

옵트인: `PIRACY_P132=1` (새 월드만) · `WorldSim.create(seed, { piracy: 'p132' })`. P13.2 월드는 P11·P12·P12.5·P13.1을 모두 포함한다(`combatV 2`, `opsV 1`, `logisticsV`, `salvageV 1`, `piracyV 1`). 기존 저장은 변환하지 않는다.

## 1. 조사 결과 (작업 전 코드 기준)

### 1.1 전투 시작 — P11 접촉 (`sim.ts detectEngagementsP11`)

- 매 전략 초마다, 서로 **적대**(`coRelation === -1`)인 두 회사의 자유 함대(공간에 있고 워프·교전 중이 아닌 함선)가 **420m**(`ENGAGE_R`) 안에 들어오면 교전이 시작된다. 1,700m(`JOIN_R`) 안의 적대 함대는 진행 중인 교전에 합류한다.
- 중립(관계 0) 회사끼리는 절대 교전하지 않는다. 해적은 모든 비해적과 적대.
- 플레이어 회사에 `attack` 명령을 내리면 그 순간 자동 적대 선언(`setStance(... 'attack')`)이 된다.
- **약탈과의 충돌**: 적대 관계에서 수송선에 접근하면 420m에서 무조건 교전이 시작되므로, 항복 요구는 그보다 먼 거리(위협 거리 1,200m)에서 끝나야 하고, 요구에 응한 뒤 공격자가 투하 화물을 회수하는 동안(수송선이 바로 옆에 있음)에는 교전이 시작되면 안 된다.
  → **휴전(truce)**: 응낙 직후 공격 회사 ↔ 피해 회사 사이에, 투하 지점 반경 4km·180초 동안만 새 접촉을 만들지 않는다. 다른 회사, 다른 장소, 이미 진행 중인 교전에는 영향이 없다(전역 차단 아님). 무력 사용으로 넘어가면 즉시 해제.
    *(P13.2.1 정정: 초기 설계 문안의 120초는 코드(`PIR.truceFor = 180`)와 달랐다 — 실제 값은 180초. P13.2.1에서 휴전 범위를 회사 쌍 → 해당 약탈 사건의 참여 편대로 좁히고, 편대 단위 휴전은 투하 지점 반경 대신 당사자를 따라가도록 바꿨다 — §6 참조.)*

### 1.2 기존 습격

- P12 `harass`(`fleetops.ts`): 작전 구역에서 취약한 적대 함대를 골라 추격·교전한다. 화물은 다루지 않는다. 레거시 의미는 그대로 두고, P13.2 월드에서 `plunder` 필드를 붙인 `harass`만 화물 약탈 작전이 된다.
- NPC `raid`(`sim.ts behaveRaid / pickRaidTarget`): 해적 무리가 은신처 성계에서 목표(수송선 등)를 골라 편대 대형으로 돌진 → 420m 접촉 → P11. 위협·항복·화물 탈취 없음.
- 민간 편대 공통 `threatCheck`: 근처 해적(P12.5 월드는 적대 군함)을 감지하면 `g.fleeing` → 가장 가까운 정거장으로 대피. P13.2의 「도주」 응답은 이 기존 경로를 쓴다.

### 1.3 P12.5 자동 물류 (`autonomousLogistics.ts`)

- `LogisticsJob`: `reserved`(출발지에서 빼둔 예약 재고), `carried`(함선에 실린 작업 물량), `delivered`/`cycleDelivered`, `lost`(함선 손실), `withdrawn`(함선은 남았지만 화물이 작업에서 빠짐), `held`(직접 명령으로 보류된 화물).
- 도착했을 때 실제 화물이 `carried`보다 적으면 그 차이를 `withdrawn`으로 넘긴다. **즉 지금 코드에서는 약탈로 화물이 빠져도 도착할 때까지 「배송 중」으로 남고, 그 뒤 「회수됨」으로 잘못 분류된다.** → 투하 순간 정산하는 공통 함수 `cargoLost()`를 추가(`carried −`, `lost +`, `logistics/pirated` 기록). 화물이 0이 되면 기존 `detach(..., lost)` 경로로 작업이 함선에서 풀리고 남은 수량은 재배차된다.
- 도착 예정량(`incomingPool` = `carried + reserved`)과 조달(`procurement.ts outstanding = amount − cycleDelivered`)은 이 정산만으로 다시 맞는다. 조달 계획은 작업의 남은 수량을 그대로 보므로 중복 요청이 생기지 않는다. 자동 구매 기본값(비활성)·예산·결재 규칙은 건드리지 않는다.

### 1.4 P13.1 인양 (`wrecks.ts`, `salvage.ts`)

- `WreckSite`는 실제 격침 함선을 출처로 갖는 객체다. `salvage.ts`는 잔해 ID로 `st.wrecks`를 찾아 접근·작업(로트에서 함선 화물칸으로 같은 단계에 이동)·하역(`unloadSalvage`, 정박해야만 창고로)을 한다.
- 비적대 회사 화물은 보호 로트(`protectedLot`) — 명시적 `illegal` 허가가 있어야 회수, 치안 구역에서는 평판·세력 우호도 하락(`crime`).
- 군함은 작은 인양 공간(선가 × 0.1)을 가진다.
- **재사용 방식**: 투하 화물은 가짜 잔해가 아니라 별도 컬렉션 `st.drops`(`CargoDrop`)에 둔다. 인양 엔진이 다루는 공통 형태(`SalvSite`: id·이름·위치·만료·로트·회수 기록·인지 회사)를 두 객체가 공유하고, 엔진은 `siteOf(id)`로 둘 중 하나를 찾는다. 회수 규칙·물품 이전·하역·범죄 처리는 한 벌이다.

### 1.5 기타

- 독점 콘텐츠: `isExclusiveEquip`, `isExclusiveShip`, `isExclusive`(설계도). 투하 대상에서 서버가 제외한다.
- 동기화(`server/sync.ts`): 다른 플레이어 회사의 회사 설정(`publicCompany` 화이트리스트), 편대 작전 상태(`publicGroup`), 함선 화물(`publicShip`)은 이미 가려진다. 새 상태도 같은 자리에서 가린다.

### 1.6 문서·코드 차이

- P12 문서의 `harass` 설명에 "약탈 없음(P13)"이 있고 코드도 그렇다. 일치.
- P12.5 문서는 "실린 화물은 함선이 살아 있으면 보존"이라고 하는데, 약탈처럼 함선은 살아 있고 화물만 빠지는 경우의 정산은 정의되어 있지 않았다(1.3). P13.2에서 정의한다.

## 2. 설계

### 2.1 상태 흐름 (플레이어·NPC 공통, `src/world/piracy.ts`)

```
search → intercept → demand ─┬─ comply → 투하(CargoDrop) → collect(인양 엔진) → 하역/은신처 → search|done
                             ├─ flee / resist / stall ─┬─ 비파괴 우선: withdraw (재요구 제한)
                             │                         └─ 무력 허용: force → P11 → 격침 시 잔해 collect
                             └─ (수송망 파괴 우선은 요구 없이 force)
```

- 위협 거리 1,200m 안, 상대가 공간에 있고(정박·교전·워프 아님), 화물이 있고, 공격자에게 전투 가능한 군함이 있을 때만 요구한다.
- 같은 함선에 대한 요구는 10분에 한 번(누가 요구하든). 응답은 서버가 즉시 결정하고 기록한다. 무적 시간이 아니다 — 무력 공격은 언제든 가능.

### 2.2 대응 판단 (결정론 + 월드 RNG ±10%)

`압력 = (공격 군함 가치 / (방어 + 50)) × (1 + 1.2 × 손상) × 회수 능력 × (1 − 0.5 × 도주 가능성) × (1.15 − 0.3 × 지휘관 공격성)`

- 방어 = 대상 편대 군함 + 1.8km 안의 자사·동맹 군함 (+ 공격자가 해적이면 연합 경비).
- 도주 가능성 = 속도 차와 가장 가까운 정박 가능 정거장까지의 거리로 계산(0–1).
- 회수 능력: 공격 함대에 인양 공간이 없으면 0.35배(빼앗아도 못 가져가는 위협은 덜 믿음직하다).
- 정책 문턱: 생존 우선 0.6 · 균형 1.2 · 화물 보호 2.5.
- 압력 ≥ 문턱 → **응낙**. 아니면: 6km 안에 아군 지원이 오는 중 → **버팀**(stall), 방어 전력이 있음 → **저항**, 도주 가능성 ≥ 0.4 → **도주**, 화물 보호 → 저항, 그 외 → 응낙 못 함(저항). 생존 우선이고 방어 0·도주 불가면 응낙.
- 플레이어 수송선은 서버에 저장된 정책(회사 기본값, 편대 재정의)으로 자동 응답한다. 편대가 직접 이동·정박·복귀 명령을 수행 중이면 「도주」가 그 명령을 덮지 않는다.

### 2.3 화물 요구·투하

- 요구: `part`(가치 50%, 기본) · `all` · `item`(그 품목 우선, 가치 50%까지).
- 투하량은 함선의 실제 화물(정수 단위, 독점 콘텐츠 제외)을 넘지 않는다. `투하 전 = 함선 잔존 + 컨테이너`.
- `CargoDrop`: id(사건 ID에서 유도, 멱등)·출처 함선·원소유·공격자·성계·위치·생성/만료(30분)·로트·회수 기록·인지 회사. 원소유의 화물로 남아 있다가 회수되는 순간 회수 회사의 화물칸으로 넘어간다(소유권 이전은 회수 때만).
- 투하 순간 물류 정산(1.3). 인양 전용 하역 표시(`salvaged`)가 있던 화물이면 그 표시도 줄인다.

### 2.4 플레이어 작전

- `plunder` 명령: 대상 편대(`group`) 또는 구역(`at`, `radius`). 정책 `nonlethal`(비파괴 우선) · `force`(무력 사용 허용) · `destroy`(수송망 파괴 우선). `neutral: true`일 때만 중립 회사도 노린다.
- `harass` + `plunder: 정책`(P13.2 월드)은 같은 구역 약탈 작전이다. `plunder`가 없는 `harass`는 기존 그대로.
- 회수는 공격 함대가 직접(인양 엔진). 군함만 있으면 군함 인양 공간만큼만, 화물칸이 있는 함선이 있으면 그만큼. 가득 차면 하역(인양 엔진의 정거장 선택) 후 작전 재개.
- 중립 플레이어에게 무력: `attack`과 같은 규칙(그 순간 적대 선언). 중립 NPC(길드 상선)에는 무력 사용 불가, 비파괴만.

### 2.5 NPC 해적

- `pickRaidTarget`에 기대 약탈 가치(실제 화물 가치)·자기 회수 공간을 반영.
- `raid` 중 목표에 화물이 있으면 1,200m에서 같은 요구·판단을 쓴다. 응낙 → 같은 인양 엔진으로 회수(군함 인양 공간 한도) → 은신처로 가져가 `lair.hold`에 보관(실재 보관, 다른 용도 없음 — P14). 거절 → 기존 돌진·P11.

### 2.6 치안·평판

- 사건 기록: `threat`(요구) · `comply`/`flee`/`resist`/`stall` · `drop` · `withdraw` · `force` · `sunk`. 회사 알림 + 분석 기록(`piracy/*`).
- 비적대(중립) 회사에 대한 요구가 응낙되면, 치안 25 이상 성계에서 투하 가치에 비례해 평판·세력 우호도가 하락한다. 회수할 때는 P13.1 무단 회수 규칙이 그대로 적용된다. 적대 회사·해적 상대 약탈에는 제재 없음.

A 조사·설계(이 문서) → B·C·D 약탈 엔진(요구·판단·투하·휴전·공통 회수·물류 정산) → E 플레이어 작전·대응 정책 → F NPC 해적 → G 치안 → H UI·테스트·실서버·장기·성능·회귀.

### 4.2 작업 중 확정한 세부 규칙 (보고 대상)

1. **직접 공격 명령은 휴전을 끝낸다.** 응낙 직후 휴전(180초·4km) 중에도 공격 회사가 `attack` 명령을 내리면 무력 사용과 같은 규칙으로 즉시 해제하고 `force` 기록(`policy: attack:<대상>`)을 남긴다. 휴전이 공격 명령까지 막으면, 한 번 응낙한 수송선을 플레이어가 공격할 수단이 3분간 없어진다(실서버 S3에서 발견).
2. **무력 추격의 반복 이탈 제한 `PIR.forceEscapes = 3`.** P11에서 민간선은 교전 중 900m 밖으로 이탈한다(기존 설계, 변경하지 않음). 무력 약탈은 원래 `forceMax`(2,400초) 동안 대상을 따라가므로, 이탈한 수송선과 곧바로 새 교전이 시작되기를 반복했다(2차 실서버 시도: 같은 수송선과 18회 이상, 수송선 hp 0.29 유지). 이제 대상이 교전에서 3회 이탈하면 추격을 끝내고("대상이 교전에서 3회 이탈 — 약탈 실패"), 같은 대상은 재요구 시간(600초) 동안 다시 고르지 않는다. 전투 자체(P11)는 바꾸지 않았다.
3. **플레이어 군함은 워프를 막지 않는다.** `scrambled()`는 해적 군함만 워프를 방해한다(기존 규칙, 변경하지 않음). 위협받은 플레이어 수송선은 P11 접촉 전에 워프로 피할 수 있으므로, 약탈은 워프 이탈 지점(관문 출구·목적지 접근로) 매복에서 가장 잘 성립한다. 항로 약탈(`harass` + `plunder`)은 그 용도다.
4. **`threatCheck` 대피.** P12.5 월드에서 민간 편대는 적대 군함을 감지하면 가장 가까운 정거장으로 대피한다(기존). 출발지 근처에서 위협받은 수송선은 바로 재정박하므로 요구가 성립하지 않는다 — 실서버 S1을 목적지 접근로 매복으로 바꾼 이유.
5. **회수 중 컨테이너도 군함 자동 인양 대상.** 대기 중인 군함은 근처의 합법 컨테이너를 잔해처럼 자동 인양한다(P13.1 자동 인양 규칙 그대로). 상태 문구가 "잔해"로 표시되는 것은 미수정(표시만의 문제). *(P13.2.1에서 수정 — §6.3.)*

### 4.3 문서·지시서와 코드 차이

- NPC 해적이 은신처에 보관한 화물(`lair.hold`)은 실재 보관만 하고 다른 용도가 없다(P14 이후 경제 연결 — 보류).
- `harass`(P12) 문서의 "약탈 없음"은 `plunder`가 없는 기존 `harass`에 대해서는 그대로 맞다.
