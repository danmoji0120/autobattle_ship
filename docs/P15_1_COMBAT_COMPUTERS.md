# P15.1 — 전투 컴퓨터 (함선별 실제 기동 차이)

GitHub 이슈 #6(갱신된 P15.1 명세). 전투 컴퓨터는 **함선 한 척이 지휘관 명령 범위 안에서 어떻게 싸우는지**를 바꾸는
실제 장비다. 함급별 장착 제한은 없다. 맞지 않는 무장에 단 컴퓨터는 자동 최적화하지 않고 기본 제어로 돌아간다.

## 1. 장비와 베이

| 항목 | 내용 |
|---|---|
| 베이 | 전투용 선체마다 전용 `cpu1`(종류 `computer`, 크기 S) 1개를 레지스트리가 자동으로 붙인다(`withComputerBay`). 민간 선체(역할 civilian), 플랫폼, BB-EX 같은 전용 선체, 이미 컴퓨터 베이가 있는 선체는 제외. |
| 장착 규칙 | 컴퓨터는 컴퓨터 베이에만, 컴퓨터 베이에는 컴퓨터만(`bayAccepts`). 특수 베이도 컴퓨터를 받지 않는다. **함급 조건 없음** — 초계함에 공성 컴퓨터, 전함에 군집 컴퓨터도 장착 가능. |
| 빈 베이 | 기본 제어(기존 AI 그대로). |
| 기존 모듈 | `mod_fcs`(명중), `mod_pd`(요격)는 변경 없음. 컴퓨터는 스탯 효과(fx)가 없다. |
| 제품 ↔ 원형 | 제품 id(`cpu_*`)와 행동 원형(`cpu.arch`)을 분리. 같은 원형의 저가·고급·구형·수출형은 새 행으로 추가한다. |

기본 제품(`src/content/packs/growth/computers.ts`, 성장 콘텐츠 contentV 3 전용):

| id | 이름 | 원형 | 판단 주기 | 전력 | 질량 | 연구 |
|---|---|---|---|---|---|---|
| cpu_generic | 범용 전투 컴퓨터 | 전열 | 1.6초 | 2 | 2 | 없음 |
| cpu_swarm | 군집 돌격 컴퓨터 | 군집·돌격 | 1초 | 3 | 2 | fire_control |
| cpu_picket | 초계 컴퓨터 | 초계 | 1초 | 3 | 2 | fire_control |
| cpu_line | 전열 컴퓨터 | 전열 | 1초 | 3 | 2 | fire_control |
| cpu_artillery | 포격 컴퓨터 | 포격 | 1초 | 4 | 3 | fire_control |
| cpu_siege | 공성 뇌격 컴퓨터 | 공성·뇌격 | 1초 | 4 | 3 | fire_control |

`carrier`(항모) 원형은 데이터·확장 지점만 있고 행동은 기본 제어다(함재기 체계가 없음).

경제: 전자 공장(`electronics_fab`) 레시피로 생산하며 가격은 다른 모듈처럼 레시피에서 나온다. 새 표준 월드
(`STANDARD_WORLD.computers = 'p151'`)는 공용 정거장 4곳(helios·astra·bastion·drakeout)에 판매 행을 넣는다(`stockComputers`, `st.cpuV = 1`).
**기존 월드에는 자동으로 넣지 않는다**(아래 보류 항목).

## 2. 연결 경로

`WShip.fitting.bay` → `cpuOfFitting()`(정렬된 베이 id 중 첫 컴퓨터) → 교전 `ShipSpec.cpu` → `World.spawnTeam` →
`Ship.cpu`(`initCpu`). 스커미시 설정 화면은 함선별 컴퓨터 선택(`data-scpu`), 개발 실험실은 피팅 베이로 선택한다.
피팅 목록(실험실·전략 피팅 UI)은 현재 무장 기준 전술·조준 거리·대역을 보여준다(`cpuSummary`, 전투와 같은 `cpuRange` 사용).

## 3. 규칙 버전·호환성

`BATTLE_RULES = 2`. `Ship.cpu`는 `rules >= 2`이고 원형이 basic이 아닐 때만 생기므로, 모든 신규 분기는 `s.cpu`로 막혀 있다.
기록된 전투(rules 0/1)는 `ShipSpec.cpu`가 있어도 무시된다.

검증: 변경 전 HEAD(5682e98)와 14개 매치업 × 3시드 × rules {0,1} × {cpu 필드 유무} = 168개 전투 다이제스트가 **완전히 동일**.

## 4. 사거리 대역 (`bandsOf` / `weaponBands`)

평균이 아니라 **실제로 쓸 수 있는 무장**(파손·탄약 소진·특수 무장 제외)에서 계산한다.
- 함수(艏) 오프셋 0, ±60°, ±90° 중 지향 화력이 가장 큰 각도를 고른다(`offset`). 그 각도에서 지향되지 않는 포(사각 170° 미만)는 대역에서 뺀다.
- 화력 20% 이상인 무장으로 **최소 / DPS 가중 중앙값 / 최대**를 정한다. 방공(pd)과 어뢰 사거리는 따로 둔다.
- 탑재 무장이 바뀌면(파손·탄약 소진) 서명(`mountSig`)이 바뀌어 다시 계산한다 — 미사일이 떨어진 포격함은 최대 사거리가 줄어든다.

## 5. 원형별 행동 (`steerComputers`, 3틱마다 기존 `steer()` 뒤에 실행)

| 원형 | 조준 거리 | 행동 |
|---|---|---|
| 군집·돌격 | max(반경합+60, 최소×0.6) | 측면 화력 비중이 절반 이상이면 표적 주위 선회, 아니면 표적 옆을 스치는 강습 → 이탈(1.25R) → 반대편 재진입 반복 |
| 초계 | 중앙값×0.85 (무장 없으면 방공×0.45) | 호위 대상(호위 명령의 최고가 함, 없으면 1,500 이내 자신보다 비싼 아군) 곁에서 근접 위협(어뢰정·초계함 가중)과 호위 대상 사이에 선다. 위협으로 표적 전환(플레이어 지정 표적은 존중). 방공 엄호 반경 1,100 |
| 전열 | 중앙값×0.88 (혼성 전열은 가장 짧은 중앙값) | 같은 그룹의 전열 컴퓨터 함끼리 적 중심에서 횡대를 이룬다. 가장 느린 함 속도에 맞추고, 최적 지향 각도로 표적을 유지 |
| 포격 | 최대×0.9 | 최대 사거리 유지 + 측방 이동. 가장 가까운 적이 R×0.78 안(이탈 중 0.92 히스테리시스)이면 비스듬히 후퇴 |
| 공성·뇌격 | 어뢰 사거리×0.55(직진)/0.85(유도) | 가치/거리로 대형함 선택(구조 보유 ×1.5) → 재장전 동안 사거리 밖 대기(도착 시점에 장전이 끝나도록 미리 출발) → 측후방으로 돌입 → 발사 → 표적의 사선을 가로지르며 바깥으로 이탈(최대 9초, 발사 대역을 벗어나면 종료) → 반대편 재진입 |

**명령 우선** (`orderAllows`): engage/attack에서만 동작. flank는 측면 기동이 끝나 strike 단계일 때만, escort는 초계만.
move·hold·reserve·retreat에서는 항상 기본 제어다. 플레이어가 지정한 표적은 초계·공성이 바꾸지 않는다.

**기본 제어로 돌아가는 경우**: basic·carrier, 어뢰 없는 공성, 공격 무장 없는 비초계, 공격·방공 모두 없는 초계.

전투 규칙 연결부(world.ts): 공성 돌입 중 어뢰 발사 거리 계수(`cpuLaunchFactor`), 초계는 부포가 자기 표적을 쏘고
군집은 주표적에 집중(`cpuOwnGuns`), 초계 방공 엄호(`cpuPdCover`). 컴퓨터가 동작 중이면 돌격형 함선도 `faceTo`를 따른다.

## 7. 보류·결정이 필요한 사항

1. **기존 월드 판매 행**: 기존 저장 월드에는 컴퓨터 판매 행을 자동 추가하지 않았다. 운영 월드에 넣으려면 명시적 마이그레이션(`stockComputers`)을 결정해야 한다.
2. **BB-EX·플랫폼**: 전용 선체와 플랫폼에는 컴퓨터 베이가 없다. 필요하면 선체 데이터에 직접 `computer` 베이를 넣으면 된다.
3. **항모 원형**: 함재기 체계가 없어 데이터만 있다.
4. **방공 전용 비초계 함**: 공격 무장이 없으면 초계 외 원형은 기본 제어로 돌아간다(명세의 "자동 최적화하지 않음" 해석).
5. **성장 콘텐츠 전용**: 컴퓨터는 contentV 3 월드에만 있다. 스커미시·실험실은 콘텐츠 버전과 무관하게 선택 가능.
6. **전열 지표**: 전열 유지를 직접 보여주는 지표(거리 표준편차)는 초계와 구분되지 않았다. 더 나은 측정법은 후속 과제.
7. **포격 초계함**: 짧은 사거리 함에 포격 컴퓨터는 비효율적이다(D2). 명세대로 자동 보정하지 않았다.
8. ~~공성 효율~~ → P15.1.1에서 분석·해결(8절). 피해 보너스 없이 기동만 고쳤다.
9. **대형함 공성**: 드레드노트처럼 둔한 함은 측후방 각을 만들지 못한다(D3). 명세상 함급 제한이 없으므로 그대로 두었다.

## 8. P15.1.1 안정화 — 공성 분석, 전열 검증, 브라우저, 기존 월드 이전

### 8.1 공성 컴퓨터: 시간 배분과 측후방 공격의 실제 이득

하네스 `npx vite-node scripts/p15/siege.ts [seeds] [T]` — 어뢰 한 발마다 발사 시점의 상대 각, 결과(명중·요격·빗나감),
명중 면(정면·측면·후면)과 피해, 함선별 시간 배분(대기·돌입·최종 돌입·이탈 × 장전/재장전)과 손실 시점. 원본 `docs/p15/siege-p1511.txt`.

**측후방 공격의 이득 (변경 전 측정, 단독 전함 L·호위 전함 C)**
- 피격 면은 탄의 진행 방향으로 정해지며(`applyHit`: cos < −0.6이면 후면), 선체 구조는 **후면 피격에만** 흡수를 절반으로 줄인다.
  측면과 정면 명중 피해는 같다(≈700). 후면 명중은 ≈880–917로 **약 +25%**, 치명타 확률도 ×1.8.
- 측면(60–120°) 발사는 명중률이 높고 요격이 적다: 단독 전함 0.69–0.73 vs 정면 발사 0.30–0.61, 요격 0.18–0.24 vs 0.33.
  → 측후방 돌입 자체는 실제 이득이 있다. 피해 보너스는 추가하지 않았다.

**변경 전 공성 기동의 낭비**
| 항목 | 변경 전 측정 | 원인 |
|---|---|---|
| 장전된 채 돌입 중인 시간 | 함선 시간의 17–19% | 재장전이 끝난 **뒤에** 대기 위치(어뢰 사거리의 약 1.75배)에서 출발 |
| 이탈 중 손실 | 손실의 절반 이상(단독 전함 4.5척 중 2.0) | 이탈 방향이 자기 속도 방향 = 표적 쪽이라 이탈하면서 표적의 함수·함미를 지나 부포 사정권을 가로지름 |
| 빗나감 | 단독 전함 0.23–0.26 (기본 0.05) | 발사 거리 ≈450m(어뢰 사거리×0.62)에서 직진 어뢰를 쏴 회피 기동에 빗나감 |

**변경 (rules 2 전용, 공성 전술 — 대기·측후방 돌입·발사·이탈·재진입 — 은 그대로)**
1. 남은 재장전 시간 ≤ 발사 거리까지 이동 시간이면 대기를 끝내고 출발(`soon`).
2. 이탈: 표적에서 바깥쪽 + 자기 쪽 측방(표적 사선을 가로지르는 방향). 정반대로 곧장 물러나는 이탈도 시험했지만 횡이동이 없어 포격에 더 잘 맞았다(단독 전함 손실 6.0) — 채택하지 않음. 발사 대역(어뢰 사거리×0.55×1.45)을 벗어나면 이탈 종료.
3. 직진 어뢰 발사 거리 계수 0.62 → 0.55(유도 어뢰 0.85는 그대로).

해석: 방공 호위가 있는 대형함 상대로는 공성이 기본보다 피해를 2–3배 준다(측면 발사가 요격을 덜 받음). 방공이 약한
단독 전함 상대로는 기본 제어가 이미 효율적이며, 공성은 반복 돌입 때문에 손실이 크다 — 공성의 전술적 대가로 남긴다

### 8.2 전열 vs 초계: 객관 지표

하네스 `npx vite-node scripts/p15/line.ts [seeds]` — 20초 이후 1초마다: 대형 깊이 오차(적 방향 축으로의 표준편차),
간격 불균일(gapCV), 아군에 가린 사선 비율(masked), 응집(coh), 최저속 함의 처짐(lag), 표적 거리, 표적에 지향 가능한
포 비율(bear), 장전됐지만 쏘지 않는 포 비율(idle). 원본 `docs/p15/line-p1511.txt`.

| 매치업 | 컴퓨터 | 깊이 오차 | gapCV | 가린 사선 | bear | idle | 가한/받은 피해 |
|---|---|---|---|---|---|---|---|
| L1 순양함 4 vs 4 | 기본 / 전열 / 초계 | 14 / 22 / 17 | 0.04 / 0.07 / 0.28 | 0 / 0 / **0.23** | 0.72 / **1.00** / 0.77 | 0.28 / **0.02** / 0.23 | 14,477 / **16,076** / 13,638 |
| L2 전함2+순양함2 | 기본 / 전열 / 초계 | 69 / **48** / 103 | 0.04 / 0.04 / 0.27 | 0 / 0 / 0.01 | 0.74 / 0.79 / 0.72 | 0.26 / 0.23 / 0.29 | 24,400 / 25,982 / 26,554 |

- **전열**: 간격이 고르고(gapCV ≈ 기본) 사선이 가리지 않는다. 측면 포가 많은 순양함(L1)에서는 지향 각도 유지로 포 지향률 1.00, 유휴 포 0.02.
  깊이 오차는 혼성·전함 전열(L2·L4)과 구축함(L3)에서 기본보다 작고, 순양함 단일 전열(L1)에서는 측면 지향을 유지하느라(선미 주기관이라 감속) 조금 크다.
- **초계**: 보호 대상 곁에 붙기 때문에 간격이 불규칙하고(gapCV 0.21–0.52), 순양함끼리일 때 23%가 아군에 사선이 가린다. 대신 B 매치업에서 전함 곁 135–146m, 차단 비율 0.68, 전함 잔여 HP 0.62–0.69(전열은 0.04–0.27).
- 둘은 같은 "중앙값" 대역을 쓰지만 목적이 다르다: 전열은 **대형·화력각**, 초계는 **보호 대상과 위협 사이의 위치**.

**최소 개선 1건**: 혼성 전열이 구성원 중앙값들의 **중간값**에 서서, 짧은 사거리 함(순양함 950m)이 전함 기준 거리(1,364m)에서
자기 포 사거리 밖에 서 있었다(표적 거리 1,150–1,250m). 전열 거리를 **가장 짧은 중앙값**으로 바꿨다 →
L2 깊이 오차 93 → 48, 가한 피해 17,164 → 25,982(기본 24,400). 테스트로 고정(`p15-computers`).

### 8.4 기존 월드의 컴퓨터 판매 데이터 이전 (준비만, 운영 미실행)

- 함수 `migrateComputers(st)` (`src/world/industrialGear.ts`): c3 이전 월드는 거부, 이미 적용된 월드는 건너뜀(멱등). 공용 정거장 4곳에
  새 표준 월드와 같은 13개 판매 행만 추가하고 `cpuV = 1`. 함선·피팅·자금·보관함·기존 시장 행은 건드리지 않는다.
  컴퓨터는 rules ≥ 2 전투에서만 동작하므로 진행 중이거나 기록된 전투는 바뀌지 않는다.
- 서버 시작 옵션 `COMPUTERS_P151_MIGRATE=1` (기본 꺼짐) — 로그 `[siderarium] P15.1 전투 컴퓨터 판매: 적용 — 시장 N행`.
- 점검 스크립트 `npx vite-node scripts/p15/cpu-migrate-check.ts -- [save.json]`: 저장본 사본에 서버 시작 경로로 적용해
  변경이 컴퓨터 판매 행과 `cpuV`뿐인지, 재실행 무변화, c2 거부, 이후 정상 진행을 확인한다(입력 파일은 쓰지 않음).
  레거시 표준 월드로 실행: 전 항목 통과(13행 추가, 다른 변경 0).
- 운영 절차(실행하지 않음): 저장본 백업 → 점검 스크립트를 백업 사본에 실행 → 서버를 `COMPUTERS_P151_MIGRATE=1`로 한 번 시작 →
  로그 확인 → 변수 제거.
