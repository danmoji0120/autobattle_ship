## 3. 동작 규칙 (구현된 그대로)

### 3.1 생성과 게이트

- 함재기 풀은 `rules ≥ 3`이고 전투에 `kind 'craft'` 무장이 하나라도 있을 때만 생긴다.
  - 생성 시점은 전투 시작 또는 증원 합류(`join`)다.
  - 풀이 `null`이면 새 코드는 돌지 않는다. RNG도 뽑지 않는다.
- 규칙 2 이하 전투에 함재기 무장이 실리면 그 마운트는 아무것도 하지 않는다(`updateWeapons`에서 건너뜀).
- **추가 원칙 1**: 비행대는 **무장 데이터(`kind 'craft'`)로** 찾는다. 함급 이름을 보지 않는다.
  - 테스트로 확인했다: 순양함에 함재기 무장을 피팅해도 발진한다.
  - 장착 제한(H 하드포인트·`flight` 베이)은 P16.2의 선체·하드포인트 데이터에서 처리한다.

### 3.2 비행대 판단 (약 3 Hz)

- **항모 상태**:
  - 탈출했거나 진영이 이탈하면 모든 기체가 이탈한다.
  - 격침(`dying` 이후)되면 탑재 기체는 사라지고, 공중 기체는 고아 상태가 된다.
- **임무**:

  | 비행대 | 임무 |
  |---|---|
  | 전투기 | 항모 주변(작전 반경 60 %)에 적 비행체가 있으면 공중전, 없으면 함선 공격 |
  | 뇌격기 | 대형함 우선 함선 공격 |
  | 요격기 | 적 비행체·유도 탄체가 항모 주변에 있으면 요격, 없으면 직위(CAP) |

- **함선 표적**: 항모의 지휘관 표적(`ai.targetId`)이 작전 반경 안이면 그 함선을 친다. 아니면 반경 안에서 점수가 가장 높은 함선을 고른다.
- **발진 조건**: 임무가 있거나 적 함선이 반경 × 1.1 안에 있을 때.
- **추가 원칙 2**: 함재기 외 공격 무장이 없는 항모도 적을 탐지하고 교전한다.
  - 탐지는 기존 지휘관 AI가 거리 제한 없이 한다.
  - 교전 거리는 함재기 작전 반경을 기준으로 잡는다(§3.5).

### 3.3 기체 (매 틱)

- **이동**: 목표점으로 선회율(`agility`) 제한 조향을 한다. 속도는 `speed`로 수렴한다.
- **작전 반경**: 항모에서 반경 × 1.1을 넘으면 항모 쪽으로 돌아온다.
- **함선 공격**:
  - 기체마다 방위를 달리해 접근하고, 기관포를 쏜다.
  - 근접하면 이탈(2.2초)한 뒤 다시 진입한다.
  - 뇌격기는 무장 사거리 55 % 안, 정렬 30° 이내에서 어뢰를 1발 투하하고 귀환한다.
- **공중전**: 기체마다 격자 이웃 질의로 가장 가까운 적 비행체를 고른다(0.6초마다). 요격기는 폭장한 뇌격기를 우선하고, 없으면 유도 탄체를 노린다.
- **기관포 = 즉시 판정**: 거리·표적 크기·회피로 명중 확률을 정하고 전투 RNG로 판정한다. 탄체 객체는 만들지 않는다.

  | 표적 | 명중 시 처리 |
  |---|---|
  | 함선 | `applyHit` (장갑 면·관통·도탄·구획 피해·치명타). 공격자는 항모. 피해는 항모 `stats.dmgDealt`에 합산 |
  | 비행체 | HP 차감 |
  | 탄체 | 탄체 HP −1. 요격은 항모 `stats.intercepts`에 합산 |

- **귀환**:
  - 출격 시간이 끝나면 항모로 돌아가 회수된다. `turnaround` 뒤 재무장해 재출격할 수 있다.
  - H 마운트가 치명타로 비활성이면 발진·회수가 멈추고, 귀환 기체는 항모 근처에서 대기한다.

### 3.4 손실과 보충 (추가 원칙 5)

- 격추되면 예비 기체(`spares`)에서 1기를 꺼내 `turnaround` 뒤 다시 발진할 수 있게 한다.
- 예비가 떨어지면 비행대는 줄어든 채 싸운다.
- 모두 전투 단위다. 새 소모품이나 전투 사이의 기체 손실은 없다.

### 3.5 항모 격침·진영 소멸 (추가 원칙 4, D7)

- **항모 격침**:
  - 탑재 중·정비 중 기체는 사라진다.
  - 공중 기체는 남은 출격 시간 동안 싸운 뒤 이탈한다(`craftLeave`).
  - 다른 항모의 회수(D6-b)는 후속 확장으로 미뤘다.
- **진영 이탈·소멸**: 그 진영의 비행체는 즉시 이탈한다. 비행체는 승패·가치 계산에 들어가지 않는다.

### 3.6 함선 PD (추가 원칙 3)

- PD 재표적 때 탄체 점수와 비행체 점수를 같은 척도로 비교한다.

  | 대상 | 점수 |
  |---|---|
  | 탄체 | 기존 그대로: −거리 + 어뢰 200 + `pdThreat` |
  | 비행체 | −거리 + 폭장 뇌격기 150 + 이 함선을 노리는 비행대 100 |

  - 비행체가 더 높을 때만 비행체를 쏜다.
  - 그래서 위협적인 탄체가 있으면 탄체 요격이 우선이고, 없으면 비행체를 쏜다.
- **PD 사격**:
  - 즉시 판정. 확률은 `pdChance × 2.4 × pdBonus / (1 + agility × 0.25)`이고, 블랙아웃 효과를 받는다.
  - 피해는 PD 무장 피해량이다.
- **포탄**: 비행체와 충돌 판정하지 않는다(D8-a). 기존 탄체 루프는 바뀌지 않았다.

### 3.7 지휘관·전투 컴퓨터

- 교전 거리(`preferredRange`):
  - 함재기를 포 사거리 계산에서 뺀다.
  - 함재기 화력이 포 화력보다 크면 타격 비행대(전투기·뇌격기) 작전 반경의 화력 가중 평균 × `lerp(0.8, 0.55, 공격성)`으로 거리를 잡는다. 카이팅 중에는 0.85다.
  - 요격기는 방어용이라 기준에서 뺀다. 요격기만 있으면 그 반경을 쓴다.
- 표적 배정 화력, 전투 컴퓨터 사거리대에서도 함재기를 뺀다.
- 함재기 무장 정의의 `salvo`는 0이다. `damage × salvo / reload` 형태의 일반 화력 합산에서 0으로 잡힌다.
- 나머지 `kind` 가정 위치(렌더·전투력 평가·UI 등)의 전수 분류는 계획대로 P16.2에서 한다.

### 5.3 성능 (T4, `docs/p16/craft-perf.txt`)

**측정 조건**
- 이 컨테이너, 단일 전투, 시드 5, 30 Hz 스텝, 최대 6000틱(200초) 또는 종전까지, 1회 실행.
- 항모는 비행대 10기 단위(전투기·뇌격기·요격기 순환)이고, 전함·방공 구축함과 함께 편성했다.
- "혼전 구간"은 비행체 정원의 50 % 이상이 공중에 있던 스텝만 모은 값이다.
- "비행체 갱신"은 같은 전투를 한 번 더 돌려 `CraftPool.update`만 잰 값이다. 두 실행의 다이제스트가 같음도 확인했다.

| 구성 | 전체 평균 / p95 / 최대 (ms) | 혼전 구간 평균 / p95 (ms, 스텝 수) | 비행체 갱신 평균 (ms) | 최대 공중 | 목표 평균 / p95 / 최대 |
|---|---|---|---|---|---|
| 함선 24 + 0 (규칙 3) | 0.10 / 0.32 / 2.8 | — | — | 0 | — |
| 함선 24 + 200 | 0.10 / 0.27 / 1.2 | 0.31 / 0.68 (573) | 0.028 | 163 | ≤ 1.5 / 3 / 10 |
| 함선 24 + 400 | 0.11 / 0.30 / 0.9 | 0.26 / 0.43 (573) | 0.038 | 308 | ≤ 3 / 6 / 15 |
| 함선 60 + 800 | 0.23 / 0.82 / 2.8 | 0.79 / 1.58 (616) | 0.071 | 744 | ≤ 8 / 16 / 33 |
| 함선 60 + 800, 함선 PD 없음 (스트레스) | 0.29 / 0.90 / 4.1 | 0.75 / 1.61 (747) | 0.15 | 777 | (참고) |

**해석**
- 모든 구성이 목표를 충족한다. 가장 엄격한 혼전 구간 기준으로도 800기 평균이 목표의 약 1/10이다.
- 비교: P16.0 측정에서 비행체 400기를 일반 함선으로 만들면 10.38 / 21.57 / 41.1 ms였다.
- 비행체 갱신 자체는 스텝 시간의 일부다. 나머지는 함선 PD 표적 선택, 함재기 어뢰 탄체, 늘어난 피격 이벤트다.
- 교전량(800기 구성): 발진 1220, 격추 1068, 함선 기관포 명중 263, 항공 어뢰 256, 함선 격침 55.

**한계**
- 단일 실행이고, 같은 컨테이너의 다른 작업과 경합할 수 있다.
- 브라우저(락스텝 클라이언트) CPU와 렌더 비용은 측정하지 않았다. 렌더는 P16.4 범위다.

### 5.4 빌드

- `npm run build`(tsc 타입 검사, vite 빌드, 서버 번들) 통과. 청크 크기 경고는 기존과 같다.
- `npm run content:check`는 실행하지 않았다. 콘텐츠 팩을 바꾸지 않았기 때문이다(`bbex/index.ts`는 타입 표기만 바꿨다).
- 전체 회귀(`npm test` 전체)도 실행하지 않았다. 관련 파일만 순차 실행했다(AGENTS.md 원칙 5).

## 6. 사용자 결정이 필요한 사항 / 보류

| # | 사항 | 현재 상태 | 제안 |
|---|---|---|---|
| Q1 | `BATTLE_RULES`를 3으로 올리는 시점 | **2로 유지했다.** 규칙 3은 셋업에 명시할 때만 쓰인다. 함재기 콘텐츠가 게임에 없으므로, 지금 올려도 결과는 같다(T2) | P16.2에서 함재기 콘텐츠와 함께 올린다 |
| Q2 | 함재기 피해에 항모 지휘관(장교)의 사격 효과 적용 | `applyHit`의 공격자가 항모라서 장교 효과(관통·대형함 피해·치명타 보정)가 함재기 기관포에도 적용된다 | 유지하거나, 함재기 전용 장교 효과를 B-1 트리에 둔다(P16.3 결정) |
| Q3 | 기본 제어 항모의 위치 | 교전 거리는 작전 반경 기준이다. 그러나 적이 다가오면 적 함포 사거리 안까지 들어가 피격된다 | 설계 §7 계획대로 P16.3 항모 컴퓨터(적 사거리 밖 유지)에서 처리 |
| Q4 | 다른 항모의 회수(D6-b) | 미구현. 항모를 잃으면 출격 종료 후 이탈한다 | 사용자 지시대로 후속 확장 |
| Q5 | 시제품 수치(PD 대 비행체 확률·우선순위 점수, 기체 수치) | 동작 확인용 값. 현 수치에서는 방공 구축함 PD가 비행체를 빠르게 격추한다(800기 구성에서 격추 1068) | P16.5 밸런스 측정에서 확정 |

**하지 않은 것 (범위 밖)**
- P16.2: H 하드포인트·`flight` 베이·장착 규칙, 콘텐츠 팩 항모·함재기, 검증기 예산 점수, `kind` 약 60곳 전수 분류
- P16.3: 항모 컴퓨터·관제 한도, 전투력 평가, 항공 모듈 효과(`ShipFx.air`)
- P16.4: 렌더(비행체 인스턴스, 기관포 예광탄 묶음 이벤트), HUD
