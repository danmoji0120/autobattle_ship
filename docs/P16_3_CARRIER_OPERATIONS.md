# P16.3 항모 운용: 항공 관제·항모 컴퓨터·장교 효과 분리·전투력 평가

상태: **구현·검증 완료 (기준 `ae5e74d`)**. 설계는 `docs/P16_0_FIGHTERS_CARRIERS.md`를 따른다. 전투 엔진 시제품은 `docs/P16_1_CRAFT_ENGINE.md`, 콘텐츠·피팅은 `docs/P16_2_CARRIER_CONTENT.md`에 있다.

공개 정책(승인 사항)은 다음과 같다.
- 여명급 항모는 일반 월드에서 계속 **미공개**(`HullDef.preview`)로 둔다.
- 개발 실험실에서만 "전투 규칙 3"을 명시한 실험으로 항모를 시험할 수 있다.
- 스커미시 공개는 P16.4에서 한다. 실제 월드 공개는 통합 검증·밸런스 검토 뒤 결정한다.
- 기본 `BATTLE_RULES`는 2 그대로다(상향 보류).
- 운영 서버 배포와 실제 마이그레이션은 하지 않았다.

## 1. 미공개 장비 보호 (`gearReleased`)

미공개 항모에만 쓸 수 있는 장비를 일반 플레이어가 쓸모없이 생산·구매하지 않게 막는다.

`gearReleased(equipId, reg)` (`src/content/registry.ts`)의 판정은 다음과 같다.

| 장비 | 공개 조건 |
|---|---|
| 함재기 무장 3종 (`kind: 'craft'`), 항모 관제 컴퓨터(`cpu.arch: 'carrier'`) | 공개 선체의 파생형 중 격납(H) 하드포인트를 가진 것이 있음 |
| 항공 모듈 3종 (`slot: 'flight'`) | 공개 선체의 파생형 중 `flight` 베이를 가진 것이 있음 |
| 그 밖의 모든 장비 | 항상 공개 (기존과 동일) |

이 판정을 적용한 경로는 다음과 같다.

| 경로 | 동작 |
|---|---|
| `prodOrder` (서버 명령) | "…: 장착할 수 있는 공개 선체가 없어 생산할 수 없음" |
| `buy` (서버 명령) | 시장 행이 있어도 "…: 장착할 수 있는 공개 선체가 없어 구매할 수 없음". 현재 어느 시장도 이 장비를 재고로 두지 않는다. |
| 회사 운영 생산 계획 (`operations.ts producible`) | 레시피 후보에서 제외 |
| 산업 화면 레시피 목록 (`industryUi.ts`) | 표시하지 않음 |
| 인양 역설계 연구 (`research.ts salvageItem / salvageable`) | 대상에서 제외 |

항모 선체 공개(`preview` 제거) 시 이 장비들은 콘텐츠 변경 없이 자동으로 공개된다(테스트에서 공개 레지스트리 사본으로 확인).

### 1.1 함재기 무장의 시간당 소모품 제거
- 함재기 무장 3종의 `supply: { chemicals: 0.8 }`를 삭제했다. 이 값은 장착 함선의 시간당 유지 소모품으로 작용했다.
- 함재기 운용 비용은 후속 밸런스 단계에서 다시 검토한다(보류).

## 2. 개발 실험실: 전투 규칙 3 실험

- `LabConfig.rules?: 3` 필드를 추가했다. 조건 패널에 "전투 규칙" 선택을 두었다(기본값 = `BATTLE_RULES`, 또는 3).
- `availableHulls(rules)`는 규칙 3일 때만 미공개 선체(항모)를 선택 목록에 넣는다.
- `configProblems` 검사 내용은 다음과 같다.
  - `rules`는 생략하거나 3이어야 한다.
  - 미공개 선체를 규칙 3 없이 쓰면 "미공개 선체(항모)는 전투 규칙 3을 선택한 실험에서만 쓸 수 있습니다" 오류를 낸다.
  - 구형(schema 1) 설정은 계속 미공개 선체를 거부한다.
- `battleSetup`은 `rules: config.rules ?? BATTLE_RULES`로 전투를 만든다.
- 규칙을 바꾸면 편성 화면을 새로 그린다. 선택 목록의 선체가 사라지면 기본 선체로 되돌린다.
- 실험실 기본 항모는 항모 컴퓨터를 자동 장착하지 않는다. 사용자가 피팅에서 고른다.

## 3. 항공 모듈 효과 연결: `AirSpec` → `ShipFx.air` → 비행체 풀

| 단계 | 위치 | 내용 |
|---|---|---|
| 콘텐츠 | `AirSpec` (`air_hangar_ext / air_control / air_maint`) | `complement`, `control`, `spares`, `turnaround` |
| 월드 | `airFx(fit)` (`industry.ts`), `shipFxOf` (`sim.ts`) | 장착 모듈을 합성한다. `complement`·`control`은 합, `spares`·`turnaround`는 곱이다. 항공 모듈이 없으면 `undefined`(기존 `ShipFx`와 같음). |
| 실험실 | `labModel.shipFx` | 같은 `airFx` |
| 전투 | `ShipFx.air` → `Ship.air` (`createShip`) | 규칙 3에서 비행체 풀만 읽는다 |
| 비행체 풀 | `effectiveCraft(base, air, ofx)` (`craft.ts`) | H 슬롯마다 기체 수 `+complement`, 예비 기체 `×spares`(반올림), 재무장 시간 `×turnaround × (1 − ofx.airTurn)` |
| 관제 | `wingControl(air, ofx)` | `BASE_CONTROL(3) + control + ofx.airCtl` |

`effectiveCraft`는 전투력 평가(§7)도 같이 쓴다. 그래서 전투와 평가의 수치가 어긋나지 않는다.

## 4. 항공 관제와 비행대 임무 배정 (`src/sim/craft.ts`)

- 항모 한 척의 비행대들은 **비행단(Wing)**으로 묶여 함께 판단한다(`THINK` 주기마다 비행단별로).
- 임무는 직위 엄호(CAP)·공격(STRIKE)·요격(AIR)·호위(ESCORT) 네 가지다.

| 임무 | 조건 | 우선순위 |
|---|---|---|
| AIR (요격) | 항모 근처에 적 비행체·유도탄 위협 | `4 + min(3, 위협/4)` |
| ESCORT (호위) | 전투기·요격기. 작전 반경 안의 아군 함선에 적 비행체가 700 이내로 접근 | 3 |
| STRIKE (공격) | 뇌격기 2.5(대상이 전열함) 또는 2, 전투기 1 | 2~2.5 / 1 |
| CAP (직위 엄호) | 그 밖의 경우, 요격기의 기본값 | — |

- **관제 한도**: 우선순위가 높은 임무부터 `control`개 비행대만 임무를 맡는다. 나머지는 CAP으로 돌리고 `stats.held`로 센다.
- CAP 비행대는 항모 반경 `CAP_R = 650` 안에 들어온 적 비행체와 교전한다(탐색은 `CAP_R × 1.3`까지).
- ESCORT는 보호 대상 함선을 중심으로 선회하고, 그 함선 1000 이내의 적 비행체를 노린다. 유도탄 요격은 요격기의 AIR 임무만 한다.
- `stats.tasks[4]`에 임무별 판단 횟수가 쌓인다(분석·테스트용).

**설계 결정(보고)**: `BASE_CONTROL = 3`이다. 표준 비행단(비행대 4)은 관제 장치 없이 최대 3개 비행대만 동시에 임무를 맡는다. 관제 장치를 달면 4개 모두 맡는다. 이 수치는 밸런스 검토 대상이다.

## 5. 항모 전투 컴퓨터 (`src/sim/ai/computer.ts` `carrier`)

- 컴퓨터 제품은 `cpu_carrier` '항모 관제 컴퓨터'다.
  - computer 베이, S, 질량 2, 전력 4, 연구 `combined_arms`, electronics_fab에서 생산한다.
  - 함재기 장비와 같이 미공개 게이트를 받는다.
- 행동은 다음과 같다.
  - 비행단이 없으면(함재기 미장착 또는 규칙 < 3) 기본 제어로 넘어간다.
  - **회피**: 적 함포 사거리 + 220 안이거나, 자신을 노리는 유도탄이 900 안에 있으면 전속으로 이탈한다. 들어오는 탄에는 측면을 보인다.
  - **거리 유지**: 표적 집단 중심에서 `max(500, min(적 최대 사거리 + 220, 작전 반경 × 0.85))` 거리를 유지한다.
  - **호위와의 거리 제한**: 아군(항모 제외) 중심에서 1100 이상 떨어지지 않는다. 가장 가까운 적의 사거리 + 110 안으로는 들어가지 않는다.
- 측정 결과는 아래와 같다.
  - 조건: 항모(표준 비행단) + 순양함 2 대 순양함 3, 규칙 3, 150초, 시드 7·8·9.

| 시드 | 기본 제어: 적 최근접 / 항모 선체 | 항모 컴퓨터: 적 최근접 / 항모 선체 |
|---|---|---|
| 7 | 514 / 0.35 | 1187 / 1.00 |
| 8 | 395 / 0.31 | 841 / 0.83 |
| 9 | 709 / 0.46 | 1159 / 0.92 |

  - 같은 조건에서 항모의 가한 피해는 기본 4777~6190, 컴퓨터 6206~6803이었다(줄지 않음).

## 6. 장교 효과 분리

- `applyHit(t, w, attackerId, pos, dir, kind, air = kind === 'craft')`로 바꿨다.
  - 함재기 기관포(`kind 'craft'`)와 뇌격기 어뢰(`Munition.air`)는 `air`로 표시된다.
  - `air` 명중에는 **함포 장교 효과**(관통 `pen`, 피해 `dmgCap / dmgSmall / rearDmg`, 치명 `crit`)를 적용하지 않는다.
  - 표적 쪽 방어 효과(`critRes`, 대형 방호 등)는 그대로다.
- **항공단 전문 효과 확장 지점**은 `ofx.airDmg`(함재기 피해), `ofx.airCtl`(관제 한도), `ofx.airTurn`(재무장 단축)이다.
  - 전투 엔진은 이미 읽는다.
  - 이 효과를 주는 장교 스킬은 아직 없다. 스킬 트리 추가는 후속 과제(보류)다.
- 함선 포격(`kind` ≠ craft)의 기본값은 기존 그대로다. 그래서 비행체가 없는 전투의 결과는 바뀌지 않는다(§9 다이제스트).

## 7. 전투력 평가와 경량 전투 판정

### 7.1 `combatRating.raw()` 항공 항
- 함재기 마운트는 `effectiveCraft(무장 CraftStats, fx.air, ofx)` 기준으로 평가한다.
- 비행대 하나의 기대 피해는 다음 두 항의 합 × 기체 수 × 생존율 0.7이다.
  - 기관포: 초당 피해 × 표적 위 시간 0.5 × 명중 0.7 × 관통 기대치(기준 함선 측면 장갑 평균)
  - 탑재 무장: 출격 주기당 1발 × 관통 기대치 × (1 − 표적 PD 차단율)
- CALIB에 항모 항목은 없다. 실전 보정(`scripts/b3/rating-calibrate.ts`)은 항모 공개 전 밸런스 단계의 과제다.

| 평가 (평균 함장) | 값 |
|---|---|
| 순양함 `cruiser` (기준, 변하지 않음) | 139.16 |
| **여명급 항모 표준 비행단** | **291.4** |
| 같은 항모, 함재기 없음 | 178.3 |
| 전함 `battleship` | 376.4 |

- 항모를 운용하는 월드 전투는 규칙 3이어야 한다. 기본 규칙(2)에서는 함재기가 출격하지 않는다.
- 이 평가는 항모 공개(그리고 규칙 3 적용) 이후를 전제로 한다. 지금 일반 월드에는 항모가 없으므로 영토 군사력에 영향이 없다.

### 7.2 경량 판정 (`quickResolve` / `quickResolveP11`)
- 함선 가치에 `airValue(s, g)`를 곱한다.
  - 표준 비행단을 기본 장비로 갖는 함급(항모)만 `airValueMul(cls, 실제 탑재, fx, 장교 ofx)`를 계산한다.
  - 값은 `rate(실제) / rate(표준 비행단)`이고, 0.3~1.6으로 제한한다.
- 그 밖의 모든 함선은 정확히 1이다. 그래서 기존 가치와 난수 소비가 바뀌지 않는다.
- 결과: 표준 비행단이면 ×1(함급 가치 250 그대로), 함재기를 빼면 약 ×0.61, 항공 모듈을 달면 1보다 크다.

1. 저장 파일을 백업한다.
2. `CARRIERS_P16_MIGRATE=1`로 한 번 시작한다.
3. 로그에서 "적용 — 시장 N행"을 확인한다.
4. 변수를 제거한다.

## 10. 미완료·미검증·보류

- **미검증 — 격침 항모 잔해의 함재기 무장(P16.0 T11 후반)**: 일반 월드에서 항모를 만들 수 없어 실제 경로로 확인하지 않았다. 잔해는 피팅 장비 목록을 쓰므로 같은 경로를 탈 것으로 보이나, 확인은 공개 전 통합 검증 과제다.
- **보류 — 밸런스**: `BASE_CONTROL`, `CAP_R`, 항모 컴퓨터 거리값, 평가 상수(생존율 0.7 등), 함재기 운용 비용(§1.1). 항모 CALIB 실측은 공개 전에 한다.
- **보류 — 항공단 장교 스킬**: 효과 키(`airDmg / airCtl / airTurn`)만 마련했다.
- **보류 — 기본 전투 규칙 상향**: `BATTLE_RULES = 2` 유지.
- **P16.4** — 스커미시 공개·렌더링.
- **미실행** — 운영 배포, 실제 마이그레이션.
- **브라우저 확인 미실시**: 실험실의 "전투 규칙" 선택 UI는 타입 검사·빌드와 `labModel` 단위 테스트로만 확인했다.
