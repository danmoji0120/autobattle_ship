## 3. 검증 의도 복구

### 3.1 `tests/p16-client.test.ts` (4 시험, 통과)

1. **규칙 게이트** — `BATTLE_RULES`는 2이고, 항모의 표준 로드아웃에 함재기가 있다.
   - 토글을 끈 상태: 일반 함대는 규칙 2, 항모 함대는 출격 차단.
   - 토글을 켠 상태: 규칙 3.
   - 판정은 `setup.ts`에서 순수 함수 `skirmishGate(fleet, trial)`로 분리했다. 화면과 시험이 같은 판정을 쓴다.
2. **함재기 없는 전투** — 풀이 생기지 않고, 그리는 기체도 0이다.
3. **역할 배치 + 결정론**
   - 렌더링하는 전투와 렌더링하지 않는 같은 전투를 900틱 동안 나란히 돌린다. 매 프레임 `drawn`이 시뮬의 OUT 상태 기체 수와 같다.
   - 다이제스트는 150틱마다 두 전투가 같다.
   - InstancedMesh는 4개다(역할 3 + 장착 어뢰).
4. **예광선 = 실제 사격** — 매 틱 표본을 뜨면, 공중에 머문 슬롯의 쿨다운 리셋 수와 `CraftView.shots`가 정확히 같다. 출격 때 쿨다운이 초기화되는 경우는 사격이 아니므로 제외한다.

## 5. 실제 공중 기체 200 / 400 / 800기 렌더 (`scripts/p16/browser-check.mjs` → `artifacts/p1641/metrics.json`)

**측정 조건**

- 헤드리스 Chromium, **SwiftShader 소프트웨어 WebGL**, 1280×720.
- 항모(관제 컴퓨터)와 **방공이 없는 함포 전용 표적** 전함 24척을 650m 거리에 배치했다. 격추가 없어서 출격한 기체가 계속 공중에 머문다.
- 300틱(10초) 뒤 측정했다.
- 프레임 하나 = sim 2틱 + 렌더 + `gl.finish()`이고, 30프레임을 쟀다.
- 함재기를 숨긴 같은 장면을 15프레임 따로 쟀다.

| 목표 | 항모 | 편성 정원 | **실제 공중(최소/최대)** | 그린 수 = 공중 | 렌더 CPU/프레임 | draw call (보임 / 숨김) | 프레임 평균 / p95 / 최대 (보임) | 숨김 평균 |
|---|---|---|---|---|---|---|---|---|
| 200 | 7 | 210 | **210 / 210** | 30/30 프레임 | 0.37 ms | 973 / 968 | 9.0 / 15.3 / 21.4 ms | 35.7 ms |
| 400 | 14 | 420 | **420 / 420** | 30/30 | 0.32 ms | 1295 / 1290 | 12.1 / 19.1 / 21.3 ms | 5.3 ms |
| 800 | 27 | 810 | **807 / 807** | 30/30 | 0.37 ms | 1893 / 1888 | 95.0 / 215.6 / 364.1 ms | 102.5 ms |

**해석**

- 목표 수와 실제 비행 수를 구분해 적었다. 800기 목표에서 실제로 **807기가 동시에 비행**했다. 풀 슬롯 버퍼(1024)나 편성 정원(810)이 아니라 OUT 상태 기체 수다.
- 함재기가 더하는 draw call은 기체 수와 상관없이 **5회**다(InstancedMesh 4 + 궤적 1). 전체 draw call 수는 함선 수(항모 27척 + 전함 24척)를 따라 늘어난다.
- 함재기 렌더 CPU는 807기에서도 **프레임당 약 0.4 ms 이하**다.
- 프레임 시간 절대값은 신뢰하기 어렵다.
  - SwiftShader를 쓰는 컨테이너에서는 부하에 따라 값이 크게 흔들린다. 200기에서 함재기를 숨긴 쪽이 오히려 느리게 나왔고, 800기에서도 보임/숨김 차이가 오차 범위 안이다.
  - 실제 GPU나 모바일 기기의 FPS가 아니다. P16.4 문서의 장시간 실시간 측정(약 300 ms)도 같은 이유로 비교 기준이 아니다.
- 이 측정은 **격추 0기**(방공 없음) 조건이다. 방공 요격과 격추 이펙트가 몰리는 고강도 전투의 최악 프레임은 증명하지 않는다.

**관찰** (밸런스 조정은 범위 밖이라 기록만 했다)

- **귀환·재출격 사이클은 실제로 돈다.**

- **항모전에서 양쪽 항모 선체가 300초 동안 100%였다.** 뇌격기는 어뢰를 20~52발 투하했지만 모두 호위함을 노렸다. 항모를 직접 타격하는 우선순위가 낮은 것으로 보인다.
- **스커미시 편성과 원거리 편성은 모두 3분 안에 패했다.** 케스트렐 적 15척 대비 전력 열세이고, 항모 단독 원거리 운용도 열세다.
- 위 셋은 함재기 표적 우선순위·생존성 밸런스 과제로 남긴다(P16.5 이후, 사용자 결정 필요).

## 7. 모바일 HUD·항모 편성 화면 (390×844, `artifacts/p1641/mobile-*.png`)

**발견**

- 스커미시 편성 화면은 P16.3 기준 커밋(`a7a74fe`)에서도 휴대폰 폭에서 넘쳤다.
  - 하단 `.sfoot` 폭이 841px였고, **출격 버튼이 x=706으로 화면 밖**에 있었다.
  - 패널은 단일 열에서 높이 0으로 눌려 서로 겹쳤다.
- P16.4에서 추가한 "규칙 3 시험" 토글도 화면 밖(x=448)에 놓여 클릭할 수 없었다. 기존 문제이지만, 항모 시험의 진입점을 막는 문제였다.

**수정** (`style.css`, `max-width: 760px`에서만 적용. 데스크톱은 변경 없음)

- `#setup`과 `.sbody`를 `minmax(0,1fr)` 단일 열로 바꿨다.
- 패널은 내용 높이를 쓰고, 목록은 최대 60vh로 제한했다.
- 하단은 줄바꿈되게 했다. 예산 · 메인 메뉴 · 시험 토글 / 기본 편성 · 출격 / 작전 설명.
- 시나리오 카드는 가로 스크롤로 바꿨다.
- 편성 행은 두 열로 바꿨다.

**검증 결과**

- 페이지 가로 넘침 0이다.
- 항모 행, 선택 상자, 토글, 출격 버튼이 모두 화면 안에 있다.
- 실제 클릭으로 시험 토글 → 항모 추가 → 출격까지 진행된다.
- 전투 HUD의 날개 줄(`#gwing`)은 지휘 패널 폭(약 134px) 안에서 줄바꿈되며 넘침이 없다.

**남은 문제 (기존, 이번 범위 밖)**

- 휴대폰 전투 화면은 지휘 패널·통신창·도움말이 화면 대부분을 덮는다.
- 날개 줄 자체는 넘치지 않지만, 좁은 열에서 비행대 칩이 4줄로 늘어난다.
- 전투 HUD의 모바일 배치 개편은 별도 과제다.

## 9. P16.5 수정 과제 — `airValue()` 혼합 H 슬롯 함선

- **위치**: `src/world/sim.ts` `airValue()`(약 4580행)와 `src/world/combatRating.ts` `airValueMul()`.
- **문제**
  - `if (!hasCraft(cls.loadouts[0])) return 1;`은 **함급의 표준 로드아웃**에 함재기가 없으면 실제 피팅과 상관없이 항공 전력을 무시한다.
  - `airValueMul`도 표준 로드아웃을 기준값(`ref`)으로 삼는다. 그래서 H 슬롯을 단 순양함·전함 변형은 평가가 틀린다.
- **현재 영향**: 없다. H 슬롯 함급은 여명급 하나이고, 그 표준 로드아웃이 비행단이다.
- **수정 방향**
  - 실제 로드아웃/피팅의 `hasCraft`로 판정한다.
  - 함포 전력과 항공 전력을 가산하는 모델로 바꾼다.
  - 비항모 함급은 계속 정확히 1이 되도록 시험으로 고정한다.
  - 평가 난수 소비 순서가 바뀔 수 있으므로 다이제스트를 갱신한다.
- **시점**: P16.5 착수 시, 그리고 H 슬롯 혼합 변형을 추가하기 전에 반드시 수정한다.

## 10. 남은 문제·미검증

- GitHub Actions에서 복구한 CI가 실제로 통과하는지는 미확인이다.
- 전체 회귀에서 드러난, 이전 문서에 없던 기존 실패 5건(`econ-baseline`, `p12-ops`, `p131-p11-outcome`, `p131-salvage` ×2)은 원인 조사가 필요하다(§8.1). `a7a74fe` 이전 어느 단계에서 생겼는지는 확인하지 않았다.
- 실제 GPU·모바일 기기의 FPS와 고강도 항공전(방공·격추 이펙트 집중) 렌더는 미측정이다(§5).
- 함재기 손실률, 항모 비타격, 스커미시 열세는 밸런스 과제로 기록만 했다(§6).
- 휴대폰 전투 HUD 전반의 배치(기존 문제)는 손대지 않았다(§7).
- 운영 배포와 마이그레이션은 미실행이다(지시대로).
