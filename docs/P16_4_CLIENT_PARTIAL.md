# P16.4 — 항모 클라이언트 통합 (연결 코드, 검증 대기)

기준 커밋: a7a74fe. 이 문서는 브라우저 검증을 완료했다는 최종 보고가 아니다.

## 연결한 내용
- 스커미시 카탈로그에 비열거 항모 함급을 시험용으로 노출한다. H 무장을 가진 아군 함선이 있으면 해당 스커미시만 rules 3으로 생성한다. 일반 스커미시는 BATTLE_RULES=2를 유지한다.
- 항모 관제 컴퓨터를 스커미시 컴퓨터 목록에 추가한다.
- CraftPool의 OUT 기체 위치·속도·역할을 인스턴스 행렬에 읽기 전용 반영하는 CraftMeshes: 역할별 3 배치, 동적 증원 처리, 친·적 인스턴스 색상.
- 전투 HUD 선택 부대 상태에 항공 기체/정원, 예비기, 관제 수와 CAP 수를 간결하게 추가한다.
- 시뮬레이션의 실제 기관포 명중 중 1/6만 시각적 craftShot 이벤트로 표시한다. 전투 RNG 사용·피해 변경은 없다.
- 항모 임시 갑판 실루엣을 추가한다.
- 브라우저에서 비행체 행렬 갱신 시간을 관측할 수 있도록 BattleView.craftUpdateMs를 제공한다.

## 엄격히 유지할 내용
- 여명급 HullDef.preview: 변경 없음.
- 월드 구매·건조·설계도·상점 게이트: 변경 없음.
- BATTLE_RULES 기본값: 2 유지.
- 운영 배포·마이그레이션: 하지 않음.

## 실행 환경상 미검증
- 이 연결에서는 저장소 전체 로컬 체크아웃과 npm/Chromium 실행 환경을 확보하지 못했다. 타입 검사·빌드·테스트·실제 브라우저 측정/캡처를 **실행하지 못했다**.
- tests/p16-client.test.ts는 작성만 했고 실행하지 않았다. 특히 기존 5개 실패와 새 실패의 구분은 이후 실행으로 확인해야 한다.
- 200/400/800기 브라우저 CPU 프레임·GPU 프레임·렌더 비용을 측정하고 기록해야 한다. CraftMeshes 자체의 CPU 측정값만으로 GPU 성능을 입증할 수 없다.
- 실험실 규칙 선택 UI와 스커미시 피팅/관전/리플레이, 실제 월드 사본의 격침 항모 잔해 경로도 아직 브라우저·통합 검증 전이다.
- 시험과 브라우저 검증 후 문제가 있으면 P16.4의 최종 완료로 확정하지 말 것.

## 남은 조치
1. npx tsc --noEmit -p . / npm run content:check / npm run build.
2. npx vitest run tests/p16-client.test.ts tests/p16-craft.test.ts tests/p16-content.test.ts tests/p16-carrier-ops.test.ts.
3. P11 및 P15 전투 다이제스트 보존, 함재기 없는 rules 3 동일성 비교.
4. 브라우저 실험실과 스커미시 UI·피팅·전투·관전·재생 통합 확인.
5. 200/400/800 기체 실제 공중 전투를 각각 반복 측정하고 CPU/렌더/GPU 지표와 스크린샷 보관.
6. 시험용 월드 사본에서 여명급 격침 → 잔해 장비 보존 확인.
7. 기존 5개 실패와 새 회귀 구분, 모든 관련 실패 해소 또는 보고.
8. airValue()의 하이브리드 함급 조기 제외 문제는 P16.5 전 해결.
