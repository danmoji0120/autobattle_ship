# P16.7 — 수리선·전투 수리함 설계 및 기존 코드 영향 분석

상태: **설계·분석 단계 (구현 전, 승인 대기)**. 기준 커밋: `9962d55` (P16.6 항모 통합 검증 완료 시점).

## 0. 전제와 범위

- 탄약·연료·보급품 **소모 시스템을 새로 도입하지 않는다.** 보급선·탄약 수송·연료 보급·함대 물류망은 범위 밖(별도 승인 전까지 금지).
- 새로운 자원 종류를 만들지 않는다. 비용은 기존 크레딧·시간·(선택) 기존 품목(alloy·machinery)으로만 표현한다.
- 수리 능력은 **특정 함선 ID에 하드코딩하지 않는다.** H 슬롯(P16)·항공 장비 베이와 같은 원칙으로 "슬롯/장비/모듈"이 능력을 결정한다.
- 기본 규칙 2(`BATTLE_RULES`)와 개발 플래그 기반 항모 공개 정책(`DEV_CARRIER_RELEASE`)은 변경하지 않는다.
- 초기 목표: 비전투 수리선 1종, 전투 수리함 1종, 최소 장비 세트. 대규모 확장은 P17.

## 2. 정거장 수리 vs 함선(현장) 수리 — 역할 구분

| 구분 | 정거장 수리 (기존) | 비전투 수리선 (신규) | 전투 수리함 (신규) |
|---|---|---|---|
| 장소 | 도킹 필수 | 현장(우주 공간), 표적 근처 | 전투 중, 사거리 내 |
| 속도 | **즉시** hp=1 | 시간 소요(장비 처리량, 선체점/h) | 매우 제한적(응급) |
| 회복 상한 | 100% | 기본 100%, 단 정거장보다 느림 (선택: 상한 85%, 결정 D3) | 전투당 표적별 예산(응급분)만 |
| 비용 | 크레딧 `0.3·worth·손상` | 크레딧(정거장 대비 할인 없음~소폭) + **시간** + 수리선 운용비 | 추가 비용 없음(장비·운용비에 포함), 전투 후 잔여 손상은 정상 수리 필요 |
| 가치 | 확실·빠름 | **이동 시간 절약**: 원정·채굴·인양 현장에서 귀항 없이 복구, 정거장 없는 성계 | 전투 지속력, 치명 손상 단축 |

핵심: 수리선은 "정거장보다 싸고 빠른 수리"가 아니라 "**정거장까지 가지 않아도 되는 수리**"다. 정거장 수리를 대체하면 정거장 수리 모듈·AUTO-P1의 의미가 사라지므로 속도는 항상 정거장보다 느리게, 단가는 같거나 약간 낮게 둔다.

## 3. 비전투 수리선 설계 (A)

### 3.1 장비
- **산업 작업 종류 추가**: `IndWork`에 `'repair'` 추가, 장비 `ind_rep_s/m/l` (S/M/L, XL은 P17). `IndSpec.rate` = 시간당 수리 선체점.
- 산업 베이를 가진 모든 선체가 장착 가능 → constructor·hauler·salvager를 수리선으로 개조(리핏) 가능. 별도 선체 ID 하드코딩 없음.
- 처리량: `gearEcon`에 `rep` 항 추가(장비 rate × 선체 `ops.bonus` × 변형 보정). 표적이 받는 실제 회복률(hp 비율/h) = 처리량 / `repairPoints` 단위의 표적 크기 가중(`DOCK_WEIGHT[berth]`) → **큰 함일수록 느림**(요구사항 "표적 크기" 반영, 기존 정비 용량 단위 재사용).
- 생산·청사진·시장·인양: 기존 산업 장비 경로 그대로(`machine_shop` 레시피, `IND_MARKETS` 행 추가, 인양 드롭 테이블은 장비 일반 경로).

### 3.2 작업(Op)
- `repair`(단일 표적, `recover` 모델): 표적 함으로 이동 → 작업 거리(예: 표적 반경 + 일정 거리) 내 정지 → 틱마다 회복 → 완료 또는 중단.
- `tender`(함대 동행, `salvzone`/`escort` 모델, 연속 작업): 지정 함대를 따라다니며 우선순위대로 손상 함 수리.
- `auto`: AUTO-P1 `RepairPolicy` 확장 — 정거장 수리 대신/전에 근처 자사 수리선을 호출하는 옵션(`useTender`). 플레이어는 표적·우선순위를 수동 지정 가능(override).
- 표적 조건: 같은 회사(또는 동맹 측), 전투 중 아님(`engagement` 없음), 도킹 중 아님(도킹 중이면 정거장 수리 경로).
- 위험 시 중단·후퇴: `salvzone`의 적 접근 판정·`salvRisk` 재사용. 전투 개시 시 작업 중단, 수리선은 전투에 참여하지 않고 이탈 우선(비전투함).
- 동시 작업: 표적당 수리선 수 상한(예: 3) + 체감(1.0 / 0.6 / 0.3). 상한 초과분은 대기 또는 다른 표적.

### 3.3 무엇을 복구하는가
- 월드에 저장되는 손상은 `hp`(선체)와 `wear`뿐. 치명 손상(엔진·함교·무장)은 전투 종료 시 사라지므로 **월드 측에는 복구할 "구획"이 없다.**
- 선택지(결정 D2):
  - (a) **hp만 복구**(권장, 최소 변경): 엔진·함교 손상은 이미 hp의 월드 영향(순항속도 ×(0.6+0.4hp) 등)으로 간접 표현됨.
  - (b) 전투 후 잔류 손상 필드(`WShip.dmg{engine,bridge,weapons}`) 신규 도입 → 수리선이 구획별 복구. 저장 스키마·전투 시작 상태·경량 판정·UI 전반 변경 필요 → **P17 이후 권장.**
- `wear` 제거는 정비(정거장)의 역할로 남긴다(수리선이 마모까지 제거하면 정거장 정비의 의미 상실). 선택적으로 소폭(예: 정비 대비 25%) 허용 가능 — 결정 D3.

### 3.4 비용
- 크레딧: 정거장 공식과 동일한 `repairQuote` 기반, 계수 `0.3 → 0.27~0.3`(결정 D3). 회복량에 비례해 틱마다 정산(즉시 일괄 아님).
- 선택: 기존 품목(alloy·machinery)을 회복 선체점당 소량 소모(수리선 회사 창고에서, 없으면 크레딧 대체). 새 자원 아님, upkeep 소모품 경로(`shipRate` supplies와 같은 창고/구매 처리) 재사용. — 결정 D4.
- 수리선 자체: 기존 유지비(`hullUpkeep`)·장비 유지비만. 별도 연료·보급 소모 없음.

## 4. 전투 수리함 설계 (B)

### 4.1 기존 경로 재사용 판단
- 전투 중 회복의 선례는 B-1 응급수리(`ofx.regen`, 4초 무피격 조건, 전투당 상한 `ofHeal`)가 유일하며, **함 자신만** 대상으로 한다. 전투 수리함은 이 규칙(무피격 조건·전투당 상한·dying 불가)을 **타 함 대상으로 확장**하는 형태가 가장 일관적이다.
- 치명 손상은 자가 해제 타이머이므로, 전투 수리는 "타이머 단축"(가속 해제)으로 표현한다. 지휘관 `dc`가 이미 타이머 길이를 줄이는 방식이라 개념이 일치.

### 4.2 장착 방식 선택지 (결정 D1)

| | (a) 무장형: `WeaponKind 'repair'` 하드포인트 장비 | (b) 모듈형: 전용 내부 베이 `'support'` + `RepairFx` | (c) 혼합: 하드포인트 장비 + 컴퓨터 |
|---|---|---|---|
| 표적·사거리·사각 | Mount의 `targetId`·사거리·arc·재장전 그대로 재사용 | 신규 구현(구형 사거리) | (a)와 동일 |
| 작업 주기·처리량·동시 표적 | 재장전=주기, 마운트 수=동시 표적 | 모듈 파라미터 | (a) |
| 피격 시 무력화 | 기존 `disabled`(무장 치명 손상)로 자연 처리 | 별도 처리 필요 | (a) |

| 무장과 트레이드오프 | **하드포인트를 차지**(화력 대신 수리) → 자연스러운 비용 | 내부 베이 차지(센서·장갑 등 대신) | |

**권장: (a) 무장형 + 하드포인트 유형 `'support'`(S 슬롯)** — 표적·사거리·주기·무력화를 모두 기존 마운트 경로로 재사용하고, "무장을 빼고 수리를 단다"는 비용이 명확하다. 단, 하드포인트 유형 추가는 선체 데이터에 `'support'` 하드포인트를 가진 선체가 필요하다(4.5).

### 4.3 전투 수리 규칙(제안)
1. 대상: `state==='alive'` 아군만. **dying·dead·escaped·inbound 불가** (침몰 직전 구조 반복 방지는 4.4 참조).
2. 응급 수리 한도: 표적당 전투 전체 회복 상한 = `maxHp × 0.15`(결정 D5 범위 0.10~0.20). 지휘관 응급수리 `ofHeal`과 **같은 예산을 공유**(합산 상한 `maxHp × 0.25` 정도로 별도 상한).
3. 무피격 조건: 표적이 최근 N초(예: 2~4초) 피격되지 않았을 때만 선체 회복(실드 재생·B-1과 동일 철학). 집중 포화 중인 함은 회복 불가 → 화력이 수리를 이김.
4. 치명 손상: 사이클당 화재·엔진·함교 타이머를 일정 비율(예: 남은 시간 30%) 또는 고정초 단축. 완전 제거 아님. 무장 `disabled`도 단축 대상. **탄약고 유폭·침몰(dying)은 수리 불가.**
5. 다중 수리: 같은 표적에 대한 수리량 체감(1.0 / 0.5 / 0.25), 표적당 동시 수리함 상한 3.
6. 수리함 간 상호 수리: 수리 장비 보유 함이 표적이면 효율 0.25배(또는 0, 결정 D5) — 무한 상호 회복 루프 차단. 자기 자신 수리 불가.
7. 작업 주기: 마운트 재장전(예: 3~5초)마다 1회 처리, 처리량은 장비 등급·크기. 사거리 짧음(예: 1.5~2.5 km급, 기존 PD 사거리대) → **수리함은 전열 근처에 있어야 하므로 피격 위험을 감수.**

### 4.4 밸런스 문제별 대책 (§3 요구)

| 문제 | 대책 |
|---|---|
| 1. 수리가 적 화력을 상회해 전투가 끝나지 않음 | 표적별 **전투당 응급 예산**(총량 상한) + 무피격 조건 + 처리량 상한. 예산이 유한하므로 전투 총 회복량 ≤ Σ 표적 maxHp×0.15. TIME_LIMIT/교착 판정은 그대로 동작 |
| 2. 여러 수리함이 한 표적에 집중 | 표적당 동시 수리 상한 + 체감, 예산은 표적 기준이라 수리함 수와 무관하게 총량 동일 |
| 3. 수리함끼리 무한 상호 수리 | 수리 장비 보유 표적 효율 감소(0.25 또는 0) + 동일 예산 상한 |
| 4. 치명 손상·화재 무의미화 | 타이머 **단축**만(제거 아님), 탄약고 유폭·침몰 불가, 무피격 조건 |
| 5. 침몰 직전 함 반복 구조 | dying 불가(hp≤0은 즉시 확정), 저HP 함 우선순위에 상한(예: hp<15%는 우선순위 가산 없음) + 예산 소진 후 불가 |
| 6. AI가 수리함 무시/표적 보호 실패 | 표적 점수에 **지원 위협 가중치**(수리 장비 보유 함 +α, `value`에 수리 장비 가치 반영) 추가 → 적이 수리함을 노림. 아군 지원 컴퓨터(`CpuArch 'support'`)는 표적 그룹 후방 유지·이격 거리 관리. 지휘관 그룹 배치: 수리함은 `escort` 역할 그룹으로 편성 권장 |

전투 수리가 정비보다 제한적이어야 한다는 요구: **응급(전투 중, 예산 15%, 치명 손상 단축) vs 정식(전투 후 현장 수리선/정거장, 100%)**의 2단 구조로 해결.

### 4.5 함선·장비 최소 세트 (초기)
- 전투 수리 장비: `rep_arm_s`(S, 'support' 하드포인트, 사거리 짧음, 주기 4초), 필요 시 `rep_arm_m`. — 생산 `machine_shop` 또는 `weapons_factory`, 레시피는 machinery/precision/electronics(기존 품목).

- 선체(결정 D6):
  - (i) 신규 전투 수리함 선체 1종(예: 구축함급 변형, 'support' S 하드포인트 2~3 + 컴퓨터 베이 + 소형 무장) — 항모처럼 `preview` 플래그로 공개 제어.
  - (ii) 기존 선체(예: destroyer_picket) 변형(variant)에 'support' 하드포인트 추가.
  - 권장: (i) 신규 선체 1종 + `preview`, 기존 선체 데이터 무변경(기존 함대 결과 불변 보장이 쉬움).

## 5. 경제·자동화

- 신규 물류망·자원 없음. 비용 = 크레딧 + 시간 + 기존 유지비(+ 선택적 기존 품목 소모, D4).
- 수리선 유지비: `hullUpkeep` 그대로. 수리 장비의 `supply` 필드(장비별 보급품)는 사용하지 않거나 0 — **"보급품 소모 신규 도입 금지"에 저촉될 여지가 있으므로 수리 장비에는 supply를 두지 않는 것을 권장.**
- 자동화: `RepairPolicy` 확장 필드(`tender: boolean`, 우선순위 `'hpLow'|'value'|'flagship'`)와 플레이어 지정 표적(override). 기존 `perHour`·`maxPerRepair` 한도를 수리선 정산에도 적용.
- 미세관리 최소화: 함대에 수리선을 편성하면 `tender`가 자동으로 함대 손상 함을 처리, 전투 후 `auto`가 잔여 손상 처리.

| 선택지 | 내용 | 장점 | 위험 |
|---|---|---|---|
| (a) **규칙 4 신설** (`rules >= 4`에서만 수리 동작) | `BATTLE_RULES`는 그대로(2, 플래그 시 3). 수리는 별도 개발 플래그(`DEV_REPAIR_RELEASE`) 시 4 | 항모(3)와 독립 공개 가능, 기존 규칙 0–3 리플레이 다이제스트 불변이 구조적으로 보장 | 규칙 4가 3을 포함하므로 "항모 미공개 + 수리 공개" 조합 불가 → 규칙을 비트 플래그처럼 쓰거나 공개 순서 고정 필요 |

## 8. 경량 판정(quickResolve)

- 현재 `lightValue`·`combatRating.ts strengthParts`는 수리를 모른다.
- 선택지: (a) 수리 장비 보유 함대에 전력 보정 `×(1 + k·수리처리량/함대maxHp)`, 상한 +10%(항모 `airValueMul`과 같은 방식); (b) 미반영 + 한계로 문서화.
- 권장: 초기엔 (a) 소폭 보정(상한 +5~10%), 보정 계수는 구현 단계 시뮬레이션으로 보정. 경량 판정 결과에 수리선(비전투) 존재는 반영하지 않음(전투 불참).

## 9. 위험 요소

1. **교착 장기화**: 예산 상한이 느슨하면 TIME_LIMIT 도달·교착 판정 증가 → 구현 단계 교전 시간 분포 측정 필요.
2. **후퇴 지연**: 수리로 groupHpFrac 상승 → 후퇴 늦춰 손실 증가 가능.
3. **AI 표적 가중 부작용**: 수리함 우선 사격이 과하면 전열함 생존이 비정상적으로 상승.
4. **정거장 수리 잠식**: 현장 수리가 저렴·빠르면 정거장 수리 모듈·AUTO-P1 무의미화.
5. **규칙 버전 결합**: 규칙 4가 항모 규칙 3을 포함 → 공개 순서 제약.
6. **월드 구획 손상 부재**: 요구서의 "손상 구획 복구"는 현재 데이터 모델에 대응 필드가 없어 hp 복구로 대체(D2).
7. **보급품 경계**: 기존 품목 소모(D4)가 "보급품 소모 신규 도입"으로 해석될 위험.
8. **AI 수리선 운용**: NPC가 수리선을 쓰지 않으면 플레이어만 이득 → 초기엔 플레이어 전용, NPC는 기존 본거지 회복 유지.
9. **성능**: 수리 표적 탐색은 아군 함 수 × 수리 마운트 수, 재장전 주기마다만 실행하면 무시 가능 수준으로 예상(미측정).
