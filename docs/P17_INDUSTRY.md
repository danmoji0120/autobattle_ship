# P17 — 산업 패시브화·전문화

기준: P16.7 `5ec5f5f`. 단계별 구현 결과, 핵심 검증, 미검증 항목만 기록한다.

## P17.0 산업 패시브화

### 기존 기능과 부족분

| 산업 | 이미 있던 자동화 | 부족분 → P17.0 조치 |
|---|---|---|
| 채광·수송·가공 | 채광 작업, 채광 수송 판매 왕복(AUTO-P1), 물류 작업, 생산 계획 | 없음 (유지) |
| 인양 | 현장 자동 인양(3 km·10분), 구역 인양 `salvzone`(지정한 지점·반경 안의 잔해를 점수로 선택하고, 하역·판매 왕복 연결) | 지점을 지정해야 했고, 일이 없으면 우주에 떠서 대기 → **자동 인양 사업** 추가 |
| 수리 | P16.7 수동 현장 수리(편대 배속), `repairzone`, 자동 정거장 수리(AUTO-P1) | 자사 함선용으로는 충분 → 변경 없음 (타사·NPC 의뢰는 P17.2) |

### 자동 인양 사업 (`salvzone` + `biz:true`)

새 작업 종류를 만들지 않고 구역 인양을 확장했다. 업무 등록, 이름, 중지·귀환 UI를 그대로 쓴다.

- **탐색 범위**: 지정 지점이 있는 성계와 그 주변 `SALV.bizJumps`(1) 점프 이내의 잔해(전장 잔해·자연 잔해·투하 화물).
- **대상 선택**: 기존 점수식 `가치 ÷ (이동 + 작업 시간 + 30 s)`.
  - 예상 회수 가치가 `bizMin`(400 cr) 미만이면 가지 않는다.
  - 적대 함대가 가까운 곳은 `bizRiskIgnore`(15분) 동안 제외한다. 일반 구역 인양은 기존대로 점수에 0.2를 곱한다.
- **회수 후**: 기존 하역(안전 하역지 판정 포함)과 판매 왕복 경로를 그대로 쓴다.
- **일이 없을 때**: 지정 지점에서 가장 가까운 정거장에 정박해 대기한다. 작업 지시는 유지되므로 새 잔해가 생기면 스스로 출항한다.
- **명령 검증**: 반경 검사를 생략하고, 인양 장비 검사는 그대로 한다.
- **UI**: 편대 인양 패널에 "자동 인양 사업 시작" 버튼(한 번 지정). 상태 표시는 "자동 인양 사업: …".

**설계 판단**: 유휴 인양선이 지시 없이 이 모드를 스스로 시작하지는 않는다. 플레이어가 편대마다 한 번 켜는 방식으로 했다. 기존 "현장 자동 인양" 설정과 같은 철학으로, 예기치 않은 장거리 이동을 막기 위해서다.

## P17.1 인양 퀄리티

인양 **속도**(기존 `salvageRate`)와 별개로 **품질**을 둔다. 품질은 잔해에서 꺼낸 단위 중 온전히 회수되는 몫을 정한다. 꺼낸 양을 넘는 회수는 없고, 잔해에 없던 장비가 품질로 생기지 않는다.

### 품질 계산 (`salvageQuality`, 0~1)

`장비 정밀도 + 연구 + 장교 − 잔해 상태`

| 요소 | 값 |
|---|---|
| 장비 정밀도 `IndSpec.prec` | S 0.35 · M 0.45 · L 0.5 · XL 0.55 (여러 장비는 효율 가중 평균, 장비 없는 회수는 0.3). 속도(1→4.2)보다 훨씬 완만하게 오른다 |
| 연구 `salvage_ops` | +0.08 |
| 장교 | 인양 속도 효과 × 0.25(최대 +0.125) + 인양 숙련 단계 × 0.04(최대 +0.2) |
| 잔해 상태 `siteDifficulty` | 자연 잔해 소형 0 · 중형 0.08 · 대형 0.15, 전장 잔해 0.1, 수명 경과에 따라 최대 +0.08 |

### 결과물

| 화물 종류 | 회수 결과 |
|---|---|
| 선체(합금·금속 등) | 꺼낸 양 × (0.7 + 0.3q) |
| 화물 | 꺼낸 양 × (0.9 + 0.1q) |
| 장비 | 온전 확률 0.4 + 0.6q (+ 장교 장비 특화 × 0.2). 파손품은 장비 가치 30%만큼의 무기 부품(화물칸 한도 안) |
| 설계도 조각·투하 화물·자사 화물 | 품질 영향 없음 (전량) |

- 결정적 계산이다(난수 없음). 소수 몫은 함선에 이월한다(`WShip.salvQ`).
- 회수되지 못한 단위는 `consume/salvage_loss`로 기록한다. 잔해 장부(`taken + 잔여 + 소멸 = 생성량`)와 물자 흐름 장부가 맞는다. `w.taken`은 잔해에서 꺼낸 양(품질 적용 전)이다.
- 장교 경험치는 실제 회수 가치 기준이다.
- **게이트**: `st.salvQV`. 새 산업 월드(`enableIndustrial`)에서 켜진다. 기존 저장본은 명시적 `migrateSalvageQuality`로만 켜지고, 그 전에는 종전처럼 전량 회수한다.
- **UI**: 피팅 화면의 인양 장비에 "정밀도 N%", 인양 작업 상태에 "인양 품질 N%".

### 검증

- 타입 검사, `content:check`(0 오류) 통과.
- `tests/p17-industry.test.ts` 9건 통과(P17.1 5건).
  - 정밀도 순서와 장비 없음 → 0.
  - 잔해 크기·경과 시간에 따른 난이도.
  - 꺼낸 양 초과 회수 없음, 잔해에 없던 품목 없음.
  - 같은 잔해에서 연구가 있으면 단위당 회수가 더 많음.
  - `salvQV` 없는 월드는 전량 회수, 마이그레이션 멱등.
- `a32b-salvage` 17건 통과. 처음에는 잔해 장부 보존 검사 2건(S5/S6, S7/S8)이 실패했다. 손실분이 장부에서 빠진 실제 결함이었다. 손실을 `consume/salvage_loss`로 기록하도록 고쳤다(기대값은 바꾸지 않음).
- `p131-salvage`: A05·C01만 실패한다. P17.0과 같은 기준선 실패다.
- 짧은 시뮬레이션 `scripts/p17/quality-sim.ts`(시드 31, 같은 대형 자연 잔해, 2시간):

  | 조건 | 꺼냄 | 회수 | 손실 | 회수 가치 |
  |---|---|---|---|---|
  | 품질 규칙 없음(종전) | 350 | 350 | 0 | 17,986 (100%) |
  | 기본 S 장비 | 350 | 265 | 85 | 12,794 (71%) |
  | S 장비 + `salvage_ops` | 350 | 274 | 76 | 13,168 (73%) |

### 미검증·보류

- 장교·대형 장비의 효과는 계산식 단위로만 확인했다. 시뮬레이션에서는 연구만 비교했다.
- **수치 조정 필요(P17.4)**: 새 월드의 기본 인양선은 종전보다 회수 가치가 약 25~30% 줄어든다(대형 잔해 기준). 첫 사업 수익성에 미치는 영향은 P17.4에서 비교한다.
- 연구 단독 효과(+2%p)는 작다. 장비 정밀도와 장교가 주된 성장 경로다.
- 브라우저 UI 확인 안 함.
