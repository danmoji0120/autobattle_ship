# P9.5 건설·원격 구매 물류

기준 `codex/p9-world-expansion`의 `07b52c90b8ac2aa6fe66275805c0fd069068dfed`. 작업은 `codex/p95-construction-logistics`의 격리된 개발·테스트 월드에서 수행한다. 운영 서버·운영 DB·기존 운영 월드에는 적용하지 않는다.

## 설계와 플레이 흐름

성장 월드의 정거장 설립 명령은 부족한 합금을 시장에서 자동 구매하지 않는다. 공작선이 실제로 보유한 합금과, 명령을 받을 때 공작선이 정박한 정거장의 **자사 자유 재고**만 화물칸 용량 이내로 싣는다. 구매하지 않은 물품이나 다른 장소의 재고를 공작선에 더하지 않는다. 함선이 부지에 도착하면 기존의 코어 건설 계획이 만들어지고, 자재가 부족하면 공작선은 현장에서 대기한다.

설립비 8,000cr는 사용자가 확인한 정책에 따라 명령 시 선납한다. 출발 중 명령 변경·위임·편대 해체 또는 마지막 공작선 상실로 착공이 불가능해지면 선납금 전액을 한 번만 환급한다. 목표 변경에는 기존 선납금을 재사용한다. 일시적인 교전·피난은 명령 취소가 아니므로 선납을 유지한다. 현장 도착 시 부지의 유효성을 다시 검사하고, 적법한 현장에서만 선납을 코어 계획의 결제액으로 옮긴다. 공작선이 파괴되면 선납금과 별개로 화물은 기존 전투 손실 규칙을 따른다.

시장 구매는 기존 서버 `buy` 거래를 사용한다. 가격, 시장 재고와 예산 규칙은 바꾸지 않는다. 구매품은 해당 시장의 구매 회사 보관함 또는 그 시장에 실제 정박한 자사 함선의 화물칸에 들어간다. 플레이어는 보관함에서 **건설 공급** 노선을 만들거나 화물을 실은 편대의 **현장 반입** 명령으로 가져온다. 물품을 시장에 산 사실과 현장에 도착한 사실은 별개다.

성장 월드의 새 클라이언트는 구매마다 회사별 순번과 고유 요청 ID를 보낸다. 서버는 회사마다 마지막으로 체결한 요청과 내용을 저장해 동일 요청의 재전송·재시작 후 재시도에서 결제와 인도를 반복하지 않는다. 더 오래된 순번 또는 같은 순번의 다른 요청은 거부하며 시장과 보관함 확인을 안내한다. 응답이 오지 않으면 클라이언트는 해당 ID를 세션 저장소에 남겨 같은 구매를 확인할 때 재사용한다. 별도로 의도한 후속 구매는 새 순번을 받는다. 한 회사의 여러 브라우저가 같은 순번으로 서로 다른 구매를 보낼 경우 뒤의 요청은 충돌을 알려 주고 새 상태에서 다시 선택하도록 한다.

관리형 건설 공급은 기존 P2 노선·명세·게이트 이동·재시도·일시정지·저장 경로를 확장한 모드다. 출발지는 이용 가능한 정거장, 목적지는 자사 정거장 또는 미완공 현장이다. 출발지의 자유 재고만 싣고, 현장의 실제 계획 부족량에서 이미 현장에 있는 재고와 다른 자사 노선의 운송 중 물량을 뺀 만큼만 추가로 싣는다. 각 수송선은 실제 항로를 거쳐 현장에 접근한 뒤 필요한 자재만 외부 반입한다. 외부 반입은 건설 자재에 한정되며 일반 정박·거래 권한이나 완공 창고를 부여하지 않는다.

개발용 성장 봇 `worldbot`·`pmcbot`도 현지 시장에서 합금을 실제로 구매하고 공작선에 실을 재고가 준비된 뒤 설립 명령을 내리도록 변경했다. 재고·자금이 부족하면 기존 공작선을 재사용하며 기다린다.

현장 용량은 기존 `constructionRoom`과 창고 용량을 함께 적용한다. 계획이 정지·취소되거나 다른 화물이 먼저 도착해 더 받을 수 없으면 남은 화물은 함선에 유지하고 이유를 표시하며 재시도한다. 목적지 소실·소유권 변경은 노선을 일시정지하고 화물과 명세를 보존한다. 수동 명령·노선 취소 시에도 화물은 함선에 남는다. 기초 코어는 기존대로 취소할 수 없고 일시정지·재개만 가능하다. 다른 시설 계획 취소는 기존 규칙대로 미사용 예약 자재를 돌려주고 미진행 공정의 선납금을 환급하며, 이미 투입한 자재는 회수하지 않는다.

## UI

자사 정거장의 건설 화면은 필요량, 실제 투입량, 현장 예약·가용량, 부족량, 노선 화물을 분리한다. 노선 화물은 실제 확보량에 합산하지 않는다. 출발지·목적지·함선과 노선의 일시정지 여부를 표시하며, 시장 화면과 현장 목적지가 미리 선택된 건설 공급 편집기로 연결한다. 모바일에서는 자재 항목을 가로 스크롤 없이 읽을 수 있도록 재배열한다. 화물선도 건설 현장을 직접 선택해 필요한 물품을 반입할 수 있다.

## 저장·권한·회계

선납금은 회사별 선택적 `foundingEscrow`에 편대 ID별로 보관한다. 새 설립 명령의 서버 생성 표식과 함께 JSON 월드에 저장되며, 서버는 명령이 유효하게 남아 있는지 검증해 환급한다. 과거 성장 저장에서 기록된 설립 명령은 이전 코드가 명령 시 선납했다는 사실을 근거로 재결제하지 않고 선납 기록으로 복원한다. 이전 버전에서 위임 등으로 이미 중단했으나 편대에 남은 설립 명령도 이 대상이다. 이 경우 새 중단 환급 정책이 적용되어 잔액이 8,000cr 한 번 늘 수 있다. 과거 c0의 설립·경제·시뮬레이션 경로는 사용하지 않는다.

구매 확인 기록은 회사당 마지막 거래 한 건만 저장하므로 거래 횟수에 비례해 늘지 않는다. 이전 클라이언트와의 호환을 위해 요청 ID 없는 구형 `buy` 명령도 허용하지만 그 명령의 재전송은 식별할 수 없다. 새 클라이언트에서도 브라우저 세션 저장소가 완전히 차단되면 같은 탭의 메모리에서만 미확인 ID를 유지할 수 있으므로, 탭 재시작 후의 미확인 구매는 보관함과 시장을 먼저 확인해야 한다. 과거 거래의 서버 영수증이나 응답 유실 이전 이력은 만들어 내지 않는다.

시장 거래는 기존처럼 서버에서 즉시 체결되며, 체결 후 구매 취소·환불 계약은 제공하지 않는다. 연결이 끊긴 동안 전송 대기 중인 명령은 재연결 시 처리될 수 있으므로 응답이 불명확하면 같은 요청으로 확인하거나 보관함을 확인해야 한다. 운송 노선 취소는 구매품을 환불하는 동작이 아니며 남은 물품은 해당 창고나 함선에 유지된다.

자재는 기존 회사별 창고, 함선 화물, 건설 예약·투입과 노선 명세에만 보관한다. 명세는 실제 화물의 추적 정보이며 별도의 자산이 아니다. 타 회사의 창고·화물·선납 및 노선은 스냅샷에서 가려지고, 명령할 때 서버에서 소유권을 재검증한다. 구매 및 환급은 기존의 동기 거래 경계와 관측을 사용한다. 선납금은 기존 건설 선납과 같이 자유 현금에서 빠지며 분석용 자산 평가에는 남는다. 기존 게임의 성장 판정용 `netWorth` 계산은 변경하지 않는다.

신규 NPC 배송 회사와 자동 시장 구매는 없다. 기존 물류센터가 필요한 생산 공급 모드의 규칙도 그대로다. 건설 공급은 공작선이 최초 변경 기지를 세우기 전에는 물류센터가 없을 수 있으므로 별도의 센터 없이 자사 현장으로 외부 반입한다.

**롤백 제약:** 이전 바이너리는 새 선납 기록이나 건설 공급 모드를 이해하지 못한다. 저장을 이전 서버 버전에서 실행한 뒤 다시 올리는 것은 안전한 롤백 절차가 아니다. 향후 적용이 승인되더라도 완전한 백업·서버 중지·호환 복원 절차가 필요하다. 이번 작업에서 운영 데이터를 이행하거나 배포하지 않았다.
