## 전환 전 문제와 수정

P9.7의 `legacyRecipe`는 진행 중인 배치뿐 아니라 **같은 주문의 모든 후속 배치**를 종전 입력으로 시작했다. 특히 재고 목표 주문은 취소할 때까지 무한히 희귀 소재를 우회할 수 있었다. 수정 전 새 회귀 두 건에서 실제로 재현했다.

기존 P9.7 테스트 중 두 번째 배치의 구형 재료 생산을 의도적으로 기대하던 검사는 이번에 요청된 정책에 맞춰 수정했다. 첫 배치 완성, 기존 재료 보존, 새 희귀 소재 부족·자동 공급 및 보충 후 완성까지 검증하며, 반복 주문과 개발판 저장 검사를 별도로 추가했다. 시간 초과를 피하기 위해 테스트 제한·조건을 완화하거나 삭제하지 않았다.

배치는 시작 시 입력을 창고에서 이미 차감한다. P9.7에서 바뀐 것은 네 장비 레시피의 **입력뿐이며 산출물·수량은 동일**하다. 따라서 기존 `jobs`와 `orders`, 이미 차감된 재료, 완료 수와 재고 목표를 보존하고 신규 배치만 `recipeFor(world, id)`를 따른다. 과거 P9.7 개발 저장의 `legacyRecipe`도 지역 활성 저장을 읽을 때 제거한다. 진행 중 작업은 원래 산출물을 한 번 내고, 다음 작업은 새 입력이 없으면 대기한다. 저장·복원과 반복 활성화에서 동일하며, 지역 미활성 P9와 c0에는 적용되지 않는다. 함선의 기존 예약·진행 계획은 원래의 `regionalMaterials` 스냅샷을 그대로 사용한다.

서버 생산·화면의 주문 상세·`stationNeeds`와 `supplyBatch`가 동일한 새 레시피를 사용한다. 실제 구형 진행 작업, 개발판 플래그가 있는 반복 주문, 추가 소재 없는 재시작 및 소비 후 생산을 검사했다. 격리 PostgreSQL 두 차례 서버 재시작에서도 투입 후 상태, 진행 작업과 목표를 확인했다. 이미 제조된 장비·함선은 수정하지 않는다.

화물 압축 연구는 관리형 물류에는 적용됐으나 채굴 작전의 채굴선·지원 수송선에는 적용되지 않았다. 수정 전 재현 후 지역 활성 월드에서만 기존 연구 배율을 적용했다. `cargo_compression` 단독일 때 명목 용량은 채굴선 140→175, 지원 수송선 450→562.5다. 실제 출발 기준·이동·하역은 별도이며 처리량이 25% 늘어난다는 뜻이 아니다. 지역 미활성 월드는 이전 동작을 유지한다. 연구 효과 자체의 수치를 새로 조정하지 않았다.

함선 목록·상세도 같은 지역 채굴 용량을 표시하고 연구 완료 시 갱신한다. 상세 화면에서 이를 채굴·운송 기준으로 구분한다. 공영 시장에서 선박 화물칸으로 직접 구매하는 별도 기존 한도는 변경하지 않았다.

## 원가·가치·가격

입력 원가는 해당 배치에서 **실제로 요구하는 품목 수량 × 품목별 참고 가치**다. 생산자가 지불한 현금이나 실제 매입 호가가 아니다. 아래 값은 cr 단위, 배치당이며 생산 시간·시설 비용은 재료 원가에 포함하지 않는다. 참고 가치는 가치 모델의 공임·단계 마진을 포함한다.

|---|---:|---:|---:|
| 레일 캐논 | 10,958.6 | 11,561.4 | 13,872.5 |
| 입자 창 | 10,995.6 | 15,991.0 | 18,976.1 |
| 반응장갑 | 3,183.0 | 4,344.6 | 5,125.6 |
| 고출력 반응로 | 5,293.3 | 6,611.8 | 7,619.5 |

특수 가공품은 배치당 투입 참고 원가 / 배치 산출 총 참고 가치가 고강도 합금 4,753 / 5,298, 공명 광학 소재 5,182 / 5,792.8, 안정화 동위원소 5,042.4 / 5,639.2, 특이 합금 13,103.2 / 14,552다. 희귀 원료의 참고 가치는 순서대로 100·150·130·220 cr/개다. 일반 원료의 실제 NPC 매입가는 기존 시장 재고·예산·세금에 따른다. 가치 모델의 원료 참고가와 NPC 실제 호가를 동일시하면 안 된다.

기준 새 월드에서는 위 네 희귀 원료, 네 가공품, 네 고급 장비 모두 NPC 시장 항목이 없다. 실제 매입 보장 가격은 0으로 보아야 하며 플레이어 매물은 구매자가 수락한 가격에서만 체결된다. 공영 피팅은 지역 대상 장비의 실제 NPC 시장 항목·재고·구매 가격과 자금을 확인하고 차감하는 기존 P9.7 정책을 유지한다. 희귀 자원이나 고급 장비를 NPC에 자동 생성하지 않았다. 일반 NPC 매입·매도, 예산, 정거장 재고 보충 및 공영 조선소 가격은 변경하지 않았다.

지역 월드의 창고·보류 전리품과 분석의 선박 화물·매물·착공 재료에는 같은 지역 참고 가치가 적용된다. 함선 자산 평가는 기존 선체 기준값에 드레드노트의 추가 지역 재료와 실제 피팅된 희귀 장비 가치를 반영하며, 장착 무기가 기본 프리셋을 대체한 경우 그 기본 무기 가치를 빼서 중복을 줄인다. 이는 자산·성장 이정표의 **참고 평가**이며 실제 판매가나 군사 효용은 아니다. NPC 선체 판매가·수리비·유지비 기준은 바꾸지 않았다.

드레드노트 표준 프리셋의 실제 등록 요구를 참고 가치로 평가하면 재료 677,000.4 + 등록 공임 90,000 + 조선소 비용 1,728,000 = 약 2,495,000.4 cr이다. 입자 창 프리셋은 같은 방식으로 약 2,508,336.9 cr이다. 선택한 피팅·거래 가격에 따라 달라지며, 참고 가치 추정이지 실제 현금 지출 합계가 아니다. 네 장비·네 가공품·함선·시장 조회 재현: `npx vite-node scripts/p971-valuation.ts`, 결과 `artifacts/p971/valuation.json`.

생산 화면은 배치 재료, 보유량과 부족량, 가능한 배치 수, 기존 참고 가치, 지역 반영 참고 가치와 예상 재료 원가를 구분한다. 조선 화면은 선택한 무장·모듈·지역 자재의 예상 재료 원가와 서버에서 실제 등록 시 요구하는 공임+조선소 비용을 표시한다. 매물 화면의 참고가는 사용자가 명시적으로 선택할 수 있는 정보다.

## 실현 거래가 포함된 위험 비교

`npx vite-node scripts/p971-risk.ts 5 1800`은 시드 97100~97104별 독립 월드에서 30분을 진행한다. 각 회사는 동일한 지급 시작 함대·100만 cr에 현장 시작 채굴선 한 척을 더 받는다. A는 안전 지역 케스트렐→아스트라, B는 검은 관문→드레이크아웃 무호위, C는 같은 노선과 초계함 1척, D는 구축함 1·초계함 2와 자동 물류선 1척을 추가하고 드레이크아웃→아스트라로 희귀 원광을 보낸다. D의 전투함은 채굴 편대 호위이며 수송선을 따라가지 않는다. 정상 NPC와 전투를 켰다.

한 시험 구매 회사는 지급받은 자금으로 도착한 특이 광석을 **220 cr/개**에 실제 플레이어 거래소에서 산다. 수량·창고·자금은 유한하다. 구매자가 체결하지 않은 물품·지급 자금·지급 원재료는 매출에 넣지 않는다. 일반 혼합 광물은 실제 NPC 시장에서 매각한다. 표의 매출은 세후 실제 수령액, 운영비는 시작 함대를 포함한 회사의 현금 비용, 교체비는 손실된 시험 함선의 게임 내 선체 기준 가격 추정이다. 전투 보상 등 별도 수입은 순이익에서 제외했고, 팔지 않은 재고의 추정 가치는 포함하지 않는다. 미결제·소모품 잔여나 새 선박의 실제 구매 가능성은 별도다. 기간 말에 교체를 수행한 것은 아니다.

## 다회사 및 저장 호환

한 회사의 실제 채굴→다중 게이트 운송→가공→장비 제작·피팅, 두 회사가 같은 유한 광상에서 동시에 채굴할 때 혼합 화물·광상 잔량과 저장 복원 보존, 네 회사의 서로 다른 산지 채굴을 검사했다. 별도 실제 거래 시험에서는 생산사가 원광을 채굴·운송·가공한 다음 합금 12개를 매물로 등록하고 비채굴 회사가 6,000 cr에 사서 실제 수송선으로 가져가 반응장갑을 제작했다. 매도자 세후 대금, 구매자 차감, 매물 제거·화물·잔여 8개와 구매자의 채굴 0을 검사했다. 시작 자금·일반 자재·시설·기술은 픽스처로 제공했다.

위는 물품 복제와 거래·운송 경로를 확인한 제한된 시험이다. 실제 서버의 장기간 동시 주문, 가격 발견, 충분한 거래 상대, 특정 회사가 재고 판매를 거부할 때의 영구 독점 해소는 입증하지 못했다. 재생 자체는 계속되지만 재고 소유자가 팔지 않으면 다른 회사의 희귀 장비 제작은 막힐 수 있다. NPC 자동 희귀 재고는 없으므로 이 유동성 위험은 남는다. P9.6.3.3의 비정상 종료 후 거래 영속성 후속 과제도 그대로다.

c0 5성계와 미활성 성장 22성계는 개발 기준 `b041dedc2da59d34492233f4eee07bd36778ff8d`과 같은 합성 두 회사·거래 명령으로 300초, 150초에 저장·복원하여 60초 간격 상태 해시가 모두 일치했다. 이 비교는 벽시간에 따른 NPC 예산 변동을 없애도록 시계를 고정했으며 합성 저장에 생산 주문은 넣지 않았다. 활성 기존 성장 월드, 이미 저장된 지역 월드, 구형 플래그 주문과 진행 중 배치는 별도 자동화 및 PostgreSQL에서 검사했다. 상세 `artifacts/p971/legacy-comparison.json`.

## 시간 초과 조사와 검증

P9.7의 두 전체 회귀에서 각각 3건, 1건이 시간 초과했으나 개별 재실행은 기준·변경 양쪽에서 통과했다. 이번에 같은 단일 워커와 기본 시간 제한으로 네 경로를 개발 기준 `b041ded` / 원래 P9.7 `8c8b2a6` / 이번 코드에서 따로 실행한 결과 모두 4/4 통과했고, 전체 소요는 33.27 / 37.45 / 33.62초였다. NPC 계약은 19.48 / 22.07 / 19.67초, 연구 선행 조건은 9.06 / 9.88 / 9.00초, 정거장 설립은 0.96 / 1.01 / 0.96초, 개발자 인증은 1.86 / 2.29 / 2.06초다. 각각 한 번의 표본이므로 이 차이만으로 성능 회귀를 단정하지 않는다. NPC 계약은 2,400 게임 초의 0.25초 전략 틱과 NPC 활동을 동기 실행하고, 연구 시험도 실제 연구 시간을 수천 틱으로 진행한다. 개발자 인증은 비동기 scrypt를 쓴다. 제한 시간은 늘리지 않았다.

네 실패 경로의 테스트 코드를 확인했을 때 각 게임 시험은 새 `WorldSim`을 만들고 인증 시험은 새 메모리 저장소와 명시적 가상 시각을 사용했다. 인증 시험의 다섯 동시 비밀번호 검사는 실제 scrypt 작업을 수행한다. 해당 파일들에서 공유 전역 타이머·폴링은 발견하지 못했지만 이 검사만으로 전체 스위트의 모든 격리 문제를 배제할 수는 없다.

이 실행 환경은 cgroup CPU 상한 2코어, 메모리 상한 8 GiB, 단일 Vitest 워커다. 여러 실험·브라우저를 함께 실행했을 때 CPU throttling이 관측됐다. 과거 실행 당시의 동시 부하 자료는 없어 이것이 과거 시간 초과의 원인이라고 단정할 수 없다. 현재 개별 기준 비교로는 P9.7의 뚜렷한 성능 회귀나 데드락을 재현하지 못했다. 방법별 수치와 추가 결과는 아래에 기록한다.
