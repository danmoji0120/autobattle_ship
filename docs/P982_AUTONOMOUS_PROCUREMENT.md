# P9.8.2 자율 자재 조달 — 구현 및 검증

**판정: Partial.** 시설 건설, 생산, 함선 건조의 실제 자재 수요를 공용 물류와 연결했고, 세 창고의 자재만으로 시설 완공, 생산 배치 완료, 선체·무장 자재 운송 및 진수, 지역 희귀 소재 운송 후 고급 함선 착공을 확인했다. 1·2·4회사에서 각각 8게임시간 동안 건설·조선과 500배치 반복 생산을 함께 시험했다. 다만 장기간 작업 기록 증가에 대한 보존·정리 정책과 위험 구역에서의 지속 부하 상한, 장기 중복 예약의 전수 계측은 아직 검증되지 않았다. 아래의 원본 상실 예약 처리와 측정되지 않은 지표도 남아 있으므로 완료로 과장하지 않는다.

## 기존 구조와 경계

| 원본 | 실제 수요 및 기존 동작 | 조달 연결 |
| --- | --- | --- |
| 건설 | `construction.ts`의 각 계획은 현장 자유 재고를 대기열 순서로 `reserved`에 옮기고 공사 중 `used`로 소비한다. 다른 창고나 함선 화물은 현장에 도착하기 전에는 사용할 수 없다. | 안정적인 계획 ID와 품목별 `moduleMaterials`, 투입·예약량으로 미확보량을 계산한다. 공용 작업은 건설 현장의 실제 필요량과 입고 가능량을 따르며, 기존 예약을 다시 사용하지 않는다. |

| 기존 물류 | P9.8.1 공용 배차는 출발지 자유 재고를 제거해 작업 예약에 두고, 실제 적재·하역으로 소유 자산을 옮긴다. P9.7 관리형 노선은 별도 실행하고 운송 명세를 가진다. | 새 시뮬레이터 없이 공용 작업을 생성한다. 기존 노선의 매니페스트와 수동 공용 작업의 예약·적재 물량을 목적지 공급에 반영한다. 기존 노선 설정, 화물과 실행 방식은 변환하거나 삭제하지 않는다. |
| 저장·시장·유지비 | 회사별 창고, 물류 예약, 화물 및 시장 거래가 서버에 있다. 시장 가격·재고, 보관 공간 및 유지비는 기존 거래와 틱 규칙이 결정한다. | 다른 회사의 보관함·함선 화물은 검색하지 않는다. 승인된 구매는 기존 `buy` 명령을 실제로 호출한다. 기존 가격·산업 수율·유지비는 변경하지 않았다. |

원래 `queueShortfall()`과 `stationNeeds()`를 그대로 합산하면 같은 현장 재고·기존 운송을 여러 원본에 중복 배정할 수 있다. 계획자는 원본별 수요를 우선순위와 안정적 순서로 배분하고, 동일 품목의 현장 가용량·기존 수동 운송을 한 번씩만 차감한다. 출발지에서는 회사별 보호 수량과 다른 작업의 미적재 계획을 차감하며, P9.8.1의 실제 예약은 이미 자유 재고에서 분리되어 있다. 예약·계획·적재·현장 보유는 별도 수량이다. 착공 및 배치 완료는 기존 시스템의 실제 소비와 생산으로 판정한다.

## 데이터, 배차 및 정책

`Company.procurement`는 전체 활성화, 자동 구매 허용, 누적 예산과 지출, 최소 잔고, 경로 위험 한도, 품목별 최대 단가, 출발지별 보호 재고, 원본별 정지·우선순위를 보관한다. 기존 저장에 필드가 없으면 자사 재고 운송 허용, **자동 구매 금지**로 해석한다. 생산·건설·조선 명령을 받거나 플레이어가 정책을 설정할 때만 정책을 저장한다.

`WorldState.procurementPlans`는 회사·원본 종류·원본 ID·목적지·품목으로 식별된다. 원본 필요·투입·건설 예약, 할당한 현장 자유 재고, 기존 운송, 신규 작업의 계획·출발지 예약·운송 중, 부족량, 우선순위, 상태·마지막 검토·이유 및 실제 구매 지출을 저장한다. 서버만 공용 작업의 `procurement` 연결을 설정한다. 회사가 다른 클라이언트에는 이 계획·작업 및 정책을 보내지 않는다.

계획자는 원본·정책 변경 때와 제한된 10초 주기 점검에서 실행한다. 각 회사의 명시적으로 참여한 수송선, 정박 규격, 연결된 게이트, 정책상 허용 위험과 후보 간 거리, 출발지의 실제 자사 재고 및 목적지 공간을 검토한다. 여러 보관함을 조합하고 이미 할당된 함선은 함부로 바꾸지 않는다. 이동 자체에도 같은 위험 제한을 적용한다. 300초 단위 대기 시간 가산과 생성 순서로 낮은 우선순위의 무기한 기아를 줄인다. 배차·적재·하역은 P9.8.1에서 수행하고, 직접 명령은 공용 배차에 우선한다.

구매는 명시적 허용, 남은 **회사 누적 예산**, 해당 품목의 양수 최대 단가, 최소 보유 크레딧, 실제 시장 재고·공간·접근성·경로 위험이 모두 충족될 때만 실행한다. 계획과 실제 구매는 서버 틱의 단일 동기 트랜잭션 순서에서 처리하며, 구매 즉시 실제 지출을 기록하므로 별도로 미결 구매 금액을 중복 약속하지 않는다. 시장 가격이 거래 사이에 바뀌면 그 시점의 단가를 다시 확인한다. 구매품은 해당 시장 보관함에 들어간 후 실물 운송된다. 보호 재고는 해당 보관함에서 **출발하는 자동 조달**에 적용된다. 현장 생산·건설과 플레이어의 직접 명령은 기존 규칙을 따른다.

## 취소·복구와 호환성

- 원본 취소는 불필요한 작업을 취소하고 출발지의 미적재 예약을 돌려준다. 생존 함선에 실린 화물은 함선에 남으며 순간이동하지 않는다.
- 원본 또는 회사 정책의 일시정지는 미적재 작업을 정리하고, 이미 적재한 작업은 같은 함선과 화물에 연결된 채 정지한다. 원본을 재개하면 그 화물부터 다시 운송한다. 직접 명령으로 함선을 분리하면 화물을 보존하고 해당 작업을 명시적으로 정지시켜 중복 조달을 피한다.
- 출발 정거장이 사라져 아직 적재하지 않은 예약을 되돌릴 곳이 없으면 예약은 원래 출발지에 귀속된 상태로 남고 계획에 복구 불가 이유를 표시한다. 다른 정거장에 재고를 생성하지 않는다. 이미 함선에 적재한 화물은 출발지가 없어져도 목적지까지 재개할 수 있다. 영구 소실 자산의 최종 소유권·회수 정책은 후속 결정이 필요하다.
- 목적지 포화·경로 차단은 화물을 보존하고 조건 회복을 기다린다. 파괴된 함선에서 실제로 잃은 적재분만 손실로 기록하며, 남은 수요는 실제 가용 재고로 다시 판단한다.
- 새 필드는 선택적이며 구형 노선을 변환하지 않는다. 저장을 반복 복원해도 원본별 계획과 기존 작업을 재사용한다. 실제 P9.7.1 운송 중 저장을 P9.8.1 회귀에서 복원해 기존 노선과 공용 작업이 함께 운행하는 것을 확인했다.

## 통합 및 보존 증거

- `tests/p982-procurement.test.ts`: 서로 다른 세 창고의 합금·구조재로 시설 실완공, 생산 완료, 실제 패스파인더 선체·프리셋의 진수, 드레드노트의 고강도·특이 합금 실물 운송 후 착공을 검증한다. 기존 월드 버전의 레시피와 실제 등록 `regionalMaterials`를 사용한다.
- 같은 재고를 두 건설 계획과 수동 운송이 경쟁하는 경우, 반복 스캔·JSON 복원, 다른 회사 재고·함선·스냅샷 격리, 보호 재고, 정지·재개, 소수점 부족분, 정거장 포화 복구, 파괴된 함선의 실제 손실과 재배정, 외부 보관함과 출발지 소실을 검증한다.
- 구매 금지 기본값, 회사 예산·최대 단가·최소 잔고, 실제 시장 재고와 크레딧 감소, 구매 후 물리적 운송 및 복원 후 중복 지출 방지를 시험한다. 자산 보존 시험은 자유 창고 + 출발지 예약 + 함선 화물 + 기존 건설 예약에 관측된 실제 소비·생산을 더해 대조한다.
- 격리 PostgreSQL은 임의 비밀번호의 일회용 컨테이너와 루프백 포트만 사용한다. `scripts/p982-postgres-check.sh`는 월드·DEV-1 인증용 데이터베이스를 분리하고 실행 후 컨테이너를 삭제한다. 실제 서버 프로세스 2회 재시작 후 구매 지출, 원본 계획, 미적재 예약 및 적재 화물을 대조하고 정상 생산과 추가 재시작을 확인한다. 별도로 DEV-1 PostgreSQL 계정 인증 및 재시작·비밀번호 변경 시 권한 회수 시험을 실행한다.

## 장기·성능 시험

별도 단기 부하 표본에서는 4회사에 수송선 100척을 두고 600게임초를 실행했다. 이 기간에 원본 목표 8/12가 완료됐으며 나머지 목표는 관측 종료 시 아직 완료되지 않았다. 최초 조달 계획 27.02ms, 최초 배차 21.17ms, 틱 평균 3.837ms / P95 5.307ms였고 품목 보존 오차는 0.00001 미만이었다. 이 짧은 표본을 장기 완료율로 취급하지 않는다. [100척 표본](../artifacts/p982/sample-4-ships25.json).

평균 대기는 관측된 각 작업의 생성부터 최초 함선 배정까지, 최초 자재 확보는 각 원본의 첫 착공·배치 시작까지다. 빈 이동은 화물 없이 이동 중인 함선의 초를 표본으로 센 값이며, 전역 최적 경로 대비 불필요한 운항 횟수는 측정하지 않았다. 장기 중복 예약의 모든 순간을 별도로 전수 계측하지 않았고 종료 시 미완료 작업과 자산 보존, 반복 스캔·경쟁 단위 시험으로 확인했다. 불안정·적대 성계의 장기 운용, 운영 서버 부하·메모리 상한, 산업 수익성은 측정하지 않았다.

## 남은 과제와 P9.8.3

1. 출발지 정거장이 영구 삭제될 때 미적재 예약의 실제 회수·청산·소유권 정책을 정하고, 그 결정을 적용하는 별도 복구 동작이 필요하다. 현재는 위치를 바꾸지 않고 명확히 차단한다.
2. 완료·취소된 공용 작업은 이력으로 남는다. 1·2·4회사 지속 시험에서 8시간 뒤 각각 522·1,046·2,092개로 증가했다. 장기 운용의 검색·저장 비용을 제한할 보존 정책과, 네 회사 이상의 지속 부하·더 많은 함선 및 장애가 섞인 24시간 이상의 측정이 필요하다.
3. 경로 위험 제한은 실제 항로에 적용하지만 연료비·정확한 이동 시간의 전역 최적화나 여러 경유지 최적화는 하지 않는다. 위험한 성계에서의 장기 생존과 기아 방지의 장기 상한은 별도 시험이 필요하다.
4. P9.8.3은 고갈 광구의 감지·후보 선택·기존 채굴 작전의 안전한 전환을 별도 구현해야 한다. 공용 참여 여부와 각 물류 작업 ID, 실제 창고 재고·예약, 원본별 조달 계획을 인터페이스로 이용할 수 있다. 채굴 편대의 자체 수송선을 자동으로 빼앗거나 신규 공장·연구·자동 판매를 시작하지 않는다.
