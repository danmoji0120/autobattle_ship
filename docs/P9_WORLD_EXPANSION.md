# P9 대규모 월드 확장

기준: `integration/growth-p8-logistics` `fcc1485a94dee0a5983a637c59005e3db7f7c89e`. 작업 브랜치: `codex/p9-world-expansion`. 이 문서의 월드는 격리된 개발·테스트 월드다. 운영 월드, 운영 DB, 서버 또는 통합 브랜치에는 적용하지 않았다.

## 적용 범위와 저장 호환성

- `WorldSim.create()`로 **새로 만드는 성장 월드**에만 P9 배치를 적용한다. `newWorld()`의 기존 c0 생성 경로와 5개 성계의 물리 좌표·게이트·행성·시설을 보존한다. 기존 성계의 지도상 위치만 새 월드에서 재배치한다.
- 저장된 월드를 여는 `WorldSim` 생성자에서는 P9을 호출하지 않는다. 기존 c0 및 성장 저장은 성계 추가, 좌표 이동, 자산 재생성 없이 그대로 복원된다. 기존 성장 저장을 P9으로 바꾸는 마이그레이션은 **구현하지 않았다**. 사용자가 보유한 기존 성장 월드를 확장하려면 별도 설계와 승인된 이전 절차가 필요하다.
- 월드 형식 버전과 콘텐츠 버전은 올리지 않는다. 새 배치에는 `worldLayout: 'p9'`를 기록한다. 성계 인덱스는 기존 0–4를 유지하고 5–21을 고정 사용한다. 새 정거장·광상·은신처 ID는 `p9_` 접두사를 사용한다.
- 추가 배치는 RNG를 소비하지 않는다. 탐사 지점 위치는 기존 해시 기반이고, 기존 인양 보상과 4시간 재생성 규칙을 사용한다. 지점·진행도·발견 회사는 서버 월드에 저장되며, 멀티플레이 스냅샷은 해당 회사가 발견한 지점만 보낸다.

### 게이트와 전략

기존 다섯 링크는 유지하며 새 링크는 항상 역방향 게이트와 함께 생성한다. 리라–세레스–아스트라–헬리오스와 하버–포지–아스트라가 중심부의 우회로를 제공한다. 포지–갈라진 회랑–엠버, 회수 항로–균열 공백–기록 보관지–황혼 광맥–송곳니는 산업·변경 및 위험 지역을 연결한다. 서리 변경, 고요한 공백, 끝자락과 검은 관문은 막다른 성계다.

드레이크–북방 관문–파편 항로는 북방 외곽의 유일한 진입로다. 북방 관문–파편 항로를 끊으면 감시자의 틈과 검은 관문에 외부에서 갈 수 없지만, 이들 내부 경로는 유지된다. 가장 긴 최단 경로는 8점프로, 기존 편대 이동 경로 생성기의 8점프 한도 안에 있다. 실제 8점프 왕복과 4점프 화물 운송을 시험했다. 길찾기에는 기존 `nextGate()`와 사용 가능 게이트 필터를 쓴다.

기존 코드는 자동 하역과 피난 항구를 고를 때 성계의 일차원 저장 좌표를 거리로 섞었다. 확장 배치에서는 황혼 광맥에서 한 점프 거리인 녹슨 정박지 대신 네 점프 거리인 포지를 고르는 문제가 재현됐다. P9에서는 성계 간 점프 수와 각 성계 내부 거리를 기준으로 자동 하역·피난·건설 자재 공급 항구 및 토벌 계약 게시처를 고른다. 자동 판매는 해당 화물 중 적어도 한 품목을 실제 매입하는 시장만 선택한다. 파편 항로에서 수정을 사지 않는 북방 보급소 대신 드레이크의 시장이 선택되는 것도 검증했다. P9이 아닌 저장은 기존 선택 규칙을 그대로 사용한다.

## 경제·탐사·NPC

기존 P4 수요·시장 예산·가격 공식과 함선 가격, 기존 시장·제작량은 변경하지 않았다. 신설 시장만 기존 c4 원자재 가격 계수와 생산 원가 평가를 사용하며, 지역별 초기 재고·소비·정제·예산을 설정했다. 앤빌의 제한된 구매 예산은 광물을 세레스·포지로 운반할 이유를 만들고, 두 산업항의 원료 소비 및 가공품 공급은 돌아오는 화물의 후보가 된다. 리라·하버의 설비 수요와 북방 보급소의 작은 예산도 서로 다르다. 새 광상은 단순히 거리에 비례해 산출량을 키우지 않는다.

리라·세레스·하버·포지는 L급 정박을 제공하고 앤빌·북방 관문은 기존 기본 M급을 사용한다. 기존 대형 조선소와 시작 성장 경로는 유지된다. 새 공영항은 선박을 직접 판매하지 않는다. 거래 기회는 가격, 예산, 재고, 운송비와 위험을 함께 고려해야 하며 고정 수익은 보장하지 않는다.

**P9 당시 남은 문제 — 정거장 설립 자재:** 기존 `prepareFound`는 공작선의 합금이 부족하면 다른 성계의 시장에서 즉시 구매해 공작선에 보충할 수 있었다. P9에서는 이 구매 방식을 유지했다. 이후 성장 월드에 대한 실제 운송과 설립비 환급은 [P9.5 건설 물류](P95_CONSTRUCTION_LOGISTICS.md)에서 다룬다.

P9 성계는 `exploration.slots`와 `tier`를 별도로 지정한다. 기존 성계와 저장에서 이 값이 없으면 종전 치안 기반 규칙을 쓴다. 비어 있는 위험 성계와 높은 치안 대비 희귀한 기록 보관지가 함께 있어 위험과 보상이 일대일로 연결되지 않는다. 탐사·인양의 기존 작업 시간, 화물 용량, 무작위 설계도 획득, 재생성 시간은 변경하지 않았다. 장기적인 탐사 수익률과 실제 여러 플레이어의 경쟁에 대한 검증은 아직 필요하다.

기존 연합·상인·해적 시스템을 재사용한다. 새 해적 은신처는 세 곳이고 각각 편대 상한 1이다. 독립 상선은 새 주요 항구도 방문할 수 있다. 제국·반제국 진영의 경계는 향후 활용을 위한 지리적 설정이며 실제 P10 세력 AI, 전쟁, 생산·보급 체계는 없다.

떠돌이 해적은 원래 거주 항로에 나타나는 유형이다. 확장 월드에서 변경의 치안 수치를 임시로 높이면 비어 있는 공역까지 거주 항로로 취급하는 문제가 있어, P9에서는 해당 유형의 출몰을 실제 `settled` 성계에만 제한했다. 기존 월드와 원래 치안의 P9 배치에서는 출몰 가능한 성계가 달라지지 않으며, 변경의 은신처 해적은 그대로 활동한다. 향후 성계 자체의 거주 유형을 변경한다면 `kind`도 함께 관리해야 한다.

## 지도와 조작

성계 이름, 치안 색상과 수치, 실제 게이트 선, 현재 성계와 자사 함선·기지 수를 표시한다. 수도권의 짧은 순환 항로를 묶고, 드레이크–북방 관문–파편 항로를 지나 검은 관문으로 뻗는 병목과 남부 변경을 서로 다른 가지로 배치했다. 고요한 공백·서리 변경·끝자락은 연결된 성계로부터 떨어진 막다른 지점이다. 28개 게이트 선은 서로 다른 연결끼리 교차하지 않는다.

새 배치는 P9 성계 ID에 적용하는 **클라이언트 지도 투영**이다. 기존 P9 저장에 포함된 `map`, 성계의 물리 좌표, 게이트 위치와 연결은 변경하지 않으며 새 저장에도 마이그레이션하지 않는다. 기존 5성계 월드와 알려지지 않은 성계는 저장된 지도 좌표를 그대로 사용한다. 지도상의 거리는 항로 관계를 읽기 위한 배치이며 실제 이동 횟수는 점프게이트 그래프로 계산한다.

선택 성계의 치안·정거장·자원·해적 거점과 항로는 별도 패널에 정리한다. 정거장과 자원 항목은 실제 정거장 화면과 자원 지대 선택으로 연결되며, 선택 편대의 실제 경로를 지도에 강조한다. 연결이 없으면 경로를 그리지 않고 이동 명령을 비활성화한다. 드래그 이동, 확대·축소, 전체 보기, 키보드 선택을 지원하고 지도가 열려 있는 동안 게임 카메라의 키 이동을 차단한다. 모바일은 상세 패널을 지도 아래에 두고, 전체 조망에서는 성계 이름을 숨겨 지역 구분을 읽기 쉽게 유지한다. 변경 없는 스냅샷에서는 SVG 전체 재구성을 건너뛰어 0.4초마다 불필요하게 지도를 다시 그리지 않는다.

### 성능과 한계

성능 수치는 부하와 환경에 따라 달라지는 단일 개발 환경 관측치이며 운영 수용량 보증이 아니다. 같은 시드·회사 1개, 양쪽 모듈을 예열한 뒤 각각 20회 생성, 100틱 예열 및 1,600틱(400게임초)을 측정했다. 그 상태를 각각 실제 `GameServer`에 넣고 100스텝 예열 뒤 통계 수집을 켠 채 800스텝을 추가 측정했다. 접속 클라이언트는 없다. 동일 변경 코드에서 기존 성장 5성계는 `new WorldSim(newWorld(seed))`, P9은 `WorldSim.create(seed)`로 비교한다. 실제 NPC를 끄지 않아 첫 측정 종료 시 함선 수는 각각 98척과 110척이었다. CPU 시간은 프로세스 전체 스레드를 합산한다. 메모리는 GC 후 30개 월드를 유지했을 때의 V8 힙 증가분을 월드 수로 나눈 추정치이며 RSS나 운영 서버 전체 메모리는 아니다. [측정 원본](../artifacts/p9/performance.json), 재실행: `node --expose-gc node_modules/vite-node/dist/cli.mjs scripts/p9-performance.ts`.

| 지표 | 5성계 | P9 22성계 |
| --- | ---: | ---: |
| 월드 생성 평균 | 3.15ms | 1.86ms |
| 0.25초 시뮬레이션 틱 평균 벽시계 | 3.39ms | 3.29ms |

이 표본에서 P9 서버 스텝 벽시계 시간은 약 10% 늘었고 250ms 틱 간격 이내였다. 성계 조회는 캐시 적중 시 상수 시간에 찾고 변경·삭제 시 캐시를 검증해 다시 검색한다. NPC 수·JIT·GC와 호스트 변동이 섞여 있어 월드 크기의 순수 비용이나 장기 부하를 확정할 수 없다. 생성 시간이나 CPU 차이를 성능 개선으로 해석하지 않는다. 더 많은 회사·화물·전투를 포함하는 반복 단독 측정이 필요하다.

월드 확장 1차 지도의 소프트웨어 WebGL 측정에서는 1440px 기준 20회 강제 SVG 갱신 평균이 기존 5성계 3.11ms, 22성계 5.83ms였고 변경 없는 22성계 확인은 0.065ms였다. 이 수치는 위의 지도 개선 이전 결과다. 개선 후 별도 실행에서는 Chromium SwiftShader와 정지된 3D 장면에서 22성계 지도 강제 갱신 평균이 19.21ms, 변경 없는 확인은 0.055ms였다. 강제 갱신은 60fps의 한 프레임보다 길었고 실행 환경과 부하가 달라 1차 측정과 직접 비교할 수 없다. 실제 GPU와 게임 진행 중의 프레임, 장기 운영 부하 및 다수 플레이어의 경제 균형 검증은 **Partial**이다.
