# 공용창고 안정화와 월드 분석 개발 기록

작업 기준: 2026-11-08 1차 개발 지시서. 기존 `GROWTH_PLAN.md`의 콘텐츠 전용 Codex 역할 경계는 이번 지시서에서 명시한 시스템 작업에 한해 대체한다. P9 경제 수치와 운영 DB는 변경하지 않는다.

## Stage 1

- 구획별 첫 시간 선납 만료 시각을 `Company.leasePaidUntil`에 기록한다. 추가 구획만 새로 선납하며 이후 사용 시간을 기존 60초 운영비 정산에 합산한다. 반납은 최근 구획부터, 환불 없음. 이미 발생한 미정산 요금과 체납은 유지한다.
- 과거 선납 시각은 기존 세이브에 없으므로 추정하지 않는다. 기존 임대 수·재고·체납을 유지하고 기존 구획은 후불 누적을 계속한다.
- 자동 채굴 하역지는 정박 규격·권한·시장·품목별 구매 예산·창고 여유·거리·점프 수·자체 정거장 선호도를 적용한다. 모든 목적지가 막히면 기존 화물을 유지하고 원인·해결책을 알린다. 고정 운송 노선은 임의로 바꾸지 않고 목적지 여유가 생길 때까지 대기한다.
- 전투 회수품은 원래 하역지별 `Company.pendingLoot`에 집계하고 공간이 생기면 자동 입고한다. 개별 지급 이력을 무한 추가하지 않는다. 전투 종료 중복 실행을 차단하고, 대기 자산을 센서스·회사 자산 평가에 포함한다.
- 미완공 코어는 건설 계획의 부족 자재만 받는다. 기존 재고·예약 자재는 보존하며 코어 완공 후 기존 창고 용량을 사용한다. 새 용량·가격·보상 상수는 추가하지 않았다.

검증: 관련 4개 파일 26개 테스트 통과(243.57초), TypeScript·전체 빌드 통과. 격리된 로컬 PostgreSQL 16에서 기존 저장/마이그레이션 경합 2개 테스트 통과. 변경 전 `4a19e19` 대비 c0 1,800초·분 단위 해시 30개 일치(벽시계 기반 전투 예산 시계 고정). 브라우저 1440×900·1024×768 확인, 실제 600초 채굴→운송→하역→판매: 채굴 824.49, 판매 수입 2,801.68 cr. 재현: `node scripts/storage-browser.cjs`.

저장 영향: 기존 JSON 월드에 선택 필드만 추가한다. SQL 스키마 변경과 contentV 변경 없음. 운영 데이터 접근·반영 없음. 기능별 CPU·메모리 정량 비교는 Stage 5 통합 측정에서 보고한다.

## Stage 2–4 설계

통계는 게임 상태 밖 `SaveFile.analytics`에 저장한다. 기존 파일 저장과 PostgreSQL JSONB 저장/세대 펜스를 그대로 사용한다. SQL 마이그레이션은 필요하지 않다. 기록 시작 이전의 과거 이력은 추정하지 않는다. 관리자 계정 목록을 설정하지 않으면 멀티플레이 관리자 조회는 거부한다.

## Stage 2 — 서버 관측 기반

구현 경로: `world/observe.ts`(비영속 관찰 훅), `server/analytics.ts`(집계·보존·조회·경고), `server/core.ts`·`protocol.ts`(인증된 조회), 기존 경제·생산·연구·물류·전투 발생 지점. 별도 시뮬레이션이나 더미 사건을 만들지 않는다. RNG·명령 결과·밸런스 상수는 바꾸지 않는다. 측정한 관찰 처리 시간은 기존 NPC 전투의 벽시계 CPU 예산에서 제외한다.

### 지표 정의

| 지표 | 정의·주의점 |
|---|---|
| 통화량 | 모든 회사의 `credits` + 정거장의 실재 구매 예산 `funds`. 미수금·재고 평가액은 통화가 아니다. |
| 생성·소멸·이전 | 동기적인 실제 거래 전후 잔액을 대조한다. 대응되는 차변·대변은 이전, 남는 증가·감소만 생성·소멸. 중첩 호출은 중복 집계하지 않는다. 지역 예산 회복·상한 감소도 실제 증감량을 기록한다. |
| 현금 수입·지출 | 회사 잔액에 실제 반영된 금액. 설립 자금·환불·자산 거래를 원인별로 구분한다. 현금 기준 순이익은 수입−지출이며 평가손익과 다르다. |
| 발생 비용 | 함선 운영비·정비·임대·보급 청구. 실제 결제와 분리하여 체납·미정산을 숨기지 않는다. 첫 시간 임대 선납도 비용 기록에 포함한다. |
| 시장 거래 | 실제 체결 수량과 대금. NPC 시장과 플레이어 상품 거래를 기록하며 구매자·판매자 통계를 월드 전체 거래량에 두 번 합산하지 않는다. 공개 가격 추세는 현재 세후 판매 호가이며 거래 가중 평균이 아니다. |
| 자원 | 실제 채굴·생산 산출, 생산·연구·건설·운영 소비, NPC 조선 자재, 전투 회수·화물 손실. NPC 시장 내부 생산·소비·수급 보정은 **시장 순공급/순소진**으로 별도 기록한다(내부 레시피의 총생산으로 추정하지 않음). |
| 평가 자산 | 기존 게임 함선 잔존가·품목 기준가를 사용. 화물·창고·회수 대기·매물 예치·건설 중 재료와 선납 건설 대금을 포함하고 미지급 운영비를 차감한다. 연구·설계도 권리는 평가하지 않는다. 매물의 희망 가격으로 자산을 부풀리지 않는다. 게임의 기존 승급/목표 판정용 `netWorth`는 바꾸지 않는다. |
| 성장 시간 | 월드 운영 시간과 수집 이후 측정한 실제 접속 시간을 별도로 기록한다. 다중 탭은 회사당 한 번만 센다. 과거 접속 시간은 역산하지 않는다. |
| 연구·계약·평판 | 연구 등록·실제 시작·완료·취소, 연구 시작 이후 실제 월드 경과 시간(일시정지 포함), 계약 수주·완료·실패, 평판 지급/차감 경로. 시작 미관측 연구는 소요시간을 추정하지 않는다. 연구 방식·계획 소요시간도 보존한다. |
| 물류 | 함선·편대별 하역량, 출발부터 하역까지의 노선 시간, 현재 대기 원인·시간, 실제 창고 점유·회수 대기. 직접 귀속 수입·운영/정비비만 편대에 연결하고 공용 보급비·창고 임대료·수동 거래는 회사 공통 항목으로 남긴다. |
| 전투·월드 | 교전 발생, 함급별 참여·승리·손실, 실제 피격 무장별 선체 피해, 치안·해적 열기·습격·세력 영향력·성계별 거래 활동. 원거리 전력 모델의 가상 피해는 실제 전술 피해 비교에서 제외한다. |

### 저장·제한·운영 설정

- `SaveFile.analytics`는 월드 밖의 선택 필드이다. 기존 파일 원자 저장과 PostgreSQL JSONB 저장·세대 펜스를 사용한다. SQL 스키마·월드 버전·contentV 변경과 운영 DB 마이그레이션은 없다.
- 기본 600초 스냅샷(`ANALYTICS_INTERVAL_S`, 300~900초). 기본 최근 상세 구간 144개, 시간 집계 720개, 일 집계 365개. 오래된 구간은 시간·일 단위로 합친다.
- 기본 통계 직렬화 상한 8 MiB(`ANALYTICS_MAX_BYTES`, 256 KiB~32 MiB). 싱글플레이는 localStorage를 고려해 1 MiB. 구간별 상세 지표 2,048개, 진행 메타데이터 종류별 4,096개, 샘플의 회사·시장·창고 등 512개로 제한한다. 한도를 넘으면 오래된 기록/상세 항목을 생략하며 생략·만료·수집 오류를 화면에서 명시한다. 큰 조회의 행 생략도 별도 표시한다.
- 기간 경계에 걸친 압축 집계는 자의적으로 나누지 않고 실제 포함 구간을 표시한다. 기록 시작 전 이력은 복원하지 않는다.
- `ANALYTICS_ENABLED=0`이면 수집·조회는 중지하고 기존 통계는 보존한다. 다시 켜면 미관측 구간과 통화 순변동을 명시하며 그 기간의 사건을 추정하지 않는다.
- 관리자: `ANALYTICS_ADMIN_ACCOUNTS=<인증된 계정 UUID,쉼표 구분>`. 비어 있으면 멀티플레이 관리자 조회 거부. 클라이언트가 전송한 계정/관리자 값은 권한 근거로 사용하지 않는다. 싱글플레이 소유자는 로컬 월드 관리자 조회 가능.
- 경고 기준: `ANALYTICS_ALERTS_JSON`의 `assetPerHour`, `repPerHour`, `saturationRatio`, `saturationSeconds`, `tradeShare`, `tradeMinimum`, `waitSeconds`, `researchFraction`, `combatWinRate`, `combatSamples`, `weaponDamageRatio`, `weaponSamples`. 유효한 양수만 적용하고 서버에서만 설정한다. 경고는 실제 수치와 기준을 표시하며 자동으로 게임을 조정하지 않는다.
- 일반 스냅샷에도 타 회사의 현금·연구·설계도·임대·창고·화물·피팅·비공개 물류 명령이 노출되지 않도록 전송 전에 걸러낸다. 통계 요청에는 접속별 속도 제한을 적용한다.

검증: 통계·권한·재시작·압축·중복 거래·실제 연구/생산·수집 중지/재개·자산 보존·접속 시간 10개 회귀 검증 통과. PostgreSQL 서버 재시작에 통계·선납·회수품이 보존되는 검증을 기존 마이그레이션 경합 검사에 추가했다. 실제 HTTP/WebSocket 별도 검증은 관리자 기본 거부·위조 차단·회사 격리·재시작 등 14개 통과. 전체 회귀 및 성능 수치는 아래 최종 검증에 기록한다.

### 기존 시스템에서 발견하여 유지한 사항

- 정비비와 보급 구매 비용은 실제 회사 현금 결제보다 먼저 NPC 예산에 반영될 수 있다. 체납 중의 예산 증가는 통화 생성, 나중에 실제 결제되는 금액은 별도 현금 변동으로 기록한다. 이 시점을 바꾸면 기존 경제가 바뀌므로 수정하지 않았다.
- 기존 예산 유입은 최대 예산의 1.5배까지 받지만 정기 회복 경로는 최대 예산까지 제한한다. 이로 인한 실제 감소도 상한 조정에 의한 소멸로 기록한다. 수치나 규칙 변경은 P9 검토 사항이다.
- 시각 없는 과거 임대 기록의 선납 만료를 추정하거나 소급 환급하지 않는다. 구획·기존 재고·누적 체납을 보존하고, 새로 추가한 구획부터 명시적 선납 기록을 적용한다. 과거 중복 청구의 정산·운영 데이터 보정은 별도 정책과 승인 대상이다.
- 이전 바이너리로 롤백하면 구버전 `SaveFile` 작성 코드가 모르는 최상위 통계 필드를 다음 저장 때 제외할 수 있다. 운영 반영 전 전체 세이브 백업을 보존해야 한다. 게임 자산과 신규 통계 이력의 롤백 보존은 구분해야 한다.
