## 성능과 장기 실행

3개 회사가 실제 자동 채굴·판매·NPC 시장을 사용하고 기존 후불 임대도 유지하는 월드에서 수집 비활성/활성 600초를 교대로 3회 측정했다. 매 쌍의 전체 게임 상태는 동일했다. 다른 무거운 검증과 동시에 측정하지 않았다.

| 회차 | 비활성 CPU ms | 활성 CPU ms | 증가율 |
|---|---:|---:|---:|
| 1 | 6,233.179 | 6,693.315 | 7.38% |
| 2 | 5,968.722 | 6,888.782 | 15.41% |
| 3 | 5,334.727 | 6,578.775 | 23.32% |

- CPU 증가율 중앙값 **15.41%**, 추가 CPU 중앙값 **게임 시간 1초당 1.53ms**. 수집기 내부 계측 약 0.83ms/게임 초. 실행 순서·JIT·GC에 따른 변동은 원자료에 남겼다.
- 600초 통계 직렬화 크기 **87,940 bytes (85.88KiB)**. 누락 0, 통화 대사 오차 약 0.000000000049cr. 이 측정은 틱 내 수집 비용이며 대규모 PostgreSQL 쓰기 처리량 측정은 아니다.
- 게임 시간 **6시간** 월드 진행(3회사, 정상 채굴·후불 임대·시장 운영), 2시간·4시간에 파일 저장/재로드 후 전체 상태 일치. 통계 **1,506,804 bytes (1.44MiB)**, 완료 구간 36개, 수집 오류 0·누락 0. 시간·일 압축과 보존 상한은 별도 2,000개 구간(약 6.94일) 회귀 입력으로 검사했다.
- 6시간 실행 전체 프로세스 CPU **204.81초**, 벽시계 **200.20초**. GC 후 전체 게임+수집기 힙은 **7.67→15.95MiB**(시간별 표본 최대 16.89MiB), 최종 조회 직후 25.64MiB, 최대 RSS **230.82MiB**. 통계만의 메모리 증가량으로 해석하지 않는다.
- 6시간 통화 대사 오차 **0.000002534565cr**. 임대 원장은 정수 단위로 정확하지만 기존 월드 잔액과 합산은 Number이므로 소규모 부동소수점 오차가 남는다.
- 기본 서버 통계 상한 **8MiB**, 싱글플레이 **1MiB**. 상세/시간/일 구간, 구간별 행, 회사/시장 표본과 진행 메타데이터도 별도로 제한한다. 먼저 도달한 상한에 따라 보존 기간이 짧아질 수 있으며 화면에 만료·생략을 알린다.

성능·6시간 검증은 해적 거점을 비활성화하고 치안을 높인 경제/물류 시나리오다. 전투는 실제 멀티플레이 교전·관전·리플레이 검사와 기존 전투 회귀로 별도 확인한다. 대규모 전투와 다수 접속자가 동시에 있는 운영 부하의 성능 보증으로 주장하지 않는다.

## 저장·운영 영향

기존 월드 JSON에 선택 필드(구획별 선납·정수 미납 원장·회수 대기)와 `SaveFile.analytics`를 추가한다. SQL 스키마·contentV 변경이 없으며 운영 DB 마이그레이션은 필요하지 않다. 기존 임대 수·재고·미수금을 보존하고 알려진 미정산 임대료를 한 번만 이관한다. 기록되지 않은 과거 선납·사건·연체 시각은 추정하지 않는다.

관리자 권한은 운영 서버의 `ANALYTICS_ADMIN_ACCOUNTS`에 인증된 계정 UUID를 설정해야 활성화된다. 일반 플레이어에게 관리자 자료를 전송하지 않는다. 이전 바이너리로 롤백하면 구버전 저장 코드가 신규 통계를 제외할 수 있으므로 운영 반영 시 전체 세이브 백업을 보존해야 한다.
